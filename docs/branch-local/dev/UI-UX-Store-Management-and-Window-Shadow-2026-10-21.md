### 呈现细节

- 行内展示一个最相关的主操作，并给已安装条目提供卸载。工坊项仍打开工坊，不伪装成本地安装。
- 列表分页通常每页六项，根据当前详情/错误等占用的动作数适当减少；保留两项翻页预算，严格遵守现有单贡献者 32 动作上限，不提高限制或另建动作系统。搜索和切筛选回到第一页，页码会随结果数量收敛。分页新增的是操作入口预算约束，不能宣称所有任务点击数都下降。
- 搜索、安装/已装/更新筛选、插件/主题筛选、翻页与对应行操作共用同一公共 presentation 和 typed action point；操作中的禁用原因可见。计划/本地包复核时不允许竞争性的列表选择、搜索或翻页；复核结束后原查询保留。
- 远程安装计划只在右侧滚动区核对一次，不再叠加同内容的第二个弹窗。确认与取消留在所选项固定标题区；依赖列表很长时仍可找到按钮。确认前继续核对原快照、计划实例和根包身份。
- 失败详情放在滚动正文，不将大量诊断塞进固定全局工具区。不会自动跳到技术信息，也没有增加盲目重试。
- 未切换目录、筛选或搜索时，快捷操作复用当前查询；安装计划取消不触发下载。选中项与恢复继续使用现有稳定包身份规则。

## 1.7 窗口背后明暗闪烁

**用户确认**：发生在 RimWorld 1.7，把 Phinix 拉到最大时，只有背后的游戏画面忽明忽暗。

**本地静态证据**（引用版本 1.7.4977 rev1248）：

- 原版 `Verse.Window` 构造默认开启 `drawShadow`。
- `WindowStack.WindowStackOnGUI` 在调用每个窗口的 `WindowOnGUI` 前，通过 `Widgets.DrawShadowAround(windowRect)` 绘制阴影图集；这一层不受 `doWindowBackground=false` 关闭背景的设置控制。
- 1.7 `UnityEngine.GUI.Window` 将窗口内容加入 pending 队列，后续 `RunPendingWindow` 才进入 backend 的窗口内容绘制。
- Phinix 主窗已关闭原生矩形背景，并自行绘制圆角主题背景/边框，但此前仍保留原生矩形阴影。

**本轮局部处理**：仅在 `PHINIX_RIMWORLD_17` 下为 `ServerTab` 设置 `drawShadow=false`，移除这条多余的原版阴影绘制路径。1.6 保留原行为；其他原版/模组窗口和 Phinix 弹窗不被全局修改。不限制最大尺寸、不强制用户主题不透明、不改游戏亮度/渲染后端，不增加 Harmony 全局补丁。

这是一项基于可疑叠加路径的修复候选。静态证据证明旧阴影存在及本包已移除它，**不能证明它是闪烁的唯一根因，也不能声称游戏中已不闪烁**。

### 闪烁复测

1. 关闭游戏，替换主 Mod 后重新进入相同存档、相同位置、相同主题；不要同时启用两份主 Mod。
2. 主窗逐渐拉到屏幕边缘、拉到最大并停止拖动，观察后方地图；再缩小、移动、关闭重开。
3. 检查主窗口主题背景/圆角/边框、聊天、右侧与弹窗仍正常；再试深浅主题及已有半透明主题。
4. 若仍闪，记录完整 1.7 构建号、使用主题及不透明度、是否只在拖动时出现；不能将候选静态检查替代实际复测。
