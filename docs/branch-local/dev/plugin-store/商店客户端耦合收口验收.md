## 范围与结果

用户批准修 C1，其他问题先处理客户端可以独立完成的部分。对应[耦合审查](商店耦合性审查.md)，C1/C3 客户端代码及 C2 本地工具/静态校验边界已完成；远端索引未同步这批校验器/测试。C4 Gateway 和 C5 索引 owner 配置未改。没有业务 Bug 修复、红包上传、远端文案重写、提交或部署。

- **C1**：清单解析只保留 CLR/游戏/框架基础库保留名，不再写死 Chat/Trade/Inventory/LegacyAdapter；旧 CatalogReader 也复用该规则。程序集身份和文件别名共同检查：包内自相冲突、商店规划、实际安装、启动预检、当地 Mod 扫描、打包器显式宿主输入和本地发布闭包均检查真实占用，不区分大小写。未占用业务名称可用，已加载/已安装的实际同名仍拒绝。停用不等于卸载 CLR 程序集，未放宽摘要、PE、依赖或归属校验。远端旧解析器仍可能拒绝未来独立发行的原内置程序集名，后续索引维护批次必须同步。
- **C2**：静态 ZIP 报告与安装输入分成 partial 文件；纯语言校验与文件系统加载分离。引用失败 DTO 和摘要函数不再拉入规划/库存代码。公共类型、命名空间、程序集归属、旧 API、存储键和 SHA 算法保持。production snapshot 从 24 缩为 14 个必要文件，撤出 12 个旧 runtime/事务/transport 副本，增加两个独立静态辅助文件。候选 DLL 仍只当字节输入。
- `validator_snapshot.py check` 检查固定文件集合/摘要；带 `--source-root` 比较主源码。显式 refresh 先验证并读取完整来源，再逐文件替换，最后保存摘要。拒绝快照篡改、额外文件、源缺失、路径逃逸和 symlink。多文件刷新不是原子事务；写入中断会在下次摘要检查时拒绝验证。六个测试覆盖完整性、源一致性、幂等与拒绝边界。独立索引没有主源码时，源比较明确跳过而非伪称通过。
- **C3**：正式 Store 不再编译 ManagedInstallation.cs，历史源码和专用测试保留。DLL 安装仍走通用服务，Workshop 仍只打开订阅链接。不删除玩家历史收据、设置、存档、业务数据或未知文件。实际产物字符串元数据不再包含旧 ManagedInstallation 类型名。
