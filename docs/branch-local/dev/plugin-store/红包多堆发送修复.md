## 原因与实现

列表通过 `StackedThings` 合并显示可堆叠的实体堆，发送却在出栈、脱离地图后检查 `selectedThings.Count == 1`。原版白银上限 500，500+300 的选择会触发 `Stateful red packets require one physical stack`。该异常在入队前发生，本次红包没有成功发送；旧处理路径随后尝试将所选物品恢复到地图。

现在红包和库存物化共用 `RedPacketStackTemplate`：核对完整数量、唯一来源、游戏双向可堆叠规则和完整 Scribe 状态。多个相同普通物品可以用总数量生成一个有状态传输模板，原始各堆仍分别保存在发送方托管中。只在序列化期间临时调整首堆数量，并用 finally 恢复；不吸收、销毁或改写原堆来做合并，失败仍走原恢复路径。

比较排除顶层实例 ID、数量、地图位置/方向及放置时间，保留 health、stuff、tickDelta、questTags、图形和嵌套组件/引用状态。未知自定义 Thing/ThingComp 多堆不合并；原单堆支持保留。首版接受原生 Thing / ThingWithComps 及已知每单位组件 Forbiddable、Quality、Colorable、Rottable、Ingredients，但仍要求完整状态相同。不同品质、损伤、腐烂等状态不能被首堆覆盖；提示已添加中英文。红包语言键从原 70 增至 71，摘要声明同步更新。

领取落地时的有状态模板也按真实堆上限拆分，例如 800→500+300；最多 1000 堆，超限在物化前拒绝，任一部分解码失败清理临时副本，不部分交付。库存领取原有拆堆路径保留。发送成功后可见日志 `PhysicalSelectionCaptured stacks=2 items=800`，只记录数量，不记录物品载荷或中继凭据。

未变更 wire、codec、模块/程序集/存储身份，也没有调整确认/恢复判据。该补丁不等于物理发送跨重启托管、未决历史核对或独立发行门槛已经全部完成。
