## 当前 UI / UX 评估与目标

当前流程已经验收安装到卸载，但界面仍呈现开发工具，不能视为正式玩家体验。仅将文字翻译成中文或英文并不能解决操作负担。

| 内容 | 玩家界面处理 | 开发与维护位置 |
| --- | --- | --- |
| 正式目录 | 固定读取，默认 GitHub | 可信配置写在客户端代码 |
| GitHub / CF | 保留快速切换；属于同一目录的访问方式 | 固定源与缓存身份校验 |
| 测试源、任意源 ID、接口地址、本地 JSON 路径 | 移除，旧设置不再决定正式入口 | 独立命令行测试工具和回归夹具 |
| 手动解析依赖、只下载不安装 | 从普通商店移除，统一为安装按钮 | 内部计划、静态验证、回源复核与整批提交保留 |
| 额外依赖 | 安装时弹出名称、版本、安装状态、总下载量供确认 | 继续严格验证完整闭包 |
| 不同版本 | 一个列表项，详情选择版本；默认最新可用版本 | 保留每版资产、摘要和兼容性约束 |
| 插件 ID、模块 ID、SHA、CLR 引用、请求编号、路径 | 不放在常规简介及状态行 | 错误详情、结构化日志和管理诊断 |
| 兼容版本、简介、作者、许可、更新日志、已安装版本、重启状态 | 保留，直接支持用户决策 | 多语言按当前游戏语言选择 |
| 旧 Mod 清理/迁移预览 | 移除玩家入口，不自动清除旧文件 | 如需排查，保留源代码及测试，但不编译旧预览 UI 到正常商店 |

| 下载阶段及字节进度 | 仍需补全，属于上线阻塞项 | 合并限频的进度回调，不增加每帧请求或日志 |
| 更新检查和版本替换 | 尚未交付，不显示能更新的按钮 | 先实现替换事务和恢复，再接入仅提示的更新检查 |

## 执行顺序

1. 固定玩家入口为 phinix.official，删除测试源选择、旧预览 UI 和开发输入字段。旧开发设置不迁移；现有安装、用户数据和启动恢复不受清理影响。
2. 移除正式 index 中的 Playtest 展示。维护者提交有原因的目录排除清单；新增目录快照并最后切换 stable，原审批、发布锁及历史目录保持原样。可见目录重新检查依赖；其他插件依赖被排除项时必须拒绝发布。未来批准新插件不能使 Playtest 再出现。
3. 清理独立测试仓库：默认分支只留最新版 Playtest 源码、打包工具、本地化和说明；只保留 v1.3.0 发布及资产/标签。删除旧测试目录发布和旧插件发布，关闭旧测试源服务。原 v1.3.0 ZIP、标签及 sourceCommit 不改写；此操作不需要把任何源码复制进正式 index。
4. GitHub 正式索引保留真实功能所需的 workflows、可信验证器、测试、审批证据和历史快照。它们是维护基础设施，不是玩家内容。维护者使用同一套标签审批流程；关闭 Issue 是拒绝，发布后的下架另走可审计目录排除。
5. CF 固定来源只保留正式 index，默认禁用已淘汰的测试路由。当前域名仍是 plugins-staging.hunyuan2333.com；正式上线前要迁移到最终域名，清点 secrets、权限、限额及运行环境，不在界面暴露配置输入。复核 GitHub 与 CF 返回同一目录字节/摘要、同一源身份。
6. 将版本合并和单按钮安装连通；核对过期确认窗口、取消、切换访问方式和失败后的重试不能触发旧计划。用真实可发布的插件做最后安装验收；Playtest 在独立开发环境以文件夹方式验证，不重新塞入正式 index。
7. 补齐下载进度、常见错误解释、空目录提示、小窗口布局和按钮状态，再执行下方人工验收，最后构建并检查发布包。不要仅凭编译成功宣称游戏内验证成功。
