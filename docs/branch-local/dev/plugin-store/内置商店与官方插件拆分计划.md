## 最终发行组成

| 功能 | 发行与管理 |
| --- | --- |
| 商店 | 主体 `Common/Extensions` 中的独立 `PluginStore.Client.dll`；语言资源随主体。默认启用 `phinix.plugin-store`，保留用户已有禁用设置；统一发现/Register/Activate/Shutdown，可停用，Mod 设置保留管理恢复入口。宿主不新增商店工程/业务类型依赖 |
| Chat、Trade、Inventory、LegacyAdapter | 暂时继续随主体发行，统一模块管理 |
| 红包 | 独立托管 ZIP：自己的 Contracts/Client DLL、manifest 和声明资源，商店索引及 gateway 下载，安装到 SaveData/Phinix/ManagedExtensions。保留 `builtin.legacy-redpacket` 和程序集/codec/设置/存储身份 |
| 人才贸易 | 独立托管 ZIP，同一路径/生命周期。保留 `builtin.legacy-talent-trade`、程序集/类型、Harmony ID、Scribe 字段及设置身份 |
| 完整 RimWorld Mod | 商店提供工坊索引/链接，玩家自行订阅，仍走 RimWorld 管理 |

商店“内置”是发行位置与默认入口，不产生特权注册机制。下载的两个业务包不写入主体或 Mods，不附带 About；基础框架、Trade/Inventory、游戏/Unity/Harmony 等由宿主已提供的程序集不复制进业务包。主包提供商店升级，首轮不实现商店自替换自身 DLL。当前独立预览商店仍存在，正式内置前必须处理新旧商店并存的重复程序集/模块，不能用枚举顺序决定版本。

## 源码审计与迁移约束

- 当前商店项目只生成 `Output/phinix-plugin-store-preview`；M6a 才改主包复制与资源。现有构建命令仍同时生成主体和独立预览。
- 红包和人才的四个 Client/Contracts 工程仍复制 DLL 到主体，产物脚本仍将它们列为必需项；停止复制不清除旧 Output，因此必须从干净发行目录验收。只删除可证明属于旧官方发行的文件，未知/改动文件不自动删，工坊更新由 Steam 执行。
- 红包直接引用 Trade.Client 中的协议实现。首轮保留编译依赖、准确锁定兼容范围、确保 host 已加载引用对象，独立包不携带副本；解耦到 Contracts 另立验证，不能顺便改 wire 或确认语义。
- 两组翻译当前在 Client/Languages；托管 Resources 不自动参与 `.Translate()`，需要真实可用的通用能力与最小调用适配。资源只读且绑定已核验包；当前 1.5.0 环境归属字段本身不是资源接口。
- `TalentTradeGameComponent` 目前依赖 `GenTypes.AllSubclassesNonAbstract` 自动实例化，并在 ExposeData 保存待返还数据。晚加载 DLL 可能遇到类型缓存或组件初始化先后问题，必须实测；仅模块 Tab 成功不足以证明人才拆包安全。
- 既有 `GetStoragePath` 指向 `framework-extensions/client/<extensionId>/...`，不同于新增 SaveData/ExtensionData。首轮保持旧路径/身份和现有内容，不顺便迁到新目录；如以后迁移，单独做有归属、可重试且保留原数据的迁移。
- 商店库存当前可检查代码/模块依赖，不能凭空知道其他插件是否有业务未决操作。拆包阶段明确未决处理及缺包保护；若需阻止危险停用/卸载，应增加通用参与者契约，由插件报告，宿主不检查红包或 pawn 专用状态。
- 旧主包仍含同名 DLL 时拒绝安装并列托管副本。退出游戏、备份数据/存档、换干净主体、装所需插件、重启核对；缺插件情况下重存人才旧档的风险不能用备份说明替代技术保留方案。
