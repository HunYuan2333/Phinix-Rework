## 事实和路径规则

服务在主线程建立，可在 Activate 中解析。`Capture()` 必须在明确的主线程操作中调用，不在 Draw 中重复扫描。宿主构造尚未结束、模块发现结果不可用时返回 `ExtensionDiscoveryNotReady`；消费方应在启动完成后重新捕获。工作线程请求直接拒绝，不执行游戏读取工厂。

快照复制已安装模组（包含未启用副本）、加载中的程序集、模块实际激活状态。RimWorld 版本来自 `RimWorld.VersionControl.CurrentMajor/CurrentMinor`；路径来自 `GenFilePaths.ModsFolderPath` 和 `SaveDataFolderPath`。模组 packageId 使用 `PackageIdNonUnique` 保留真实身份，避免把重复/工坊后缀当成新包。CLR 版本单独展示，不赋予商店管理权。

程序集归属按规范化绝对路径和完整目录边界判断，不以字符串前缀认领；空 Location、不唯一/嵌套根不猜归属。模块按程序集实际归属关联，不以 builtin 前缀或旧 SourcePackageId 的字符串推定宿主提供。无法核实模块归属、Host 根不唯一或游戏读取失败时保留 Diagnostics，商店适配器拒绝不完整快照。当前逻辑不修改原 ExtensionAssemblyLoader 或旧 ResolveModPackageId。

规划器仅把主包中实际 Active 的模块视为宿主提供。其他已加载模组的模块/程序集归其本地身份；没有明确模组归属的已加载程序集保守保留为全局冲突。已有模组来源、包版本、文件摘要均未知，不从 About、目录、CLR 版本或旧日志推断，匹配到已存在包仍阻断重复安装。未来安装记录校验器完成后才能把可信已装记录接入，当前没有冒领任何模组。

商店新数据目录固定为 `<SaveData>/Phinix/ExtensionData/phinix.plugin-store`。路径必须完全限定，扩展 ID 必须可移植，不允许路径分隔、父目录、控制字符或设备名。新目录必须在本地 Mods 根之外，改变工作目录不改变结果。分配路径不会创建目录或写文件；旧 `framework-extensions/client` 根保持原位，不迁移红包、交易、库存或 pawn 数据。

目录归属目前是词法判断，不解析符号链接；路径存在/可写、游戏扫描范围、同文件系统暂存与安装恢复仍须在步骤 1/5 验证。仅有 API 的编译结果不能证明实际 Mods 扫描或游戏启动行为。

## 验证

实际通过命令：

```bash
dotnet run --project Tests/PluginStoreRuntimeTests/PluginStoreRuntimeTests.csproj --configuration Release --no-restore
dotnet run --project Tests/Phase35RuntimeTests/Phase35RuntimeTests.csproj --configuration Release --no-restore --no-launch-profile -p:BuildInParallel=false -m:1
dotnet msbuild Phinix.sln -t:Client -p:Configuration='Release 1.6' -p:BuildInParallel=false -m:1 -verbosity:minimal
dotnet build Extensions/PluginStore/Client/PluginStore.Client.csproj --configuration Release -p:BuildInParallel=false -m:1
dotnet build Extensions/PluginStore/Client/PluginStore.Client.csproj --configuration Release --no-restore -p:BuildInParallel=false -m:1
git diff --check
```

商店 harness 通过 **142 条断言**，增加路径逃逸/设备名/相似前缀/嵌套根、快照只读、未知本地来源/版本、宿主与禁用模块、未启用副本、缺失宿主路径和工作目录变更回归。Phase35 原有框架生命周期测试及新增主线程工厂保护测试通过；宿主和商店 net472 编译通过。宿主路径不可用时只保留 Diagnostics，不因新增服务的构造打断原宿主启动。

本机 Mono 6.12 冒烟也通过：共享源码读取/依赖链、环境适配、新路径不创建目录和主线程工厂保护。测试用临时脚本扩展自第一批，不等于真实游戏验证。实际命令：

```bash
mcs -langversion:latest -r:System.Runtime.Serialization -r:System.Xml.Linq -out:/tmp/phinix-plugin-store-mono-smoke.exe /tmp/phinix-plugin-store-mono-smoke.cs Extensions/PluginStore/Client/PackageVersion.cs Extensions/PluginStore/Client/PackageModels.cs Extensions/PluginStore/Client/CatalogReader.cs Extensions/PluginStore/Client/DependencyPlanner.cs Extensions/PluginStore/Client/StoreEnvironmentAdapter.cs Client/ClientExtensionAbstractions/Framework/ClientEnvironmentSnapshot.cs Client/Source/Framework/ClientEnvironmentService.cs
mono /tmp/phinix-plugin-store-mono-smoke.exe Tests/PluginStoreRuntimeTests/Fixtures/chain.catalog.json
```

编译保留 NuGet 审计服务不可达的 `NU1900` 警告；首次恢复还出现 vendored protobuf 的旧目标框架/trim 提示。框架 harness/首次宿主依赖编译保留已有 `AuthResponsePacket.Expiry` 弃用警告。未改 vendored submodule 或关闭安全审计来隐藏警告。

初次直接构建 `Client/Source/Client.csproj` 的 `Release 1.6` 失败：独立项目构建不能继承 solution 对抽象项目的 Release 映射；改用上面的 solution `-t:Client` 完成窄构建。首轮宿主编译还发现 VersionControl 属于 RimWorld 命名空间，已修正并重新编译通过。

没有运行完整 solution、远端 CI、真实游戏/Unity Mono、Steam Overlay、网络代理、PE/归档、文件安装与重启恢复或官方拆包/历史存档迁移。下一批可接入独立商店模块和本地索引浏览；游戏/网络实际验收继续保持未完成。
