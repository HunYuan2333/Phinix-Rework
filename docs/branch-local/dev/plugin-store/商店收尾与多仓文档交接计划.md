## 当前范围

先做 Store、托管运行时、索引机器人和 Gateway 的设计哲学耦合审查，再安排有证据的局部调整、正式商店 UI 和发行包验收。红包发行由用户暂挂；红包/人才业务 Bug、主三仓迁移、全面换库、AI 作者工具与 skill 不插入本轮。已验收的安装、卸载、升级与访问方式切换不从头重做。红包未发行不阻止其余审查和交付，但不能把完整的两插件发行主线记为完成。

## 实施顺序

1. **耦合审查**：核对真实项目编译引用与源码调用，追踪 Host/抽象/插件依赖方向、普通插件发现和生命周期、策略与数据归属、GitHub/CF adapter、线程快照/派发、持久化事务与校验器副本。标注文件/行号、影响、优先级及最小处理建议；区分真实耦合、维护者配置和合理部署绑定。先审查，不顺带修复两个旧业务插件。
2. **必要局部调整**：按审查证据消除插件专用宿主分支、通用代码里的业务名称和无必要的重复实现；不降低依赖、归属、摘要或恢复检查，不为了形式统一做大规模重构。
3. **正式 Store UI**：改善详情层次、版本选择、安装/重启状态、进度和失败重试；隐藏开发字段，保留必要诊断。首版只用简介，不增加远端图片。人测中文/英文、长文本、窄窗口、缩放、取消及错误反馈。
4. **发布和产物验收**：核对宿主配置更新、固定版本资产及审批异常；检查干净主包、退役副本、独立插件和语言资源。最终给用户增量游戏清单；不把编译和自动测试当作游戏或业务恢复验收。

## 交给其他模型的文档任务

用户另选模型执行以下公开文档修改，本代理仅记录范围、要求和代码审查事实。每个仓库先提交改写提纲供用户审查，确认后再修改，单仓文档 PR 交付。
