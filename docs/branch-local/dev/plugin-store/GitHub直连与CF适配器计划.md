# GitHub 直连与 CF 适配器计划

2026-10-05 已交付：profile 身份、GitHub/CF 适配器、共用校验/缓存、默认 GitHub 和手动来源按钮。见[实现验证与开发期存储边界](仓库访问适配实现与验证.md)。下方初始审计为历史依据，目录 v3 仍待交付。


[English](RepositoryAccessAdapters.md)。2026-10-05，`dev`。用户决定：默认 GitHub，提供按钮快速切到 CF；CF 只作同一仓库的 adapter/cache 加速。本决定覆盖此前“强制 CF 分发”的客户端访问安排。直连适配器和按钮尚未实现。

## 当前实现核对

| 项目 | 当前情况 | 所需调整 |
| --- | --- | --- |
| 客户端读取 | RepositoryEndpoint 生成 CF 的 `/v1/sources/...`，Transport 拒绝跳转 | 增加 GitHub 适配器，返回同一 stable/published/catalog 字节链；不能直接把 GitHub URL 填进现有入口字段 |
| GitHub 来源核验 | 目前在 Worker GitHubOrigin：固定仓库/owner ID、分支、commit/tag、release/asset 归属、长度/摘要 | 客户端直连具备对应核验，公共源不要求每个玩家配置 token |
| ZIP 下载 | 客户端只请求 CF 固定路由；GitHub Release 跳转在 Worker 处理 | GitHub 适配器单独处理 API 请求头、有界的指定资产 CDN 跳转及类型差异；复用既有 ZIP/PE/语言校验，不放松全部 CF 请求 |
| 缓存与安装身份 | CacheKey 是 Origin + SourceId 的摘要；缓存绑定 Origin，Planner 用这个摘要核对已安装包 | 拆开稳定仓库身份与访问方式；切通道不能变成另一个插件或导致已安装包身份错误 |
| 默认与 UI | 当前默认 CF staging，只有入口/来源输入，没有切换按钮 | 两条链路验收后默认 GitHub，增加手动切换，保存选择 |
| 下载目录 | SaveData 下每包一个受管目录；Common/Extensions 支持直接子插件目录 | 保持每插件文件夹，入口选择不改变安装位置和 RimWorld Mod 管理方式 |

现状是 CF 从 GitHub 取相同发布数据，但客户端只有 CF 通道可用，不能说两边已对等。当前依赖所配置 HTTPS 入口的可信性；整条链的摘要相同不能独立证明受攻陷的 gateway 未改写目录。发布侧签名仍是独立待决项，不把缓存称为独立密码学来源证明。

## 确定的结构

1. **仓库 profile** 保存稳定 sourceId、批准的索引仓库/owner 固定 ID、发布分支、可选的批准 CF 入口。**访问方式**另存 `github | cloudflare`。作者插件仓库仍按锁定资产 ID/策略核验；名称和域名不是仓库身份。
2. 客户端只有一套仓库读取接口：当前指针、不可变描述/目录、锁定包字节。GitHub 映射到公开 API/Release；CF 映射到现有固定路由。共用格式读取、长度/摘要、连续性、依赖、载荷、安装事务。协议一致指发布对象和规则一致，不要求 HTTP URL/请求头完全相同。
3. 缓存内容与安装归属使用稳定 profile 身份，访问方式/实际主机作为审计信息。ETag 和新鲜度证据按通道隔离；离线缓存只浏览，安装仍通过所选通道完成必要的实时复核。
4. 切换时在安装提交决定之前取消任务，清掉计划/下载状态并重新读取；已经提交决定的事务完成既有恢复语义后再切换。不混用不同通道的不相关指针/描述/包，切通道仍保留同源连续性检查。
5. 新配置默认 GitHub，记住用户选择。来源面板有“使用 CF 加速 / 使用 GitHub 直连”、当前方式、结果和重试反馈。手动切换，不静默回退，不自动下载或更新。真正换仓库仍按新来源隔离身份和信任。
6. 直连的请求次数、超时、取消、元数据缓存都有限额。限流/访问失败时明确提示可手动切换；CF 回源凭据继续只留在服务端。

## 顺序调整

1. 先通过现有目录 v2 测试链发布已校验的 1.3.0 语言 ZIP，验插件发现/翻译/安装卸载；这不代表要保留 v2 兼容层。
2. **先实现 profile 身份、共用读取接口和 GitHub 直连，再改默认值/加切换按钮。**开发期直接改安装/缓存契约和样例，不加旧 endpoint 身份兼容分支。若测试安装需重建状态，清楚报错，不静默收编或删除已有目录。
3. 目录 v3 多语言展示/发布只做一套，同步接两种适配器、CF 和可信机器人校验。开发期两端与测试来源一起替换，不维护 v2/v3 双读。
4. 来源按钮随商店 UI 批次交付；随后机器人 A2 → 受控 A4 → A3，以及剩余正式发行工作。

自动验收：两通道锁定的发布对象和 ZIP 字节一致；切换仍识别同一安装，不混用 ETag；错误仓库 ID/tag/release/asset/摘要/长度拒绝；仅允许规定跳转；提交前发现撤回/变化拒绝；下载/刷新/取消时切源不能混合状态；离线缓存不能授权安装；限流/超时有界重试和清楚审计。.NET 10 与 net472/Mono 都验证。

两适配器和按钮交付后再游戏测试：免代理默认 GitHub、手动 CF 切换及重启记忆、两通道浏览下载安装、切换后已安装包仍识别、取消/断网反馈、提交前撤回/版本变化、语言资源归属。CF 实测成功不能代替游戏 GitHub 直连验收。
