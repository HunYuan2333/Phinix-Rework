## 文件与提交边界

`ManagedInstallation` 属于独立商店扩展，没有在宿主增加插件专用入口。规划可只读核验归属，无需 Mods 可写。商店记录只有在来源、完整锁定记录、清单、实际文件集合和每个 SHA-256 均重新核对后，才能用于识别已安装版本；手动包和 Workshop 包仍不归商店管理，也不冒领所有权。

- 安装目录：`<LocalModsRoot>/phinix-store-<来源和包 ID 的 32 位摘要>`，游戏显示名仍取 About/商店名称。
- 下载：保存数据中的扩展目录，Mods 外独占、关闭自动删除的临时文件。
- 暂存和卸载隔离区：Mods 的兄弟目录 `.phinix-store-<Mods 根 16 位摘要>/<事务 ID>`，不会作为 Mod 扫描。提交只使用同文件系统目录移动，跨卷失败不退回逐文件复制。
- 归属与日志：`<SaveData>/Phinix/ExtensionData/phinix.plugin-store/installation-v1/{installed,journals}`。不要靠删除这些记录消除冲突。
- 同一 Mods 根的独占文件锁、可写探测、严格相对路径、禁止符号链接/junction、CreateNew 解包、禁止覆盖。新增文件/空目录、标记缺失或变化、摘要变化、损坏及尾随内容日志都会阻止自动删除。

所有新依赖包都先下载、静态校验并解包，之后才移动任何目标目录。解包直接读取同一独占下载句柄，并逐文件重新核对长度和摘要。下载前和提交前各检查一次完整在线链；快照变化、撤回、身份变化或本地计划变化都要求重新查看计划。离线缓存不能授权安装。

目录移动前先落盘并刷新事务意图日志。下载、解包和 freshness 检查期间可以取消；开始提交后进入短暂不可取消阶段，磁盘 IO 不占 GUI 状态锁。多个目录的安装**不是原子事务**。完成后写归属记录，移除暂存树，最后退休日志，提示用户在游戏 Mod 列表启用并重启。

## 恢复与卸载

打开商店会检查已安装包并恢复未完成事务；“刷新已安装插件／恢复未完成操作”可重复执行。它发生在游戏 Mod 扫描之后，不是宿主早期加载钩子。所有目标已移动且核验完整时补全安装；只有部分提交时，对可证实且未启用/加载的目标回滚。删除前持久化 `install-rollback` 意图，因此回滚自身再次中断后，也能核对剩余已归属文件再继续。部分包已加载、记录损坏或用户改动时停止并保留现场。

卸载一次只操作一个商店归属包，不级联删除依赖。其他已安装包的必要包/module/外部依赖，以及本地/Workshop About 中声明的依赖都会阻止删除。启用或匹配 DLL 已加载时返回 `PackageInUse`：需要先禁用 **RimWorld Mod** 并重启，再卸载。仅关闭 Phinix 扩展不能卸载 CLR 程序集。

写卸载日志后，将完整目录移动到隔离区，再核对并逐个删除归属文件，归属标记最后删除。删除中断后仅在剩余文件及目录仍符合记录时继续；移动前中断则放弃卸载、保留安装记录。不删除存档、设置或已经生成的白银；不自动擦除用户添加或修改的内容。

仍有实际边界：net472 无法可移植地 fsync 父目录，不能宣称断电零风险；写失败采用注入 IOException，真实磁盘满仍待验收；游戏扫描先于商店恢复；损坏归属需要人工核对。大包峰值内存/CPU、Windows 文件系统和游戏行为仍待验收。伴随清单 DLL 安装、升级和热卸载不在这版 ZIP 候选范围内。

## 验证与游戏交接

已运行的准确构建/回归/公网命令见英文对应页；完整构建使用普通 `dotnet build`，不带触发混合目标 Rebuild 问题的 `--no-incremental`。公网命令采用实际 net472/Mono，关闭系统代理，在新建隔离 Mods 和假宿主元信息中完成真实在线链、条件刷新、包长度/摘要、七文件静态校验、同句柄解包、提交、归属和卸载，并检查不加载候选 DLL。另用真实通用 Registry 加载已编译样例，验证发现、一个 Tab Provider 注册、激活和关闭；没有绘制游戏 UI 或执行地图操作。NU1900 和旧目标警告不视为游戏证据。

日志固定字段有 `clientRequestId`、`transactionId`、source/package/version/digest、原因及 HTTP request ID，不写本地路径/凭据/响应正文。重点事件：`install.preparation_started`、`install.package_staged`、`install.journal_prepared`、`install.freshness_verified`、`install.commit_started`、`install.package_committed`、`install.committed`、`uninstall.journal_prepared`、`uninstall.quarantined`、`uninstall.committed`、`recovery.*`。扩展日志另有 `Playtest: activated`、点击次数、白银放置结果和 shutdown。

1. 退出游戏，替换已重新构建的主体 Mod 和商店预览两个目录，启用并重启。
2. 在 staging 在线刷新，选 Playtest 1.1.0，查看依赖计划，点击“安装计划中的新包”并确认。应出现已安装/重启提示及商店归属条目。
3. 在游戏 Mod 列表启用 **Phinix Store Playtest** 并重启。Phinix 应出现“商店测试”Tab，扩展管理应显示 `phinix.poc.playtest` active，并有激活日志。
4. 点击计数；加载测试地图，确认生成 100 白银，查看地图中心附近。另取消一次确认，确认取消没有生成白银。
5. 仍加载时试卸载，应提示 `PackageInUse`，不删除。可另在扩展管理禁用并重启，验证 Tab 消失；DLL 仍随游戏 Mod 加载，因此此时仍不能卸载。
6. 禁用 **游戏 Mod** 并重启，进入商店已安装列表确认卸载。再重启应没有该包的发现结果/Tab；存档、设置和已生成白银保留。
7. 删除后重复安装。取消、修改文件和提交中断在可丢弃目录中验证；出现 `RecoveryRequired` 时保留日志并提供事务 ID。

这轮游戏安装/启用/Tab/地图/卸载尚待用户验收；Windows/Steam、大包、多网络、生产缓存周期和成本约束仍未完成。
