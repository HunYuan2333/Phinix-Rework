## 术语约定

建议统一表述：**Phinix 的基础功能以模块化方式实现；商店用于分发可选扩展。** Chat、Trade、Inventory、LegacyAdapter 是内置功能模块；红包、人才贸易定位为官方可选扩展，当前仍随主包打包，独立发行尚未实现。

“扩展模块”描述统一技术机制，“扩展包”描述安装单位，“官方”描述维护者，“商店收录”描述索引与审核范围。产品分类不改变原有生命周期和禁用能力；具体词义及历史命名对应见上述术语文档。

## 已确认的方向

- 首版游戏内客户端商店，服务端暂时手动安装；商店请求支持独立 HTTP/SOCKS5 代理。
- 默认源由 Phinix 维护，允许任何作者申请；官方发布索引，作者发布 DLL，工坊索引条目链接。
- 工坊条目在 Steam 游戏内浏览器打开，由玩家自行订阅；商店不下载工坊内容，其前置依赖交给 Steam。GitHub DLL 包由作者声明版本号和依赖，商店处理 GitHub 依赖链。
- 首次入库人工批准，后续正常版本自动检查后更新索引；不等于客户端静默升级。
- 默认源 GitHub 插件必须提供可审查源码，不收录无源码 DLL。
- 增加完整开发/发布文档与 AI 指引的设计，帮助非计算机专业者完成简单插件。
- 红包、人才贸易定位为官方可选扩展，后续独立发布；Chat、Trade、Inventory、LegacyAdapter 暂时继续随主包发布。
- 商店后续按类似 Trade 的正式官方功能模块交付：独立工程/DLL、统一生命周期与禁用规则、主 Tab 和设置，随主包提供。当前独立商店包仅用于开发预览，主包打包、翻译、产物检查及避免双副本加载列入后续发行工作。

模板、发布指南、实际 `AGENTS.md`/`agent.md` 与校验工具的未来交付方案见可行性文档第 10 章，本目录不表示已存在这些工具。建议措施与已确认要求在各文档中分别标注，开发者便利不改变安全审核边界。
