## 持久化和限制

新批准凭据随 stable 原子加锁；删除/改动已接受版本锁或批准锁会被拒绝。凭据合入后若申请编辑/撤标，会阻止发布；恢复需由维护者通过审计变更移除尚未随 stable 发布的凭据，以及仅关联该申请的未发布版本元数据，再授权新标签事件；不能修改已发布锁。正常成功流程没有增加人工审批步骤。

试运行仍限制八个版本，并限制八份标签凭据、400 条 Issue 事件及原 API/ZIP/时间上限。扩容和待发布撤回自动清理后续独立处理。CF 协议/缓存和客户端归属没有变化，现有安装保持原源身份。
