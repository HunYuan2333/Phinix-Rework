# 仓库访问适配实现与验证

[English](RepositoryAccessImplementation.md)。2026-10-05，`dev`。交付[访问适配计划](GitHub直连与CF适配器计划.md)这一批；没有修改公开资产、远端发布指针或部署 Worker。下一批仍是目录 v3 多语言展示/发布。

## 已实现

- `RepositoryProfile` 固定 sourceId、公开索引仓库/owner ID、发布分支；访问方式/CF 地址单独保存。身份摘要不包含通道。自定义 gateway 没有已批准 GitHub 映射时仍按独立 gateway 来源处理。
- `IManagedRepositoryAccess` 共用 stable/published/catalog 字节链与包校验报告。CF 保留原严格 HTTP 边界；GitHub 客户端匿名读取公开 API，先固定分支提交再读取文件，核对公开仓库身份、release 状态、asset 归属/名称/长度/摘要和包标签到提交（最多五层 annotated tag），不把 target_commitish/下载 URL 当来源证明。
- GitHub 元数据拒绝跳转，资产最多五次跳转且只到规定的 HTTPS release-assets.githubusercontent.com 主机/路径；不带 Cookie/token。压缩/Range/异常类型、超限/截断/篡改和身份不符都拒绝。元数据整体 30 秒、单次读头/读体有界、每操作最多 24 次请求；包下载遵守调用者的读头/空闲/总时限。
- 两种通道共用 `ManagedPayloadTransfer`：独占临时文件、流式长度/摘要、原 ZIP/PE/清单/语言校验、结束自动清理；不执行候选 DLL。安装仍复核下载前后实时目录，复用宿主整批提交/恢复事务。
- 新 PCS3 托管浏览缓存按 profile 身份存储，保留通道出处，跨通道不复用 ETag；快照/版本连续性检查共享。旧缓存失效，不迁移；离线内容不能授权安装。
- 宿主安装输入/凭据/库存改为 `RepositoryIdentitySha256`，JSON 为 `repositoryIdentitySha256`，开发期直接替换原 endpoint 字段。目录仍按来源/包独立管理，不生成 RimWorld Mod。已知同一 profile 切 GitHub/CF 不影响归属，真正换仓库不能静默认领旧包。
- 当前内置 phinix.managed 测试来源默认 GitHub；“商店来源”增加 GitHub 直连/CF 加速按钮、当前方式和重试反馈，记住用户选择。任务忙时禁止切换，先取消或完成；切换后清空旧目录/入口/计划并重新读取，失败不会留下旧安装计划可用，确认框也检查计划是否被替换。没有自动回退或更新。
- 审计增加通道/profile 摘要、受限 GitHub request ID、剩余额度/重置/重试信息及明确拒绝原因；不输出签名 URL、原始响应、凭据和本地绝对路径。本地可信机器人 24 份生产快照/provenance 已同步，不代表远端工作流已经更新。

目前 profile 对应受控测试仓库/分支；任意手填 gateway 地址不会自动获得 GitHub 映射。仍通过当前 catalog v2 测试链工作；v3 商店多语言、发布器、CF/bot 同步是下一批。
