# 远端目录协议与浏览缓存实现

日期：2026-10-03，`dev` 分支。P0 的 metadata 草案与 P2 的本地实现已交付；CF/R2 服务及正式发布仍未交付。此前用户通过的是本地浏览基础游戏清单，不能扩展成当前网络功能的游戏验收。

## 当前实现

- `RepositoryEndpoint` 只接受规范 HTTPS origin 和单一 source ID，不接受路径、凭据、query、fragment 或编码绕过；可有非默认端口。所有资源由固定路径生成，无 GitHub fallback。
- `RepositoryMetadata` 复用现有严格 JSON reader，独立解析 v1 stable/published；metadata 上限 16 KiB，catalog 上限 2 MiB。交叉校验 source、40 位 snapshot、catalog schema、原始 hash/精确大小，检查索引 Release/asset 固定身份字段。新增 descriptor 路由为 `/v1/sources/{source}/snapshots/{snapshot}/published/{publishedSha256}`。
- `RepositoryTransport` 使用 net472 BCL HttpClient，禁止自动 redirect、压缩和 cookies，保留正常 TLS 验证；只接受完整 200 UTF-8 JSON，处理有有效缓存的 304，限制 Content-Length 和实际读入字节。429、5xx、其他 HTTP、响应类型/长度/摘要失败有独立错误。未读取或展示错误页正文；标准 gateway 错误 envelope/requestId/retry 时间和商店独立代理尚待后续接入。
- `RepositoryBrowser` 先取得 stable，再定位固定 descriptor/catalog；已有完整相同快照可复用字节。304 缺少有效完整缓存或 validator 不一致时，只允许一次无条件重新取 stable；再次 304 失败。已观察的相同 snapshot 不允许替换描述或目录；相邻已验证快照的同版本包不能变更固定身份、manifest 元数据或资产。新快照可以撤回内容未变的包。这不是永久防回滚账本或签名。
- 缓存位于 `SaveData/Phinix/ExtensionData/phinix.plugin-store/repository-cache/<SHA256(origin+换行+source)>/catalog.cache`。单个有界 bundle 包含配置身份、成功检查时间、ETag 及完整原始链；重新读取再次校验。缓存路径拒绝已观察的 links/junctions，这是浏览缓存保护，不是安装归属或抗文件系统竞态证明。
- 写入和刷盘在后台 staging 文件完成；主文件仅在 controller 的取消/代次检查后作原子替换。失败保留旧 bundle，无 delete-then-move 降级。迟到、取消和 timeout worker 不能提交缓存，正常失败/取消清理自身 staging。刷盘及名称原子替换仍需实际游戏文件系统验收；不保证断电后的目录 metadata 持久性，进程强制中断遗留的 `.tmp` 尚未自动回收。
- 页面支持保存 endpoint/source、“在线刷新目录”和明确的“离线浏览缓存”；无需服务器登录。端点默认空，源默认 `phinix.official`，不伪造生产 URL。本地 JSON 样例移至可展开测试工具，保留旧路径设置。游戏路径只在 UI 操作时主线程 Capture，IO/解析不在 Draw 中执行。
- 当前在线/本地/离线都只能浏览和计划预览，没有文件下载或安装。离线显示成功检查时间，30 分钟过期或刷新失败显示旧缓存状态。启动后在线刷新失败时，玩家可明确使用离线浏览按钮读取有效磁盘缓存；不拿浏览 freshness 授权安装。切换 origin/source 清空不匹配的展示，防止把其他源的旧目录当作当前目录。

Controller 复用 metadata/规划的十秒整体 watchdog 和最多两个未结束 worker 限制；包下载必须另定连接/空闲/总超时。刷盘发生在锁外，只有最终名称替换与取消状态按顺序完成，不在 UI 线程运行网络或整包写入。

## 草案和测试输入

[固定向量及双语说明](metadata-protocol-v1/README.zh-CN.md)包含现有官方空目录和合成 Release/asset ID。`build-repository-metadata.py` 是**本地协议生成器草案**，创建不可覆盖的 `published/<snapshot>.json` 并在最后写 stable；没有调用 GitHub、创建 Release 或独立核实所有包。不能把它当完整可信发布器。

当前未签名，信任用户配置的 origin/TLS。同路径 hash 不独立防 gateway 伪造批准记录。正式来源配置、签名选择、304 的 Age/Date freshness、发布核验、Worker origin adapter、资源预算和实际 CF/R2 行为仍属后续批次。
