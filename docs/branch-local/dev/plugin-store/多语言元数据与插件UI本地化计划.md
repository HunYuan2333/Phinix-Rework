## 当前实现与缺口

- 商店自己的按钮/提示已有随主体发布的中英文翻译。
- 目录 schema v2 的 `name`、`summary` 是单一字符串；`name` 还与 manifest 的规范名称关联，不能直接换成随游戏语言变化的值。
- Playtest 用内嵌中英文词典测试 Tab/按钮，没有使用通用托管本地化服务。
- manifest 可以声明、校验并安装 `Resources/*` 文件，但没有自动注册到 RimWorld 的 Languages/`.Translate()`。M6b 已计划通用资源/本地化能力；此前尚未细化多语言商店名称/简介与回退规则。

## 作者可以只提供一个语言

- 允许仅有 `en-US`、仅有 `zh-CN`，或者其他一种受支持标识的语言。没有英语或没有中文不构成拒绝上架/加载的理由。
- 多种语言可选；作者提供多少种就使用多少种，不自动调用翻译服务或下载语言文件。
- 单一语言包直接用这份内容显示，即使游戏语言不同，也不显示空白或裸 key 来强制作者补语言。
- 语言标识在边界规范化（例如输入 `en-us` / `zh-cn`），与 RimWorld 语言身份通过宿主映射关联；不能要求作者依赖具体游戏语言目录名。
- 可声明默认语言，默认语言必须在已提供集合中。单语言可直接推导默认项；多语言未声明时使用确定顺序选择，不能依赖文件枚举顺序。

## 显示和缺译回退

名称、简介、版本 changelog 以及插件 UI 文本采用统一原则：

1. 当前游戏语言的精确匹配。
2. 同语言的合适变体/基础语言，按明确的地区与文字体系匹配规则选择。
3. 插件提供的英语（`en` 或合适的英语变体）。
4. 插件声明的默认语言。
5. 插件实际提供的任一种语言，按稳定顺序选择。

示例：只有 `zh-CN` 时，英文游戏也显示作者提供的中文；同时提供 `zh-CN`/`en-US` 时，中文游戏用中文，英文游戏用英文；不支持的游戏语言优先用英语，没有英语就用声明默认/实际可用语言。

回退按字段/翻译 key 处理，不能因为选中语言缺少一个按钮就丢掉其他已匹配文本。所有语言都缺少某 key 时使用调用方默认文案或可见的 key，并输出限频诊断；不静默变为空白。缺少一种目标语言是正常回退，不是错误。

## 商店多语言名称与简介

- 保留包 ID、模块 ID、CLR 名称、manifest 规范名称、版本和固定资产身份；它们不本地化。多语言名称是展示元数据，不改变归属或包发现。
- 增加按语言提供的显示名称/简介；changelog 沿用同一选择原则。现有单文本可作为默认展示内容，迁移时不要求旧作者立即补多语言。
- 译文跟随受校验目录快照/版本缓存，限制单条与合计大小并转义显示；不额外拉取外站 README/图片/语言文件。
- 列表、详情、搜索和测量缓存响应语言切换；显示文本不能成为包标识或合并依据。
- 当前严格 schema v2 不接受额外字段。实施时冻结显式新格式版本/兼容迁移，同步客户端、发布工具、Worker 和机器人可信校验器；不能先向旧目录塞字段导致整份目录被拒绝。

## 托管插件自己的 UI 语言资源

- 插件通过清单声明包内语言资源，并走现有路径/长度/摘要和 ZIP 校验。一个语言文件即有效；多文件可为各自语言提供相同 UI key 的译文。
- 宿主提供通用、按包/模块隔离的只读资源与本地化能力，契约位于客户端抽象层；内置、官方拆包和第三方使用同一路径。插件不依赖商店业务类，也不靠商店保持启用才能显示翻译。
- Tab 标题、按钮、设置、确认窗口、工具提示、通知/错误说明等可见文字从该能力取值。保持稳定 key，不把翻译文本当保存字段、网络协议或审计原因码。
- 统一处理语言选择、逐 key 回退和格式占位符；语言切换更新文本及布局缓存，不能只在 Register 时固定翻译结果。游戏语言读取/翻译与界面更新遵循主线程边界。
- 已停用/卸载插件的资源注册和缓存按生命周期释放；不同包的同名 key 不冲突，不允许覆盖宿主或其他插件语言内容。卸载不删除用户设置/业务数据。
- 语言资源是有界数据，不执行脚本，不自动注入游戏全局翻译表或依赖原生 Mod 扫描；文件格式与具体服务签名在实现时冻结。

## 机器人与作者交付

- 在 A2–A4/格式升级时检查语言标识、默认语言存在、重复键、大小、资源归属/摘要、格式占位符和作者声明的 UI key 覆盖。
- **不得要求所有插件必须提供英语/中文或两份文件。** 一种有效语言即可通过本地化格式检查；缺少游戏当前语言只触发回退。
- 静态检查不能证明所有自定义 Draw 文本都使用翻译接口；指南、模板和人工/游戏验收补充，不宣称机器人能证明全部 UI 已翻译。
- 当前 A1 仍使用 schema v2 与生产源码快照，尚不检查多语言语义；不能在语言资源服务未实现时标为支持。官方红包/人才贸易已有中英文资源，其迁移验收保留两语，不将官方已有内容的验收要求变成第三方最低语言数量要求。

## 顺序与验收

按[最新排期](发布格式与实施顺序调整.md)先冻结格式/资源契约（R1），贯通客户端兼容解析与发布校验（R2），提前完成 M6b 通用资源/本地化部分并验 Playtest（R3），再统一改商店 UI（R4）。格式冻结后接 A2 与受控 A4，验收通过再启用 A3 自动发布；可信校验器更新后才开放新格式申请。

至少验证：仅 `en-US`、仅 `zh-CN`、仅其他语言；多语言精确/变体匹配；没有英语时回退到作者默认/可用语言；部分 key 缺译；长文本/占位符；切语言刷新 Tab/详情/布局；重复键/非法默认语言/篡改资源拒绝；停用/卸载不残留注册；商店关闭时已装插件翻译仍可用。本轮仅记录架构要求，未改变现有格式、运行代码或已发布资产。
