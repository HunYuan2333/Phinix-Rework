## 本批实现

- 两 Client 插件接入现有 `IClientLocalizationService.ForModule(this)`；自己的中英文语言 JSON、companion 摘要与实际 UI/消息调用一起迁移。共享/game key 仍走原所有者的 Verse 翻译。语言事件/重新绑定使 UI 缓存失效，停止时释放 localizer 和事件。
- 主体旧 Keyed XML 移除，构建复制自己的资源和 `.dll.localization.json`，并精确删除对应旧生成 XML。不要只更新 DLL：覆盖完整 `Output/phinix-rework` 到测试 Mod，包含 `Common/Extensions/Resources`。
- 人才入队、保存、队列取消/拒绝、解码失败不清空原始待返还数据；当前挂牌快照与未决恢复合并，已撤销的当前挂牌不保留为旧备份。成功本地投放才移除，投放边界异常保留并禁止自动重放。投放后图形失败不造成二次返还。
- 回调检查 Game/组件/激活状态，跨档旧回调跳过；有界队列拒绝新回调而不驱逐已接受的工作。结构化 `talent.pending_return` 日志记录时间、原因和存档/挂牌标识，不包含 pawn 原文；异常状态为 Warning。

## 自动验证与复现

命令从仓库根目录运行。本机实际游戏引用目录为 `/mnt/data/SteamLibrary/steamapps/common/RimWorld/RimWorldLinux_Data/Managed`；其他机器换成自己的 RimWorld 1.6 编译引用目录。首次构建新 harness 先 restore；本轮已完成 restore。串行构建避免旧式/SDK 工程共享引用的并发问题。

```sh

dotnet run --project Tests/ManagedExtensionRuntimeTests/ManagedExtensionRuntimeTests.csproj --configuration Release --framework net10.0 --no-build

dotnet build Tests/TalentReturnRuntimeTests/TalentReturnRuntimeTests.csproj --configuration Release --no-restore -p:SolutionDir="$PWD/" -p:RimWorldDepDir=/mnt/data/SteamLibrary/steamapps/common/RimWorld/RimWorldLinux_Data/Managed -p:BuildInParallel=false -m:1
dotnet Tests/TalentReturnRuntimeTests/bin/Release/TalentReturnRuntimeTests.exe
mono Tests/TalentReturnRuntimeTests/bin/Release/TalentReturnRuntimeTests.exe

dotnet build Tests/RedPacketInventoryRuntimeTests/RedPacketInventoryRuntimeTests.csproj --configuration Release --no-restore -p:SolutionDir="$PWD/" -p:RimWorldDepDir=/mnt/data/SteamLibrary/steamapps/common/RimWorld/RimWorldLinux_Data/Managed -p:BuildInParallel=false -m:1
dotnet exec --runtimeconfig Tests/RedPacketInventoryRuntimeTests/runtimeconfig.json Tests/RedPacketInventoryRuntimeTests/bin/Release/RedPacketInventoryRuntimeTests.exe

dotnet build Phinix.sln --configuration "Release 1.6" --no-restore -p:RimWorldDepDir=/mnt/data/SteamLibrary/steamapps/common/RimWorld/RimWorldLinux_Data/Managed -p:BuildInParallel=false -m:1
```

结果：托管元数据/资源/恢复总计 1624 条父进程断言，现有启动子进程各 18/18/16/16/20 条通过；实际人才队列、组件快照与两客户端翻译 facade 在 .NET 与 Mono 下各 31 条通过；红包库存/发送托管/历史核对 8 组通过。整套主体/商店构建 0 错误，7 条已有 protobuf/obsolete 等警告。测试运行不调用真实人物落地或 Scribe 保存。

PowerShell 本机不可用，未运行 `.github/scripts/check-artifacts.ps1 -IncludeClient`；以 Python 等价检查其 32 个必需路径、LoadFolders、禁止游戏 DLL，并另外逐项核对构建资源的长度/摘要/所有者/源码一致性及旧 XML 清理。没有声称做过 Docker 构建或游戏验证。

额外完整重建尝试中，`dotnet build Phinix.sln ... --no-incremental` 失败：客户端先生成 net472，后续服务端共享工程的 Rebuild 清理又移除了这些引用，最终 34 条 CS0006 缺引用错误。按客户端工程依赖链可恢复；最终复现采用 **整套 clean 一次，再普通 build**，不在此商店切片修改多目标工程的 Rebuild 行为。该失败不能记成完整重建通过。

## 现在需要用户测试

退出游戏后覆盖完整测试 Mod，并先备份测试存档。本批优先使用两插件仍随主体存在的情况。

1. **中英 UI**：红包/人才 Tab、设置、详情和提示均显示正常，无裸 key；切换游戏语言后重新打开页面/存档，缓存标签也切换。年龄与版本说明正常，无 `\\n` 原文。
2. **人才正常返回**：在测试会话保存一个自己的未售挂牌，然后退出并读档。人物经空投只返还一次；再保存该档并重新读入，没有重复人物。记录名字/数量及 `Returned` 日志。
3. **停用后重存**：保留该挂牌存档的另一份副本，停用人才模块并重启，读入副本另存；启用并重启后读入另存文件，待返还内容仍存在且只交付一次。这里测试的是停用，不是删除 DLL。
4. **跨档与红包冒烟**：另一个存档不出现前一个存档的人物；红包的库存选择、发送、领取和正常返回未退化。多人 ACK/断线恢复另作专项，不拿本机空投测试代替。

若出现 `Deferred`、`Uncertain`、`uncertain-retained`、`queue-full-retained`、`invalid-or-duplicate-retained`、`active-backup-uncertain`、`active-payload-unavailable`，提供该事件前后的日志、两次操作顺序和游戏版本。未决内容应仍在待返还字段中；uncertain 不自动重放，不要为了重试删除它或覆盖唯一原始存档。
