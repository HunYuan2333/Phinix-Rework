# 宿主引用向上兼容验收

[English](HostReferenceUpgradeAcceptance.md) · 2026-10-06

按用户要求，托管插件引用宿主已提供的库时，允许同主版本升级。这是所有插件共享的规则，不给人才贸易或 Harmony 单独开例外。

| 插件所需 → 宿主实际提供 | 处理 |
| --- | --- |
| `2.3.6.0` → `2.3.6.0` | 优先精确版本 |
| `2.3.6.0` → `2.4.1.0` | 放行 |
| `2.3.6.0` → `2.3.5.0` | 拒绝降级 |
| `2.x` → `3.x` | 拒绝跨主版本 |
| 名称、语言或公钥不同 | 拒绝 |
| 没有精确版本、却有多个兼容升级版本 | 拒绝歧义 |

`ManagedAssemblyIdentity` 提供统一规则，安装/启动预检和打包器共用。只放宽外部宿主库引用；包自身/声明依赖包的 CLR 身份、内容哈希、manifest、包版本和游戏/Host 兼容范围仍严格锁定。

启动时再次核对真实已加载程序集与宿主声明，冻结“旧引用 → 实际程序集对象”。解析器只为归属插件的已检查声明引用返回启动前已有的对象，不探测文件、不加载额外 DLL、不接管其他调用者、不采用后来加载的新版本。`ManagedHostReferenceUpgraded` 审计记录所需和实际身份。不会改写插件字节或原始引用。同主版本是采用的兼容政策，不保证每一个 API 都兼容；真实类型/加载失败仍按现有路径报错。

本地可信校验器两份源码快照和摘要同步更新；未修改远端索引、网关或人才已发布 ZIP。更新主包后可复用人才 1.0.1。

实际构建、运行、打包及检查命令见 [English companion](HostReferenceUpgradeAcceptance.md#validation-performed)。.NET 10 与 net472/Mono 各通过 1661 条主断言及六个真实加载/注册子进程（18、18、18、16、16、20）。新增覆盖截图里的 Harmony 身份、跨主版本/降级/语言/公钥/名称、精确版本优先、多版本歧义、候选规划与自有 DLL 版本不允许放宽。

真实子进程预载宿主 helper 1.3.0.0，而插件仍引用 1.2.3.4；两个运行时均完成插件注册中的实际 helper 调用，解析对象和升级审计断言通过。77 项机器人回归通过，可信校验器/打包器构建通过，真实打包器接受新宿主 helper、保留原插件引用。首次还原有 NuGet 漏洞检查源不可达 `NU1900` 和既有 protobuf trimming 警告，未改 vendored 文件或增加构建绕过。主包/商店构建 0 错误、7 条缓存 NuGet/protobuf/废弃 API 警告；已核对产物 Utils 等于新 net472 二进制，等价扫描无游戏 DLL 或退役可选 DLL。完整主包构建日志 `/tmp/phinix-host-reference-main-build.log`；没有宣称游戏、Scribe 或旧服务联机通过。原生 PowerShell 不可用，主包沿用等价产物扫描。

游戏验证：退出 RimWorld，替换完整 `Output/phinix-rework` 主包，包括 `Common/Assemblies/03-Utils.dll`，只更新商店 DLL 不会更新 Host 规则。保持 Harmony 2.4.1，刷新商店并重试人才 1.0.1 安装，无须重发人才包；重启后看是否只出现一个人才 Tab，设置/语言正常。真实加载失败提供审计代码。人物持久恢复与缺包重存仍另行验收，继续使用备份测试存档。
