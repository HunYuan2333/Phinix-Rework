## 已实现

宿主已有 `IClientLocalizationService.ForModule()`，本批复用其普通激活/停止和语言事件，不增加宿主业务分支或公共 API。红包 70 个、人才 112 个文本键迁入各自 `Resources/<插件>/Localization/en-US.json`、`zh-CN.json`；两 Client DLL 旁携带带路径、长度、SHA-256 的 companion 声明。原主 Mod 的两插件 Keyed XML 已移除，构建只清理对应的旧生成 XML。

真实静态、动态及条件翻译调用改用包作用域 resolver。Inventory/框架/游戏键继续由原所有者的 Verse 翻译解析；两插件不往游戏翻译字典注入键。语言事件与重新绑定使缓存失效，停止时退订和释放。人才年龄由拼接前导空格改为编号参数，版本说明的 XML `\n` 转为 JSON 换行。资源改动后运行 `.github/scripts/update-bundled-localization.py` 更新声明，`--check` 可检查摘要过期；语义/格式由真实框架解析测试校验。

人才修复前有两处清空风险：入队后立即清空 pending，保存时完全覆盖 pending。现在保留读档恢复账本，保存合并未决返回与当前挂牌快照，已撤销的当前挂牌不残留为旧备份。仅在本地投放 API 正常返回后移除记录；反序列化/准备失败保留，投放边界异常保留原载荷并标为 uncertain，下一次读档不自动重放。重复 ID、缺失字段不物化，原始载荷留存。当前挂牌的缓存突然缺失时，保留已捕获的备份，但按所有权未知标记 uncertain；不能因为缓存没了就自动再次生成 pawn。没有可用载荷时保留挂牌 ID 并告警。

回调检查组件与 Game 身份及激活状态，旧档回调不进入新档。队满拒绝新回调，不驱逐已接受的所有权工作，返还入队失败仍保留记录。投放后的图形刷新失败不会把已交付误判为可重试。结构化 `talent.pending_return` 日志含 code、saveToken、listingId、时间，异常状态为 Warning，标识转义且限长，不记录 pawn 原文。

## 身份与依赖仍保留

- 红包 Contracts 引用 Trade.Contracts/Utils；Client 还引用 Inventory.Contracts、Trade.Client、抽象/UserManagement 和自身 Contracts。未来包只带自己的 DLL/资源，保留 `builtin.legacy-redpacket`、codec、设置与存储路径及实际 Trade/Inventory 前置。
- 人才 Contracts 无其他 ProjectReference；Client 引用自身 Contracts、抽象/UserManagement、Utils，以及游戏/Harmony。保留 `builtin.legacy-talent-trade`、程序集/类型、Harmony ID、GameComponent 与旧 Scribe 字段；新增 `pendingReturnUncertainIds`。不能虚构 Trade 依赖。

## 尚未通过的发行门槛

本批确定性测试和真实编译不等于游戏 Scribe/人物落地验收。新增 uncertain 字段是存档中的恢复状态，不是外部持久事务日志；入队/标记本身不能证明磁盘已经写入。没有新增远端下架 ACK，也不宣称旧市场跨存档回滚的全局恰好一次语义已经解决。

模块停用时其 GameComponent 仍因 DLL 随主体存在而被游戏发现，本批保存守卫保留现有字段。**真正移走 DLL、晚加载组件发现、缺插件打开并重存后的数据保留仍未验证**；这与普通停用不同。两包独立发行前必须补通用加载/存档保留方案及真实游戏证据，不把人才类型或 pawn 业务放进 Host，不无条件清空游戏类型缓存。

红包既有库存、发送托管与历史核对回归通过，但断线/未知结果/重启的真实中继确认仍是独立发行门槛。先完成人测和恢复核查，再建两个仓库、固定不可变包、走正规索引准入，验收后才移除主体产物。S2 整体尚未完成，其他专项继续后置。
