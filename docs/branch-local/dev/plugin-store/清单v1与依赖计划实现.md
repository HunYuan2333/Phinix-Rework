## 2. 当前格式

索引根字段全部必需：

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 数字整数 `1`；未知版本拒绝 |
| `sourceId` | 小写标识，必须等于调用者选定的源 ID |
| `snapshotId` | 40 位小写十六进制提交标识；当前格式不含可变分支名 |
| `packages` | 包版本/工坊记录数组，最多 1024 条；同包最多 32 个版本 |

源 ID、包 ID、RimWorld packageId、模块 ID 使用小写 ASCII 字母/数字及点、下划线、连字符分隔；不含路径或空分段。输入为无 BOM UTF-8，最多 2 MiB、深度 32。未知字段、重复字段、非预期类型、额外根对象、尾逗号、注释、控制字符和类型元数据拒绝。字段名按规范直接写 ASCII；BCL 映射的特殊/转义字段名保守拒绝，不静默忽略。

GitHub 包记录必需：

- `id`、`name`、`author`、`license`、`channel: "github-release"`、`rimWorldPackageId`、`integrationKind`、`state`、`version`。
- `integrationKind` 为 `phinix-extension` 或 `rimworld-mod`；`state` 为 `active`、`withdrawn`、`unmaintained`，只有 active 可加入新计划。状态是索引策略，不由包内自述覆盖。
- `version` 为稳定三段版本；每段为 0 至 Int32.MaxValue 的规范十进制，不接受前导零、第四段、tag 前缀、预发布或 build 后缀。`versionRange` 仅支持精确版本和 `>=x.y.z <x.y.z`，一个空格，下界含/上界不含；拒绝通配、caret、OR 和其他表达式。
- `compatibility` 必含 `targetFramework: "net472"`、非空 `rimWorldVersions`（如 `1.6`）。Phinix 扩展还必含 `phinixRange`、`abstractionsRange`；普通 patch 包不强制有 Phinix 前置。兼容版本由未来游戏适配器提供，未知时阻断，不能猜测当前安装版本。
- `dependencies` 数组包含 `packageId`、`versionRange`、布尔 `optional`；只解析同一源里的必需 GitHub 依赖，optional 默认不安装。
- `modules` 数组包含 `id`、`dependsOn` 字符串数组；Phinix 扩展必须非空，普通 RimWorld 模组必须为空。
- `assemblies` 数组包含真实 simple `name`、规范四段 CLR `version`、可移植单组件 `fileName`；不得重复名字或大小写碰撞的文件路径。代码包必须至少声明一个程序集。
- `externalMods` 数组包含 `packageId` 和可选 `workshopId`；仅输出前置提示/链接，绝不递归下载工坊。
- `artifact` 必含 `repository`（owner/repo）、十进制字符串 `repositoryId` / `ownerId` / `releaseId` / `assetId`、40 位 `sourceCommit`、匹配包版本的 `tag`（可带 v）、`assetName`、`payloadKind`、64 位小写 `sha256` / `manifestSha256` 和整数 `sizeBytes`。数字 ID 为非零 UInt64，下载声明最多 128 MiB。不接受任意 download URL、分支源码定位或占位摘要。

载荷声明支持 `rimworld-mod-zip` 和 `dll-with-manifest`。单 DLL 必须恰好声明一个程序集，资产名等于其文件名。此处仅验证元数据，尚未验证 ZIP 布局、实际 PE 身份、About、资源或生成模组壳；不能将通过读取视为可以安装。

工坊记录保留共同展示/身份/集成类型/状态字段、`channel: "steam-workshop"`、仅含 `rimWorldVersions` 的 compatibility、十进制字符串 `workshopId`，以及空 dependencies/modules/assemblies/externalMods。禁止伪造包版本或 artifact。URL 只从有效 ID 生成 `https://steamcommunity.com/sharedfiles/filedetails/?id=...`；当前没有调用 Steam、订阅或安装行为。

完整可解析形状见 [chain.catalog.json](../../../../Tests/PluginStoreRuntimeTests/Fixtures/chain.catalog.json)。该文件为本地测试数据，仓库 ID、提交和摘要均是合成值；不能发布或用作实际下载源。

## 3. 包内清单与哈希顺序

包内 `phinix-package.json` 根为 `schemaVersion: 1` 和 `package`。package 使用上述 GitHub 记录字段，但**禁止 `artifact`、`state`、`workshopId`**：发行资产/包内清单的哈希不能包含自己，审核状态也不属于作者清单。

正确顺序：生成清单 → 对清单原始字节计算 SHA-256 → 放入包并生成资产 → 对资产计算 SHA-256 → 填索引 artifact。纯 DLL 的清单是伴随文件，不写进 DLL。`VerifyManifest` 先比对锁定的清单摘要，再解析并核对包身份、版本、元数据、兼容、依赖、模块、程序集和外部模组。v1 交叉校验要求这些数组顺序一致；实际解包/伴随清单获取仍待下载层实现。

客户端不会 `Assembly.Load` 候选、执行作者脚本或构建作者代码。当前只检查声明的受保护程序集名（游戏、Unity、Steam 绑定、框架和主包共享 DLL），不能证明声明与实际二进制一致，也不能证明代码安全。静态 PE/归档检查属于后续必需工作。

## 4. 计划语义和故障结果

调用者选择一个精确 GitHub 包版本，再提供主线程捕获的环境与本地身份快照。求解固定同一个索引对象，合并所有约束，按稳定顺序尝试最高可兼容版本；约束冲突或环路可回溯到较旧候选。共享依赖只出现一次，输出依赖优先顺序；模块 DependsOn 另查缺失/环路，不能把包图当作模块生命周期图。

可信本地包须由未来适配器核实文件、清单和来源后提供旧接受记录；旧日志、文件夹名称或 AssemblyVersion 都不足以构成证据。满足要求的已装版本优先保留，不重复下载；未启用有 `NeedsEnable` 提示。已装版本不符合要求、来源未知/不同、同版本资产或清单变化、工坊/手动同身份、模块/程序集冲突均阻断。没有可核实版本的本地副本不猜测兼容，也不被覆盖。

本地主包提供模块只作为环境事实，不按 `builtin.*` 推定内置、可信或自动下载。只有实际包闭包或宿主已提供的模块可满足模块依赖；目录中恰好存在的无关包不替代作者声明。

结果保存 SourceId、SnapshotId、实际索引字节 SHA-256、完整包记录、版本、摘要、下载总量及外部前置提示；源刷新或原集合改变不修改已生成计划。最多 64 包、包/模块依赖深度 32、4096 检查步、5 秒；可取消。达到预算报告 `ResolutionLimit`，不冒充已证明“无解”。错误带可区分 code 和包/约束原因，UI 翻译层尚未接入。

计划不会下载文件、修改启用列表、激活代码、触及既有业务数据或声称外部前置已满足。没有 UI 确认、安装日志和恢复事务；这些继续由主计划步骤 4/5 交付。
