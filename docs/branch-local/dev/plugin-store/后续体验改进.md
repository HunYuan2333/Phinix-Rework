## 版本归在同一个条目

- 同一插件的不同版本合并为一个列表条目，在详情里选择下载版本；默认选择最新有效发布版本，版本号按版本规则排序。
- 分组按来源与包 ID，保留每个版本的固定资产、摘要和兼容信息；不同来源的同名条目不能借分组混用身份。
- 最新版本不兼容时明确说明原因并允许选择兼容旧版本，不静默改选旧版本。撤回版本可留在版本历史中标注原因，不提供新安装。
- 明确展示已安装版本、所选版本、最新版本与待重启状态，避免列表里的多个版本看起来像多个插件。

## 启动检查更新，只提示

- 启动后后台检查已安装插件是否有新版，在商店/扩展管理中提示；不阻塞游戏启动。
- 只检查目录元数据，复用缓存与请求合并/限频；失败不影响当前插件加载，不按每帧轮询。
- 不自动下载、覆盖安装或启用新版。玩家主动查看版本与 changelog，并主动发起更新。
- 当前安装器不支持原位升级；提供正式“更新”操作前单独实现并验证版本替换、依赖变化、归属检查、重启生效及中断恢复。检测到新版不等于升级功能已完成，也不假定旧代码回退能回退业务数据。

## 展示开发者填写的 changelog

- 版本详情及更新提示展示开发者填写、对应所选版本的更新说明；未填写时显示“暂无更新说明”。
- changelog 纳入受校验的目录/发布数据，跟随版本和固定快照；补目录格式、发布工具、作者指南及客户端支持，不临时绕过严格格式校验。
- 首版使用有长度上限的可滚动文本，保持纯文字，不增加远端图片或浏览详情时的额外外站请求。

## 普通玩家只需要一个“安装”入口

- 将“查看依赖计划 → 下载并校验（暂不安装） → 安装插件”的常规操作合并为一个“安装”按钮。
- 点击后内部自动解析依赖、检查兼容/本地冲突、下载、校验并提交安装。用户不需要先手动生成计划或先下载一个不安装的包。
- 不需要新增依赖时直接继续安装；需要额外安装依赖时弹窗列出依赖名称/版本、原因和下载总量，确认后安装整批，取消则停止。外部 Mod 前置缺失、版本冲突或不兼容仍明确说明，工坊路线继续只提供链接，由玩家订阅。
- 依赖规划与下载校验仍是内部必经步骤；提交前目录状态复核、全部文件校验、事务一致性和审计保留。简化的是用户操作，不是这些内部检查。
- “只下载校验”和手动查看依赖计划可移至开发/诊断入口，不作为普通安装前置。

## 下载反馈与统一 UI 改进

- 展示阶段（解析、下载、校验、安装提交、完成/待重启）、当前包、已收/总字节和整体进度；耗时操作有明确反馈。
- 取消、重试、错误详情和待重启提示清晰可见；提交决定后的取消语义继续遵循现有安装事务。
- 统一优化列表/详情布局、版本选择、简介/changelog、按钮状态与错误文案。进度限频推送，不在每帧读取目录或输出日志；不加入远端图片。

## 正式发布前移除旧预览 Mod 迁移入口

- 正式版可删除为旧 1.1.0 本地 Mod/旧安装记录准备的回退、迁移与清理界面（包括“旧 Mod 安装记录 / 清理工具”），普通用户不需要看到开发预览的遗留操作。
- 在正式发行清理批次检查关联代码、文档和产物；必要的开发诊断另行保留，不自动删除用户旧 Mod 或未知目录。
- 这项清理不删除新托管插件的正常卸载、设置/存档保留、安装中断恢复及重复程序集检查，也不等于删除官方拆包所需的历史存档兼容支持。
