## 公共能力与职责边界

`Client/PresentationContracts/UI/IClientPresentationService.cs` 新增 `ClientPresentationRow.WithControls`（最多四个公共动作、一个文本/整数输入）与 `ClientPresentationSplitView.WithSharedFooter`（跨双栏的独立滚动下区，可固定区头）。不增加 Unity/Verse、Thing/Pawn 或交易类型。现有 row 装饰复制保留控件。API3 本地合同加法；程序集身份仍为 3.0.0.0。当前独立三插件不调用新成员，既有 API3 双版插件包可继续使用；本次新成员由同一 Host 包内同步更新的 Trade 消费，不承诺新 Trade DLL 与旧 Host 混用。

`Client/Source/UI/ClientPresentationService.cs` 统一执行所有行/节动作：所有权、唯一 ID、一次执行、版本有效性、待处理输入、公共确认及生命周期不变。节/组合动作维持 32 上限；含行的页面总动作有界至 544，行字段另有 256 上限，普通字段维持 32。只读报价列表拒绝控件。行测量与渲染共用控件换行布局，控件区域排除行选择命中，使用既有 GUI 清理/主题/input adapter。共享下区选择不重置双方报价的滚动或导航。

`Extensions/Trade/Client/TradeList.cs` 为每行收集真实类型 action point，保持选中详情的第三方动作；视图组合拥有这些短期 action sets，替换/关闭释放全部。每行回调捕获自己的交易，不能依赖选中项而错开另一笔。

`Extensions/Trade/Client/TradeWindowPresentation.cs` 负责输入、草稿与布局。`TradeWindow.cs` 仅在现有重置、刷新/关闭的草稿生命周期中清理新 UI 状态。原报价托管、回执、预留、Scribe/物品转换、协议、地图交付和 R44 均未改动。Host 没有交易专用 renderer、第二套主题/动作或物品业务。

## 游戏验收

使用一次性测试存档，双方客户端同批候选；先 1.7，再回归 1.6。更新完整 Host，不拼装单 DLL；当前 API3 独立双版插件保留，无须改正式商店目录。

1. 两笔以上交易直接打开未选中的行，核对对方；取消的确认正文必须属于该行。取消等待期间不可重复提交，关闭列表不取消另一笔。
2. 双方报价并排正确，包括空报价、单向赠送、接受/撤回状态；量大的报价左右独立滚动。窄窗口、UI 缩放、中英文、长名称与换主题后输入/按钮可达。
3. 不先选中物品，连续输入两个数量，搜索隐藏其中一行再显示，草稿保留。超过可用数量、空草稿、负数、整数溢出均不提交；错误隐藏时仍禁提交，但可取消/重置已有报价。
4. 明确提交后等待真实报价回执，核对扣取、对方收到的数量和状态；重复点击、拒绝/断线不重复扣取，不靠关闭窗口返还。
5. 刷新、地图/库存变更及重新打开后不遗留草稿或错用输入焦点；多个报价窗口的草稿和动作不串交易。中文输入、搜索/数量切换焦点、IME Enter 不误提交。
6. 红包/人才/Example/商店仍可打开、使用公共主题与确认、导入/禁用/卸载；主题编辑、热应用、导出及第三方入口保持可用。
