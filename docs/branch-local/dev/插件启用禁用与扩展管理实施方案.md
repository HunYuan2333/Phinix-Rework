## 1. 背景与目标

### 1.1 触发需求

当前 Phinix 框架的插件化程度已相当高——Chat、Trade、LegacyAdapter 及第三方 submod 均通过统一的 `IPhinixExtensionModule` 机制发现、注册、激活。但存在三个空白：

1. **无启用/禁用机制**：所有被发现的扩展无条件走完 `Discover → Register → Activate` 全流程（`PhinixExtensionRegistry.cs:31-84`、`:261-286`）。用户无法选择性地关闭某个插件。搜索 `enable|disable|Enabled|Disabled|IsActive|ShouldActivate|Skip` 在 `Common/Utils/Framework/` 下**零匹配**（仅 `ExtensionAssemblyLoader.cs` 日志中的 `Skipped` 与生命周期无关）。

2. **ExtensionManagerTab 只读**：`ExtensionManagerTab.cs:11-331`（TabOrder=999）展示插件列表+状态+加载日志，但**无任何操作能力**——刷新按钮是 no-op（提示重启 RimWorld），无开关，无依赖关系展示。

3. **无依赖解析树**：搜索 `dependency|Dependency|Requires|DependsOn|topological|TopologicalSort|LoadOrder` 在整个代码库**零相关匹配**。插件间通过 `TryResolveApi<T>()` 隐式协作（`FrameworkTypes.cs:460-474`），无声明式依赖关系。禁用某个插件时无法预知对依赖它的插件的影响。

### 1.2 目标（按优先级）

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| **P0** | 用户可在 Mod Settings 页勾选启用/禁用任意扩展 | 勾选禁用 → 重启 RimWorld → 该扩展不进入 Register/Activate，状态显示为 `Disabled` |
| **P0** | 依赖声明机制（`DependsOn`） | 插件可通过 `[PhinixExtension("id", DependsOn = new[]{"dep.id"})]` 声明依赖；禁用某插件时，依赖它的插件被标记为 `DependencyDisabled` 并显示警告 |
| **P0** | 老插件兼容降级 | 无 `DependsOn` 声明的插件在 UI 中标记"未声明依赖关系"，不报错不阻断 |
| **P1** | ExtensionManagerTab 增强为可操作 | Tab 内显示开关列（与 Mod Settings 同步）、依赖关系树、禁用警告摘要 |
| **P2**（架构预留） | 运行时即时切换 | `IExtensionActivationPolicy` 可替换为运行时实现；本文档定义接口但 v1 不实现运行时逻辑 |

### 1.3 非目标

- **v1 不实现运行时即时激活/关闭** —— 这需要运行时 Activate/Shutdown 调度、UI 重建、handler 管线动态增删、事件订阅/退订，复杂度高。v1 仅做架构预留（`IExtensionActivationPolicy` 接口），具体运行时切换留待 v2。
- **v1 不做完整拓扑排序** —— 轻量方案只构建依赖图用于"禁用时警告"，不改变扩展加载顺序。当前加载顺序（`Type.FullName` 字母序，`PhinixExtensionRegistry.cs:28-29`）维持不变。
- **v1 不做级联禁用** —— 禁用 X 时，依赖 X 的 Y 标记为 `DependencyDisabled` 并警告，但**不自动禁用 Y**。用户需自行决定是否也禁用 Y。完整级联禁用留待后续。
- **v1 不做循环依赖检测** —— 轻量方案仅记录依赖关系，不检测循环。若出现循环依赖，依赖图构建时记录 warning 但不阻断。
- **不修改 `IPhinixExtensionModule` 接口** —— 遵循 §6 增量原则，依赖声明通过特性而非接口，避免破坏第三方实现。
- **不改变 DLL 文件名编号前缀方案** —— 编号前缀（`01-`、`02-`...）仍控制 RimWorld `ModAssemblyHandler` 的加载顺序，本方案不触碰。

## 2. 设计哲学合规要点（必须遵守）

本方案所有设计决策均以《设计哲学.md》为基准。下列条款在实施过程中**不得违反**：

| 哲学条目 | 对本方案的约束 |
|----------|---------------|
| **§1.1 插件平权** | 启用/禁用机制平等对待 Chat/Trade/LegacyAdapter/第三方 submod。不得在 host 中硬编码"官方插件不可禁用"。全部可禁用是平权的体现 |
| **§1.2 host 不依赖插件** | 启用/禁用决策在 host 层（`IExtensionActivationPolicy`），host 不通过引用具体插件工程来判断"谁是谁"。依赖图通过 `ExtensionId` 字符串匹配，不通过类型引用 |
| **§1.3 host 只做通用服务** | 扩展生命周期管理（启用/禁用、依赖图、状态展示）是通用服务，非业务逻辑 → 在 host。具体插件的业务语义不关心 |
| **§2.1 松耦合** | `IExtensionActivationPolicy` 是接口，v1 静态实现可被 v2 运行时实现替换，发现机制零改动 |
| **§2.3 减少硬编码** | host 不得硬编码"哪些插件可禁用"。禁用列表来自用户设置（`Settings.disabledExtensions`），动态读取 |
| **§3.5 错误隔离** | 依赖图构建失败、单个扩展的 `DependsOn` 声明无效 → 记录 warning，不中断发现流程 |
| **§3.8 日志与可观测性** | 所有启用/禁用决策、依赖图构建过程、跳过扩展的行为均通过 `hostContext.Log` / `ILoggable` 上报 |
| **§5.3 版本化与 API 兼容** | 新增接口/枚举值/特性属性 = `MINOR` 版本升级；不修改既有接口签名；`[PhinixExtension]` 构造函数保留原签名 |
| **§6 渐进式迁移** | 每阶段独立可编译、可运行、可验证；`Host/Core 仅做增量更新` —— 枚举追加、特性加可选属性、新增方法而非修改既有方法 |

## 4. 架构设计

### 4.1 核心抽象：`IExtensionActivationPolicy`

将"哪些扩展启用"的决策与发现机制解耦，为 v1（静态重启生效）→ v2（运行时切换）的渐进路径提供替换点。

**定义位置**：`Common/Utils/Framework/FrameworkTypes.cs`（共享契约层，client/server 双端可用）

```csharp
/// <summary>
/// 决定一个已发现的扩展是否应被激活。
/// v1 使用 <see cref="StaticActivationPolicy"/>（从设置读取一次性快照）。
/// v2 可替换为运行时可变实现，支持运行时激活/关闭扩展。
/// </summary>
public interface IExtensionActivationPolicy
{
    /// <summary>
    /// 判断指定扩展是否应被激活。在 DiscoverExtensions 实例化模块之前调用。
    /// </summary>
    /// <param name="extensionId">扩展唯一标识符</param>
    /// <param name="reason">若返回 false，输出不激活的原因（用于日志和 UI 展示）</param>
    /// <returns>true 表示应激活；false 表示应跳过</returns>
    bool ShouldActivate(string extensionId, out string reason);

    /// <summary>
    /// 当前被禁用的扩展 ID 快照（用于 UI 展示）。
    /// v1 实现返回静态集合；v2 实现返回实时状态。
    /// </summary>
    IReadOnlyCollection<string> DisabledExtensions { get; }
}
```

**v1 实现：`StaticActivationPolicy`**

**定义位置**：`Client/Source/Framework/StaticActivationPolicy.cs`（新文件，host 层）

```csharp
internal sealed class StaticActivationPolicy : IExtensionActivationPolicy
{
    private readonly HashSet<string> _disabled;
    private readonly ExtensionDependencyGraph _dependencyGraph;

    public StaticActivationPolicy(
        IEnumerable<string> userDisabledExtensions,
        ExtensionDependencyGraph dependencyGraph)
    {
        _disabled = new HashSet<string>(userDisabledExtensions, StringComparer.OrdinalIgnoreCase);
        _dependencyGraph = dependencyGraph;
    }

    public IReadOnlyCollection<string> DisabledExtensions => _disabled;

    public bool ShouldActivate(string extensionId, out string reason)
    {
        if (_disabled.Contains(extensionId))
        {
            reason = "User disabled via Mod Settings";
            return false;
        }

        // 检查依赖项是否被禁用
        IReadOnlyList<string> disabledDeps = _dependencyGraph.GetDisabledDependencies(extensionId, _disabled);
        if (disabledDeps.Count > 0)
        {
            reason = $"Dependencies disabled: {string.Join(", ", disabledDeps)}";
            return false;
        }

        reason = null;
        return true;
    }
}
```

**关键设计点**：
- `ShouldActivate` 在 `DiscoverExtensions` **实例化模块之前**调用——被禁用的扩展连 `Activator.CreateInstance` 都不执行，彻底跳过
- `reason` 输出参数让发现流程能把原因写入 `ExtensionDiscoveryResult.StateDetail`，供 UI 展示
- v2 只需替换此实现为可变版本（带事件通知），`PhinixExtensionRegistry` 零改动

### 4.2 依赖声明：扩展 `[PhinixExtension]` 特性

**修改位置**：`Common/Utils/Framework/FrameworkTypes.cs:493-504`

```csharp
[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
public sealed class PhinixExtensionAttribute : Attribute
{
    public string ExtensionId { get; }

    /// <summary>
    /// 此扩展依赖的其他扩展 ID 列表。可选——老插件不声明则视为无依赖。
    /// 被依赖的扩展被禁用时，本扩展将被标记为 <see cref="ExtensionModuleState.DependencyDisabled"/>。
    /// </summary>
    public string[] DependsOn { get; set; } = Array.Empty<string>();

    // 保留原构造函数签名（增量兼容）
    public PhinixExtensionAttribute(string extensionId)
    {
        if (string.IsNullOrEmpty(extensionId))
            throw new ArgumentException("Extension ID cannot be null or empty.", nameof(extensionId));
        ExtensionId = extensionId;
    }
}
```

**兼容性分析**：
- `DependsOn` 是属性初始化器（`{ get; set; }`），有默认值 `Array.Empty<string>()`
- 老插件代码 `[PhinixExtension("builtin.chat")]` **无需任何修改**——反射读取 `DependsOn` 得到空数组
- 构造函数签名不变——所有现有用法编译通过
- 特性是 `[AttributeUsage(Inherited = false)]`，不会影响子类

```csharp
    // ... 原有 legacy 组件发现 + 优先级排序逻辑不变 ...

```

**关键设计点**：
- `policy == null` 时行为与现状完全一致（全部激活）——**向后兼容**
- 被跳过的扩展仍创建 `ExtensionDiscoveryResult` 并加入 `discovered.ExtensionResults`——这样 `ExtensionManagerTab` 能展示"被禁用的扩展"及其原因
- 被跳过的扩展**不**加入 `discovered.Extensions` / `discovered.Modules`——后续 `ActivateExtensions` 自然不会处理它们
- 依赖图构建在实例化之前——即使被禁用的扩展代码有 bug，也不影响依赖图（纯反射读特性）

### 4.7 host 启动流程改造

**修改位置**：`Client/Source/Client.cs:155-178`

在 `ExtensionAssemblyLoader.LoadAssemblies` 之后、`new PhinixFrameworkClient` 之前插入：

```csharp
// 【新增】构建依赖图（需要先扫描程序集，此时 DLL 已加载到 AppDomain）
// 注意：依赖图构建依赖候选类型扫描，与 DiscoverExtensions 内部扫描逻辑一致。
// 为避免重复扫描，可将扫描逻辑提取为公共方法，或由 PhinixFrameworkClient
// 在 DiscoverExtensions 内部构建依赖图后通过属性暴露。
// 推荐：让 DiscoverExtensions 内部构建依赖图并放入 DiscoveredPhinixExtensions，
// ActivationPolicy 在 DiscoverExtensions 内部从 hostContext 解析。

// 【新增】注册 StaticActivationPolicy 为服务
var activationPolicy = new StaticActivationPolicy(
    Settings.DisabledExtensions,
    dependencyGraph);  // 依赖图来源见上注
extensionHostContext.AddService<IExtensionActivationPolicy>(activationPolicy);

// 原有逻辑不变
frameworkClient = new PhinixFrameworkClient(netClient, authenticator, userManager, extensionHostContext);
```

**依赖图获取的推荐方案**：让 `PhinixExtensionRegistry.DiscoverExtensions` 在内部构建依赖图，并将其存入 `DiscoveredPhinixExtensions`（新增 `DependencyGraph` 属性）。但 `ActivationPolicy` 需要在 `DiscoverExtensions` **之前**就拿到依赖图——存在鸡生蛋问题。

**解决方案**：分两步——
1. 新增公共静态方法 `PhinixExtensionRegistry.ScanCandidateModuleTypes()`，返回候选类型列表（可被外部调用，不触发实例化）
2. host 在调用 `PhinixFrameworkClient` 构造前：先 `ScanCandidateModuleTypes()` → `ExtensionDependencyGraph.Build()` → 构造 `StaticActivationPolicy` → 注册服务 → 再构造 `PhinixFrameworkClient`

这样依赖图在 `DiscoverExtensions` 之前就绪，且不重复扫描。

## 5. 兼容性与降级

### 5.1 老插件无 `DependsOn` 声明的处理

| 场景 | 行为 | UI 提示 |
|------|------|---------|
| 老插件被禁用 | 正常禁用，无依赖检查可做 | 无特殊提示 |
| 老插件的某依赖被禁用 | 无法检测（老插件没声明依赖） → 老插件仍激活，但运行时 `TryResolveApi` 可能返回 null | UI 标记"(未声明依赖关系)"灰色提示 |
| 新插件依赖老插件且老插件被禁用 | 新插件的 `DependsOn` 声明了老插件的 ID → 新插件被标记 `DependencyDisabled` | 正常警告 |

**关键原则**：老插件的"未声明"不报错、不阻断——只是无法享受依赖保护。UI 提示是为了鼓励插件作者后续补充声明。

### 5.2 禁用核心插件的影响说明

由于"全部可禁用（平权）"，用户可能禁用关键插件。UI 应在禁用时提供影响说明（但不阻止）：

| 被禁用插件 | 影响 | UI 提示文案 |
|-----------|------|------------|
| `builtin.chat` | 聊天功能完全不可用；依赖 chat 的插件受影响 | "禁用后聊天功能不可用" |
| `trade` | 交易功能完全不可用 | "禁用后交易功能不可用" |
| `builtin.legacy-adapter` | 无法连接旧版 Phinix 服务器（Legacy 模式） | "禁用后无法连接旧版服务器" |

这些提示文案通过翻译键定义，不硬编码在 host 逻辑中——host 只提供"该插件被禁用的影响"数据机制，具体文案由插件自描述（可选，未来扩展）或 host 提供通用默认。

## 6. 渐进更新路径（v1 → v2）

### 6.1 v1（本方案）—— 重启生效

```
用户在 Mod Settings 勾选禁用 → Settings.disabledExtensions 持久化
    ↓
重启 RimWorld
    ↓
Client 构造函数：
    1. ScanCandidateModuleTypes() → 候选类型
    2. ExtensionDependencyGraph.Build() → 依赖图
    3. new StaticActivationPolicy(Settings.DisabledExtensions, dependencyGraph)
    4. hostContext.AddService<IExtensionActivationPolicy>(policy)
    5. new PhinixFrameworkClient(...) → DiscoverExtensions 咨询 policy → 跳过被禁用的
```

### 6.2 v2（架构预留）—— 运行时切换

v2 需要补齐的能力（本方案仅预留接口，不实现）：

| 能力 | 说明 | v2 实现要点 |
|------|------|------------|
| 运行时 `Activate` 单个扩展 | 从 `DiscoveredPhinixExtensions` 中取出被跳过的模块，调用 `Register` + `Activate` | 需要 host 持有 `discoveredExtensions` 引用并暴露 `ActivateExtension(id)` 方法 |
| 运行时 `Shutdown` 单个扩展 | 调用 `IActivatablePhinixExtensionModule.Shutdown`，并从 handler 管线列表中移除其贡献 | `DiscoveredPhinixExtensions` 的各 List 需支持动态增删；handler 管线需支持运行时重排序 |
| UI 重建 | `ServerTab` 需要重新拉取 `IMainTabProvider`/`IServerSidebarProvider` | `ServerTab` 构造函数当前一次性缓存 providers，需改为可刷新 |
| `IExtensionActivationPolicy` 可变 | 替换 `StaticActivationPolicy` 为 `RuntimeActivationPolicy`，带 `EnabledChanged` 事件 | host 订阅事件，触发 Activate/Shutdown |
| 依赖项运行时禁用传播 | 禁用 X 时，运行时 Shutdown 所有 `DependsOn` 包含 X 的扩展 | 依赖图已就绪，复用即可 |

**替换点**：v2 仅需替换 `StaticActivationPolicy` 为 `RuntimeActivationPolicy`，`PhinixExtensionRegistry.DiscoverExtensions` 的 policy 咨询逻辑零改动。这是 `IExtensionActivationPolicy` 抽象的核心价值。

```
ExtensionDependencyGraph.Build(moduleTypes):
    dependencies = new Dictionary<string, List<string>>()
    dependents   = new Dictionary<string, List<string>>()
    undeclared   = new HashSet<string>()

    for each moduleType in moduleTypes:
        attr = moduleType.GetCustomAttribute<PhinixExtensionAttribute>()
        extensionId = attr?.ExtensionId ?? moduleType.Name  // 回退到类名

        if attr == null or attr.DependsOn == null or attr.DependsOn.Length == 0:
            undeclared.Add(extensionId)
            dependencies[extensionId] = empty list
        else:
            deps = attr.DependsOn.ToList()
            dependencies[extensionId] = deps
            for each depId in deps:
                dependents.GetOrAdd(depId).Add(extensionId)

    return new ExtensionDependencyGraph(dependencies, dependents, undeclared)


GetDisabledDependencies(extensionId, disabledSet):
    deps = dependencies[extensionId]
    return deps.Where(d => disabledSet.Contains(d)).ToList()


GetDependents(extensionId):  // 谁依赖我——禁用我时影响谁
    return dependents[extensionId] ?? empty
```
