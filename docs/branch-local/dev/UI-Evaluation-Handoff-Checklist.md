# 本轮结束与 UI 评估交接标准

日期：2026-10-11。用户要求明确做到什么状态结束，并在可以开始 UI 评估时告知；插件 API 语义用普通 Example 展示。UI/UX 重构不由本任务实现，线上发行仍延期。

## 最新约束

用户明确：接口目标是广泛开放接入点、形成一致规范并在 Example 实验，第二点不要求每个 API 有内置消费者。新增接入规范见 Plugin-Api-Integration-Standard.md；以下门槛以此为准。内置迁移是推广和旧入口删除的核对事项，不能再作为所有新增 API 的前置。

## 1. 本轮范围

收尾到“本地功能与接口语义可评估”，不把 A4 的所有游戏挂点或所有便利 API 都做成结束前置。覆盖本轮已选的主题/商店与普通作者入口，不额外扩成完整游戏 SDK。UI 评估要看真实运行状态、交互和错误路径，不等待线上发布或取得三端桌面验收条件。

交接只针对上表“本轮采用”的接口。新增需求或评估里的 A4 单列后续，不无限扩大本轮。如果某项被明确移出本轮，应记录具体原因和影响，不能只为宣告结束藏掉必要的安装/恢复或结果语义。

## 3. 如何使用 Example

每份示例只消费公开当前契约，服务借用、注册/lease 拥有，Compose 无工作副作用，Activate 绑定实际模块，Shutdown 释放。Example 不模仿旧 1.9 分支、不替代 Host/业务插件实现、不伪造真实交易/物品确认。

在 Example 上先展示：当前能力状态、可用/禁用及原因，读取资源/快照，提交操作与观察状态，关闭/取消后的失效。真实业务相关能力区分真实 provider 与示例模拟；内置消费者可用于推广，但不是每项新增 API 的硬前置。不能因为 Example 自己弹出菜单或保存一个设置就认为跨插件扩展/商店事务已验证。

现有计数操作与任务回调不同：计数在主线程同步保存，任务成功只表示回调执行完，不代表设置再次保存或远端确认。取消/失败演示只作用于无游戏业务的回调，不修改殖民地/库存。

## 4. 告知时点

上表本轮实现、制品和操作步骤完成后，明确报告“本轮实现已收尾，可以开始 UI 评估”，附候选包、评估入口、关注状态和未验收项。游戏内 UI 评估本身是交接后的工作，不要求提前拿其结果来判定是否可以开始评估；若有已知阻断启动/激活/操作的错误，先修复再交接。

目前尚未达到这一时点，不能把本次 Example 首批升级当作整轮结束。
