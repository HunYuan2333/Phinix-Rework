# 人才贸易（Talent Trade）插件移植与适配实施方案

> 2026-07-31，基于 Talent Trade mod（GitHub: CagierAsh123/-CA--Talent-trade，本地副本 `C:\Users\zydyo\Desktop\Phinix\-CA--Talent-trade`）源码与其自带文档（ARCHITECTURE/PROTOCOL/FILES）实测编写。
>
> **本文档是方案文档，不是已实施记录。** 移植模板与《红包插件移植与适配实施方案》一致：**保留老协议与中继以兼容现网老客户端，UI/服务/日志走 Rework 新流程，命名全面隔离**。

**决策记录**：
- **通信与状态：保留老方案** —— v1 文本协议（`PHXTT|v1`）+ HTTP 中继（`http://114.55.115.143:8080`，房间 `talent-trade`，无 API key）+ 客户端确定性复制状态机，**与现网 Talent Trade 老客户端互通**。
- **Pawn 传输：原样保留** —— `PawnSerializer` / `PawnDeserializer` / `DefManifestHelper` 是 RimWorld Scribe 原生能力，框架没有等价替代，不"改造"；只解耦它们对 `Client.Instance` 的间接引用（实际无依赖，序列化器独立）。
- **UI：走新流程** —— `IMainTabProvider`（1 Tab 3 子面板）、`Window`、`IClientSettingsPanelProvider`，删除 ServerTab/ChatFilter/RootUpdate 补丁。
- **保留 2 个游戏级 Harmony 补丁** —— `GenScene.GoToMainMenu`（退出存档下架挂牌）与 `PawnTextureAtlas.GC`（原版 KeyNotFoundException 修复）。二者是 RimWorld 层修复，框架无等价挂点，不触碰框架管线（§3.7 边界内）。
- **解耦原 mod 耦合** —— `Client.Instance.Uuid / Online / TryGetDisplayName / GetUserUuids(true)` 全部替换为框架服务。
- **命名隔离** —— 插件名 `LegacyTalentTradeExtension`，扩展 ID `builtin.legacy-talent-trade`，设置键 `legacyTalentTrade.*`，翻译键 `Phinix_legacyTalentTrade_*`；给作者后续新版（`TalentTradeExtension` / `builtin.talent-trade`）留出干净命名。

## 1. 背景与目标

### 1.1 触发需求

Talent Trade（人才贸易）是 Phinix 的 Pawn 交易附属 mod：玩家间**直接交易、公共市场、租借**殖民者，Pawn 以 RimWorld Scribe XML 序列化后经 HTTP 中继传输，接收方反序列化并以空投舱送达。

原实现与红包 submod 同构：Harmony 补丁注入 ServerTab / Root.Update / 聊天过滤；状态全部在客户端复制；中继为独立部署（`114.55.115.143:8080`，房间 `talent-trade`）。

Rework 采用插件化架构。本方案把 Talent Trade 移植为 Rework 插件，**保留老协议与中继以兼容现网老客户端**，同时把 UI、服务访问、日志切到 Rework 新流程，并解掉对原 `Client.Instance` 的硬编码耦合。

### 1.2 保留什么、替换什么

| 保留（兼容性红线） | 替换（现代化） |
|--------------------|----------------|
| v1 线格式 `PHXTT|v1|`（23 种消息 + Blob 分片 + Def 交换） | UI：Harmony 补丁 + 硬编码 tab index → 框架挂载点 |
| HTTP 中继（同一地址/房间，与老客户端同总线） | 资源访问：`Client.Instance.*` → 框架服务 |
| 客户端确定性复制状态机（直交/市场/租借/Blob/去重） | 日志：`Verse.Log.*` / 无分级 → `hostContext.Log`（§3.8） |
| `PawnSerializer` / `PawnDeserializer` / `DefManifestHelper`（Scribe 原生能力） | 线程：自建 `MainThreadQueue` → `IClientMainThreadDispatcher` |
| 2 个游戏级 Harmony 补丁（GenScene / PawnTextureAtlas） | 设置：`TalentTradeSettings`(ModSettings) → `IClientSettingsPanelProvider` |

### 1.3 目标（按优先级）

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| **P0** | 与老 Talent Trade 客户端互通 | 老客户端 A 上架/发起交易，新插件客户端 B 可浏览/响应，双方状态一致（同一中继房间） |
| **P0** | **双向收发（硬性验收）** | ① 新插件能发送（上架/购买/交易/租借各消息）；② 能接收并完整处理（状态机 + Blob 重组 + Pawn 生成）；③ 新↔新 双向同样成立 |
| **P0** | Pawn 传输行为不变 | `PawnSerializer`/`PawnDeserializer`/`DefManifest` 逐行迁移，XML 往返结果一致 |
| **P1** | UI 走新流程 | Tab / 3 子面板 / 交易窗 / 设置面板走框架挂载点，删除 ServerTab/ChatFilter/RootUpdate 补丁 |
| **P1** | 解耦原 mod 耦合 | 源码中无 `Client.Instance.*` 直接引用 |

### 1.4 非目标

- **不做服务端权威记账** —— 银子支付为物品 XML 传输的信任模型（老方案固有，行为保留）。
- **不改线格式、不引 protobuf** —— v1 文本协议即线格式；新增字段按"尾部追加兼容"处理。
- **不修老方案的已知问题** —— Pawn 反序列化的 hediff/need 警告（RimWorld Scribe 时序）、并发交易竞态等，行为与老客户端一致，不做"顺手改进"。

## 2. 原 mod 现状精确定位

### 2.1 组件清单

| 组件 | 职责 | 本方案处理 |
|------|------|------------|
| `TalentTradeProtocol` | `PHXTT|v1` 文本协议（23 种消息 build/parse、字段 base64） | **迁移保留**（线格式） |
| `TalentTradeTransport` | HTTP 中继轮询/发送队列 + GZip/Base64 压缩 | **迁移保留**，按 §3.6/§3.8 加固（有界队列、日志分级） |
| `TalentTradeManager`（75KB） | 状态机：直交/市场/租借/Blob 重组/去重/主线程队列/信件 | **迁移保留**，适配 Rework 服务 |
| `PawnSerializer` / `PawnDeserializer` | Scribe XML 往返（`ScribeSaver.DebugOutputFor`）、空投生成 | **迁移保留**（Scribe 主线程约束不变） |
| `DefManifestHelper` | Def 清单生成/差异对比（`defs`/`dack` 兼容预检） | **迁移保留** |
| `TalentTradeTab` + 3 面板 + `DirectTradeWindow` | Tab UI（Patch ServerTab 注入）与直交窗口 | **重写**：`IMainTabProvider` + `Window` |
| `ChatFilterPatches` ×4 | 聊天列表/未读/渲染过滤协议消息 | **删除**（协议不走聊天管线） |
| `ServerTabPatches` ×3 | Tab 注入 + Enter 拦截 | **删除**（`IMainTabProvider`，Rework ServerTab 已全局处理 Enter） |
| `RootUpdatePatches` | 每帧驱动 Manager.Update | **删除**（Timer + `IClientMainThreadDispatcher`） |
| `GenSceneGoToMainMenuPatch` | 退出存档下架自己的挂牌 | **保留**（游戏级补丁） |
| `PawnTextureAtlasGCPatch` | 原版 `PawnTextureAtlas.GC` KeyNotFoundException 修复 | **保留**（游戏级补丁，1.6 实测） |
| `TalentTradeMod` + `TalentTradeSettings` | Mod 入口 + 设置页 | **重写**：插件入口 + `IClientSettingsPanelProvider` |

### 2.2 v1 线格式（保留，即线格式）

```
PHXTT|v1|<type>|field1|field2|...
```

- 普通字段（ID/UUID/数字）：直接写入；含特殊字符文本（玩家名/Pawn 名）：Base64。
- 大数据（完整 Pawn XML）：GZip → Base64；超长拆为 `blob` 分片（`partIndex` 从 0 起，接收方全收集后拼接还原再按普通消息处理）。
- 去重键：`消息类型枚举名|parts[3]`（不足 4 字段不去重）。
- 压缩工具：`TalentTradeTransport.Compress/Decompress`（GZip）。

### 2.3 消息类型一览（23 种）

| 业务 | 类型码 |
|------|--------|
| 直接交易 | `treq` `tacc` `trej` `toff` `tlock` `texe` `tcan` |
| 公共市场 | `mlist` `mdel` `mbuy` `msell` `mpaid` `msync` |
| 租借 | `rlist` `rdel` `rrent` `rconf` `rret` `rexp` `rdead` `rrev` |
| Def 交换 | `defs` `dack` |
| 大数据分片 | `blob` |

### 2.4 状态机现状（实测，行为红线）

- 四组字典：`MarketListings` / `RentalContracts` / `ActiveTrades` / `PendingBlobs`，各自独立锁；`ProcessedProtocolKeys` 去重；主线程队列投递游戏操作。
- 市场：`mlist` 上架（含 PawnSummary + 价格）→ `mbuy` → 卖家 `msell` 发 Pawn 数据 → 买家空投收人 → `mpaid` 发银币物品 XML。
- 直接交易：`treq` → `tacc/trej` → `toff` 报价（JSON）→ `tlock` 锁定 → `texe` 双方互发 Pawn 数据。
- 租借：`rlist` → `rrent` → `rconf` 发 Pawn → 到期 `rexp` 自动归还 / `rdead` 死亡通知 → 出租方 `rrev` 用备份复活。
- 防御检查：`RequestDefCheck` / `RequestRaceCheck` → `defs`/`dack` 预检缺失 mod 的装备/植入体。
- 退出存档：`OnExitSave()` 下架自己所有挂牌（防幽灵挂牌）。

### 2.5 Pawn 序列化约束（高风险红线）

- `PawnToXml` 仅在 `Scribe.mode == Inactive` 时执行，**必须主线程**（Scribe 非线程安全）。
- 反序列化经 XML → Pawn → `SpawnViaDropPod`（`TradeUtility.SpawnDropPod` / `DropPodUtility.DropThingsNear`）。
- mod 缺失 def 安全跳过；已知 hediff/need 警告是 RimWorld Scribe 时序问题，**保留不修**。

## 3. 目标架构（老方案 + 新流程）

### 3.1 总体

```
LegacyTalentTradeExtension.Client（Rework 插件，单端）
┌────────────────────────────────────────────────────────┐
│ 兼容层（老方案，行为红线）                                │
│  ├─ TalentTradeProtocol     ：PHXTT|v1 23 种消息        │
│  ├─ TalentTradeRelay        ：HTTP 中继（同地址/房间）    │
│  ├─ TalentTradeStateMachine ：直交/市场/租借/Blob 状态机  │
│  ├─ PawnSerializer/Deserializer/DefManifest（原样）      │
│  └─ 游戏级补丁：GenScene / PawnTextureAtlasGC           │
├────────────────────────────────────────────────────────┤
│ 新流程层（现代化）                                        │
│  ├─ UI  ：TalentTradeTab(IMainTabProvider)              │
│  │        Market/Rental/DirectTrade 面板 + 交易窗(Window)
│  │        TalentTradeSettingsPanel(IClientSettingsPanelProvider)
│  ├─ 服务：IClientSessionContext / IClientUserDirectory
│  │        / IClientMainThreadDispatcher / hostContext.Log
│  └─ 入口：[PhinixExtension("builtin.legacy-talent-trade")]
└────────────────────────────────────────────────────────┘
```

### 3.2 兼容层：协议与中继（迁移）

- `TalentTradeProtocol` 原样迁移（含 blob/def 消息构建与解析）。
- `TalentTradeTransport` 迁移为实例 `TalentTradeRelay`，加固点：
  - 队列有界（§3.6）：发送/接收各设上限（如 1024，blob 分片多），超出丢最旧记 Warning；
  - 日志走 `hostContext.Log`（§3.8）：轮询/发送失败 WARNING、路由 DEBUG；**去掉对 `TalentTradeMod.Settings.EnableDebugLog` 的静态依赖**，改由插件设置读取；
  - 异常隔离（§3.5）：失败退避重试，不中断；
  - 清理：`Shutdown` / 断线时清空队列与游标。
- **与老客户端互通条件**：同一中继地址 `http://114.55.115.143:8080`、同一房间 `talent-trade`、无 API key（与红包中继不同部署，需各自保留地址常量）。

### 3.3 兼容层：状态机（迁移，行为不变）

`TalentTradeManager` 迁移为插件内状态机，**逻辑逐行对齐**：

- 市场/租借/直交/Blob 四个状态集合与锁不变；`ProcessedProtocolKeys` 去重键不变；
- `Handle*` 各消息处理、信件（购买/交易/租借通知）、银币物品传输逻辑不变；
- `RestoreMyListingsOnLogin` / `CacheMyListingsOnLogout` / `OnExitSave` 生命周期逻辑保留；
- 主线程投递由 `IClientMainThreadDispatcher` 承担（Tick 经 Timer 200ms 封送主线程，同红包方案）。

**适配点**（仅替换依赖，不改行为）：

| 原引用 | 替换为 |
|--------|--------|
| `Client.Instance.Uuid` | `IClientSessionContext.Uuid` |
| `Client.Instance.Online` | `IClientSessionContext.Authenticated && LoggedIn` |
| `Client.Instance.TryGetDisplayName(uuid, out name)` | `IClientUserDirectory.TryGetUser(uuid, out ImmutableUser)` → `DisplayName` |
| `Client.Instance.GetUserUuids(true)` | `IClientUserDirectory.GetUsers(loggedIn: true)` → 取 Uuid 列表 |
| `TalentTradeMod.Settings` | 插件设置（`IClientSettingsPanelProvider` 读写） |
| `Verse.Log.Message/Warning`（传输与状态机） | `hostContext.Log`（§3.8 分级） |
| 自建 `MainThreadQueue` | `IClientMainThreadDispatcher.Enqueue` |

### 3.4 Pawn 序列化与 Def 交换（原样保留）

- `PawnSerializer` / `PawnDeserializer` / `DefManifestHelper` 原样迁入插件，**不改序列化格式与过滤逻辑**。
- 仅调整：命名空间、日志通道（`Log.Error/Warning` → `hostContext.Log`，保留异常对象）、静态 `TalentTradeTransport.Compress/Decompress` 改为实例/静态工具引用。
- 主线程约束不变：序列化/反序列化只在主线程 Tick 或 UI 点击路径执行。
- `ScribeSaver.DebugOutputFor` 与 `ScribeMetaHeaderUtility` 等 RimWorld 原生 API 在 1.6 需实测可用性（老 mod 目标 1.3-1.6）。

UI 渲染遵循 §8.3：Tab/面板缓存列表与翻译，Draw 路径零分配（面板较多，逐个评审）。

### 3.6 保留的游戏级 Harmony 补丁

两个补丁属于 RimWorld 层修复，框架没有等价挂点，插件自带（不触碰框架管线，§3.7 边界内）：

- `GenScene.GoToMainMenu` Prefix → `OnExitSave()`：退出存档立即下架自己挂牌，防幽灵挂牌。
- `PawnTextureAtlas.GC` Prefix → TryGetValue 版清理：修复反序列化/despawn 后 Pawn 哈希变化导致的 KeyNotFoundException。1.6 需实测（原版 GC 实现是否仍存在该问题，若已修可删除）。

**挂载约束（硬性，与扩展禁用机制联动）**：

- `Harmony.PatchAll()` 必须放在插件 **`Activate()`** 内，`Harmony.UnpatchAll(harmonyId)` 必须放在 **`Shutdown()`** 内。
- **禁止**把 PatchAll 放在 `Mod` 构造器、入口类静态构造器或静态初始化器中——程序集被扩展扫描加载时静态初始化会提前触发，**绕过禁用机制**（旧 submod 即此模式，不可照抄）。
- 禁用（`StaticActivationPolicy` 跳过）→ 不执行 `Activate()` → 补丁零挂载；启用 → `Activate()` 挂载；退出/关闭 → `Shutdown()` 卸载（§3.6 配对清理，框架 `Dispose → ShutdownExtensions` 链路已确认存在）。

## 4. 设计哲学合规要点

| 哲学条目 | 约束 |
|----------|------|
| **§1.1 插件平权** | 与 Chat/Trade/红包同级注册；宿主无专用分支 |

| **§6 增量** | 不修改既有接口/签名；Scribe 序列化逻辑原样保留 |

## 5. 实施阶段

每阶段独立可编译、可运行、可验证。

### Phase A：工程骨架与协议
- 新建 `Extensions/LegacyTalentTrade/Contracts` 与 `Client` 两工程（照红包/参考 Chat-Trade 结构）。
- DLL 编号：Contracts = `15-LegacyTalentTradeExtension.dll`，Client = `16-LegacyTalentTradeExtension.Client.dll`（红包已占 13/14）。
- 注册进 `Phinix.sln`；新增中英翻译键文件 `LegacyTalentTradeExtension.xml`。

### Phase B：协议 + 中继迁移
- 迁移 `TalentTradeProtocol`（23 消息 + blob + def）与 `TalentTradeTransport`（新地址/房间，有界队列、日志分级、Shutdown 清理）。
