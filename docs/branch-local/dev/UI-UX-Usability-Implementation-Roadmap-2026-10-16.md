### 已确认的右侧体验

1. 右侧固定本人区：`我的昵称　[渲染后的本人昵称]　[改名]`，通常合为紧凑一行；长名可在一行内截断并提供完整提示，不挤没改名按钮。
2. 本人区在“用户/通知”等sidebar内容之上，切sidebar不消失，也不随成员列表滚动。
3. 点“改名”打开独立小编辑窗口：原文输入、实时渲染预览、保存、取消。点击外部或失焦不保存，不把同一个文本框在标签渲染/原文之间切换。
4. 首批保留已有手写标签，不自动去格式。逐字调色编辑器仍只做[远期评估](../audits/UI-UX-Usability-2026-10-16/Phinix-Rework-Name-Color-Long-Term-Assessment-2026-10-16.md)，当前不出现不可用的未来按钮占空间。
5. 右侧成员区去掉重复“用户”大标题和常驻“选择成员以查看操作”说明，压缩卡片留白；搜索、在线人数、屏蔽折叠和选中成员动作保持可发现。
6. 不缩小字体/命中区凑密度，不扩大侧栏挤压聊天主体。窄窗沿用抽屉；无sidebar时仍能从Host设置菜单直接改名。

## 2. 首个实现切片：右侧与快捷改名

### UX2-01 — Host固定本人区及昵称编辑窗口

状态：源码、双版构建、白盒完成，本地候选就绪；游戏交互待测。UX2-00基线已核对。

**改动归属**

- Host的ServerTab壳负责个人身份展示及通用sidebar几何；Host本就拥有用户/设置服务，不引用Chat业务类型来取得本人信息。
- 名称编辑owner负责本地draft、校验、保存、发送结果和观察到的在线名字。使用普通公共presentation session、动作与Host现有窗口桥，不新建私有renderer/确认系统。
- 本人区从共享sidebar内容矩形中预留测量后的高度，再将剩余区域交给当前provider。不能由Chat画本人区，或让通知页复制同一份本人控件。
- 无sidebar、Chat停用、provider失败或抽屉未打开时，“设置→修改名字”仍可到达同一编辑器。抽屉内显示本人区时，后面的聊天内容继续不接收穿透点击。

**本次名称状态约束**

- 在线展示目录中观察到的本人昵称；离线可显示已保存昵称并标明离线。目录暂未有本人时不把空值覆盖保存配置。
- 编辑窗口独立draft，打开/输入/取消不修改settings或在线目录。保存是唯一提交动作，同一窗口保存一次不因WriteSettings、PreClose或旧入口回调重复发送。
- 首先区分“本地保存成功”和“在线更新提交”。如果发送失败/未登录，应说明已保存供下次登录使用或尚未提交，不假装已在线生效。
- 现有UpdateSelf没有请求关联token的名称成功回执。只在目录真正变化后显示“当前在线名字已更新”，不能声称收到“本次改名的关联成功确认”；等待未变化、重新同步和失败结果分开。
- 不后台反复重发、不增加协议、不修改UUID/认证标识。现有连接页与全量设置入口重用编辑owner或严格遵守原保存语义；任何入口都不能绕过新editor的取消约定而串改draft。
- 原始富文本字符串原样进入手动编辑；预览单独显示。关窗/取消保留原名；非法输入原地提示。重连、登录或外部名称变化时，不能静默覆盖正在输入的draft，保存前重新核对当前状态。
- 显示本人名字不依赖未来调色功能，也不要求打开Chat名字格式开关。预览/展示如何尊重既有格式设置应明确记录，且不暗改用户设置。

**预计涉及**：ServerTab.cs、Client.cs/SettingsWindow入口、Host用户/设置adapter或内部owner、新的普通编辑窗口/投影、语言资源。公开能力只有在现有合同不能表达时再最小扩展。

**通过条件**：宽窗“改名→输入→保存”约2+f点击；菜单入口约3+f。取消、失焦、IME选词回车均不意外保存；富文本原文无损；两个入口打开同一owner且不重复提交；无Chat/无sidebar仍可改名；在线/离线/目录未准备好/发送异常状态准确。

### UX2-02 — Chat成员区紧凑投影

状态：与UX2-01同批完成源码、双版构建和白盒；游戏密度/命中/通知切换待测。

**目标投影**

| 区域 | 普通状态 | 选中成员/异常状态 |
|---|---|---|
| Host本人区 | 紧凑昵称和改名 | 状态不属于其他成员，不被选中项替换 |
| sidebar导航 | 用户/通知，沿用Host导航 | 同上 |
| Chat工具区 | 搜索、在线数、紧凑“已屏蔽”展开/收起 | 仍保留搜索；状态只占必要行数 |
| 所选成员动作 | 未选择时不占一整张说明卡 | 显示短姓名上下文及屏蔽/交易/贡献动作；长内容有完整提示 |
| 成员列表 | 占剩余空间，紧凑行，正常可滚动 | 过滤或动态状态变化仍保持准确选择；不按行号串用户 |

**实现约束**

- 首先使用已有WithPlainLayout、WithInlineToolbar、WithCompactRows、WithActionMenus及fixed header；删除重复page标题、长常驻summary和无意义卡片间距。
- 当前collapse-blocked属于typed action point。移动到工具区只改投影位置，不复制业务回调、不丢失动作归属，也不把成员context与本人改名context混用。
- 搜索有明确“搜索成员”提示，不保留同内容的重复大标签/说明。在线数压为状态短文，不作为单独信息卡。
- 第三方贡献动作仍全部可到达；空间不足使用公共更多菜单，不能硬截断或只展示内置动作。
- 所选成员姓名、禁用原因、离线/失败提示必须可见或可查看。紧凑不意味着删掉业务原因；错误允许占额外必要空间。
- 优先复用已有公共布局，不修改全局padding让其他插件一起被动变小；若确有通用测量缺口，独立记录并对所有消费者开放。

**预计涉及**：ChatSidebarProvider.cs及语言资源；Host公共renderer仅在已有布局确认不足时涉及。通知sidebar不做业务重写，但验证新共享顶部与其状态/滚动不冲突。

**通过条件**：相同主窗尺寸、字体、语言、主题、数据及正常未选中状态下，新增本人区后的成员列表可见高度不少于原基线；无重复用户标题/常驻选择提示卡；搜索/屏蔽/交易/第三方动作完整；长名不遮按钮，状态不串人；正常控件保持现有32逻辑像素基准命中高度，缩放不靠缩字过关。

## 4. 公共能力和业务边界

### 4.1 复用能力

已有公共text field、validation、selection、readOnly、list row WithControls/WithImage/CompactRows、Plain/InlineToolbar/ActionMenus、分栏/固定区及图像借用等优先使用。新本人区用Host通用壳和同一控件/呈现体系；新名字编辑不向插件开放原始用户管理对象。

真正需要新能力时逐项说明：为什么现有能力不足、谁拥有事实、公开/内部API形状、当前消费者、异常/释放/缓存、两版合同影响。当前已知待设计接缝包括可选库存图像元数据、通用首次设置承载、按需的通用导航/设置分组；不预先建一个包办业务的“UX框架”。

本人区是Host自身通用用户服务，不是让Host引用Chat的特例；成员列表、屏蔽和物品交易入口继续归Chat/Trade。第三方sidebar也应获得同一剩余区域计算与生命周期待遇。

### 4.2 保持的不变量

- 业务callback完成、发送提交、目录观察、真实业务成功和物品到账分别显示；UI不生成权威。
- 未知结果不自动重发、退款或返还，确认/重置/取消不改协议；R44跨存档托管不混入本次。
- 物品codec单位与完整状态不因图标/分组/行内数量改变，物化与交付仍在插件游戏adapter。
- 包预检、所有权、依赖、摘要、运行时profile、重启生效保留；首次推荐不绕过普通商店保护。
- 主题仍只有原服务，名字富文本是个人显示名，不加入全局主题profile。
- API3、CLR绑定、反射消费与两版制品按实际改动验证；不更新vendored protobuf pins/source，不擅自切正式插件Host pin。

## 5. 游戏与普通玩家验收

### 首批必须记录的场景

| 场景 | 验收要点 |
|---|---|
| 用户/通知切换、任意主Tab | 本人区固定、内容对应正确、通知功能不变、本人不被选中成员替代 |
| 未选/选中/搜索/屏蔽成员 | 正常无巨大提示卡；所选上下文清楚；过滤失效不作用到另一个人；贡献动作可达 |
| 长富文本名字、长中英文、无格式名字 | 固定本人行不无限长高；改名按钮可点；提示可查看全名；输入原文/预览分开 |
| 编辑取消/失焦/IME/Enter | draft不落库，取消无网络更新，选词不提交；保存不会被背景输入pending吞掉或重复发送 |
| 离线/登录中/目录暂缺/断线重连 | 显示已保存与在线观察的名字差异；不伪成功/自动重发，不覆盖正在编辑draft |
| 无Chat、无sidebar、provider失败 | 设置快捷入口仍有效；Host不依赖Chat合同，菜单/窗口及时释放 |
| 窄窗抽屉与极低高度 | 本人区与nav占用经过测量；不挤成负高度、遮动作或输入穿透；错误有明确可达路径 |

两版测试各自记录游戏/引用/候选指纹。布局至少覆盖可用主窗640×480～1280×800、中英文、1×/1.5×/2×缩放；屏幕分辨率与逻辑可用窗口分开记账，不把截图像素当逻辑控件尺寸。

密度指标：相同条件正常未选中成员状态下，记录本人区高度、导航高度、成员工具区高度、列表可用高度、实际完整可见行数。验收以可见列表空间不减为目标；特殊错误/长动作必须展示时单列，不用隐藏错误达标，不承诺某个未经测量的百分比。

普通玩家至少完成“改自己的名字”“取消改名”“找另一位成员并交易/屏蔽”“切换看通知”四个任务，记录求助/误入/回填/保存误解。后续各批再按总体方案的库存、商店、主题、首次引导和红包任务验收。
