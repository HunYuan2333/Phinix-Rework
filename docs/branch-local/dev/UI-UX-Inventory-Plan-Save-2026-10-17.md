# 每日计划保存校验与错误定位（2026-10-17）

## 反馈与证据边界

用户主 Mod 与红包 0.0.4 均已更新，沿用旧存档；截图显示余额 6334、每日 20、Tick 50，却返回英文余额错误。

已确认 `SetDailySchedule` 将记录不存在、codec 未注册、数量不合法和 codec 栈上限读取失败合并为同一个错误，甚至覆盖读取异常原因。截图中输入范围合法，但没有取得用户实际失败的库存 payload/运行日志，尚不能确定是哪一条件触发；不得将本轮诊断修正当作该存档已修复。之前仅测 UI 参数到 fake business port，未覆盖真实服务拒绝分支，这是验证缺口。

核对历史主仓库 b335426 和当前独立红包源码：codec ID 均为 `legacy-redpacket.template`，版本均为 1，payload 数据字段结构一致。旧存档本身不是要求清空或迁移的依据。只读检查了本机最近三个存档的库存字段，它们均无记录，不是截图样本；没有修改用户存档、日志或安装配置。

## 变更

- Inventory 模块内部增加共享 `CanSetDailySchedule`，编辑窗与保存入口使用同一校验；保持主线程/存档归属/恢复检查、原 journal append 后 publish 顺序。
- 数量、时间、记录缺失、插件未就绪、版本不匹配、payload/栈上限读取失败、写盘失败分别提供中英文原因。新增 codec 版本校验，拒绝将不兼容记录交给错误版本。
- 编辑窗预先显示拒绝原因并禁用保存；失败保留草稿，恢复来源插件后重新校验；警告使用公共主题 Warning。无新 Host 专用 API、renderer 或动作系统。
- 没有改库存字节、codec ID、协议、存档格式、每日执行规则、物品数量和来源插件更新策略。没有通过跳过 codec 校验强行创建不可执行计划。
