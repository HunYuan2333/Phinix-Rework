# 库存反馈修正：红包图标配套与独立每日计划管理

日期：2026-10-17。承接 UX2-06 用户实机截图反馈：原版物品显示问号；顶部来源/每日提取卡占用过大；缺少已有计划的集中入口。

## 图标问题的范围

用户已确认本次只更新主 Mod，没有更新配套红包插件。库存图标的可信 Def 标识由物品所属 codec 提供；旧红包插件不会填新增 `InventoryItemPresentation.IconDefName`，Host 因而显示问号。是否原版物品不能替代这条数据链。

本轮不按显示名反查 Def、不在 Host 解码红包 payload，也不修改旧存档里的物品标签来拼图标。配套红包 0.0.4 的 `RedPacketInventoryCodec.PresentItem` 已包含 Def 标识，与新 Host 一起复测；没有生成另一份相同版本不同字节的插件包。真正缺 Def、codec 未提供 metadata 或不可识别内容继续使用占位，仍不能宣称所有问号都能消失。

配套更新必须符合当前安装来源和版本规则。商店代码会阻止开发包直接覆盖正式来源或降级；本地候选不等于正式商店更新。本轮不绕过安装记录、不触碰玩家安装数据、不发布插件。若当前使用正式来源插件，应走同来源正式更新；提供的开发候选用于对应的隔离测试组合。

## 新路径

- 库存顶部：搜索/翻页＋**每日计划（数量）**，存档提示与组数缩为轻量摘要，不再插入选中物品的大卡片。
- 点击库存物品名称区：直接打开该记录的独立计划编辑窗口。常见初始高度为 360，数量和时间两项；来源 ID 等信息默认收起，需要时点“来源详情”。
- 顶部“每日计划”：集中列出当前存档已有计划，每行显示物品、每日件数、既有执行 Tick；当前有未完成任务时显示本次剩余量；每行有编辑和移除。
- 计划列表每页 10 条，保持原每贡献 32 动作限额；翻页有页数，跳转到新页开头。保存后回到包含该记录的计划页，显示保存结果。
- 移除使用现有公共 Danger 动作与确认；不影响已经提取的物品。关窗/返回不保存尚未提交的编辑，库存行内提取草稿不受影响。
- 原库存行内提取、分页、搜索和 IME 修复继续保留；不会因打开计划窗口而改变提取数量或自动发起提取。

时间暂时保留既有 `DayTick`（0～59999）语义。调度器以游戏 Tick 日周期运行，不能未经核对就把它包装成本地地图钟表时间；本轮只改入口与排版，不改变调度或补发规则。

## 实现与保护

新增 `InventoryPlansWindow` 只是 Inventory 的原生窗口/页面投影：通过已有 `IClientGameWindowService` 开窗、同一公共 renderer 画内容、同一 Inventory 动作点与 context 收集动作，使用同一主题和确认。没有插件私有绘制、Host 插件白名单、第二主题或动作系统。

- 主库存 `InventoryTab` 移除顶部 selected 区；主窗口可关闭/切页，计划窗口仍由同一模块和服务所有。卸载/关闭模块会释放计划窗口和 session；更换 Game 会在保存前关闭旧窗口。
- 列表/编辑共用该窗口的一份 session，每次投影转移新动作集；旧动作受库存版本、Game、语言、扩展点版本、窗口关闭和草稿脏状态限制。批量状态即使不改变账本版本，也会使旧保存/移除动作失效并刷新只读状态。
- 库存核对、未决交付、故障或批量提取期间，计划修改只读；详情和返回仍可用。调用原 `SetDailySchedule` / `RemoveDailySchedule`，保存日志、余额与实际调度权威不变。
- 原生文本事件先完整读取再应用，连续数量和时间提交不因首条 dirty 丢失后续字符；Enter 不自动保存，关窗不触发业务。
- 元数据按数据版本/语言/可用性变动失效，只对当前页/编辑项懒取；输入数量不重复解码整个库存。图像包装与窗口缓存配对释放。
