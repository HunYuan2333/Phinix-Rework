# P3 加速版开发与自动化收口

本轮按用户“先把P3结束”收口，不启动P4，也不把延期容量/全平台工程重新变成P3前置。状态为：**P3加速范围的实现与自动化退出门槛已满足，双方候选已冻结；真实RimWorld与生产迁移验收仍待人工。** 不能解读为完整P3所有扩展目标或P6已经通过。

## 本轮变更

关联SV-32/33/35/36/38、TQ-30/31、PF-07、FR-09/12。此前完整P3实现清单见2026-10-23记录；此次关闭确认的恢复调度缺陷并补候选联合证据。

- P3 Trade插件新增私有 `TradeRecoveryPump`，只借用现有API3任务服务并拥有每个模块任务scope/250ms计时器。后台仅提交任务，库存、保存、账本和回执处理仍在游戏主线程。
- `TradeIntentSettlementCoordinator` / `TradeDeliveryRecovery` 不再用void dispatcher及易卡住的queued标记。QueueFull保留原页和continuation；后续空位继续，不丢页、不自动重启整批。通知合并，单flow最多一个任务、一个续页；每页8条的原业务规则保持。
- Dispose先停止pump/取消排队，再解绑借用事件。模块失效不再重试；回调失败记录一次、不自动重跑该失败页；后续显式恢复通知仍可发起核对。初始化早期要求任务服务，缺失时失败清理。
- 不改变交付权限：只恢复原库存幂等计划，Unknown不退款、不盲重造Thing；未绑定/不同save-journal保持核对；direct不生成保存到账ACK。
- 新增实际DLL恢复回归与独立进程现代回执Harness；没有改UI布局、服务端产品协议、共享层/gitlink、数据库schema或依赖包。跨仓库仅Server文档同步，UI工作区仅优先级记录更新；没有合并分支。
