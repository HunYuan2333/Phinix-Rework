## 玩家路径

主窗口已打开为基准，未展开的同类组需要先展开；搜索仍直接显示匹配记录。

| 任务 | 原路径 | 当前路径 | 保留与结果 |
|---|---|---|---|
| 单条默认提取 1 单位 | 库存→选物→打开提取编辑器→提取 | 库存→物品行“提取” | 明确一次提取动作，不新增自动执行 |
| 提取指定数量 | 库存→选物→打开编辑器→填数量→提取 | 库存→行内填数量→提取 | 数量不会自动夹到余额；错误就地显示并禁用提取 |
| 连续提取不同记录 | 每条重新选择、打开编辑器 | 直接修改各行数量并提取 | 每条记录独立草稿，搜索和当前页保持；其他行草稿保留 |
| 查找大量库存 | 搜索/展开后滚动 | 搜索＋固定翻页工具，每页最多 20 个显示行 | 搜索变化/主动翻页返回新结果页开头；普通结果刷新保留滚动值 |
| 来源/每日计划 | 选物→计划编辑器 | 点击物品行文字区→详情与计划 | 每日计划仍为次级入口，保存/移除规则不变 |
| 按同类组批量提取 | 选择组→数量/全部→确认 | 保留原路径 | 仍以独立记录逐批交付，确认没有取消 |

不计文本输入字符，默认提取从 4 次点击减至 2 次（含进入库存）；指定数量从 5 次点击减至 3 次。已经进入库存后，每条默认数量只需 1 次提取点击；改数量另加 1 次输入框聚焦及实际字符输入。组展开、搜索聚焦、翻页按实际数据另计，不假定所有记录都在首屏。

## 数量、结果与重试

- 普通单位显示“提取数量”；整份 codec 显示“提取份数（每份 N 件）”。调用主体时仍传 codec 单位，余额/成功件数按已有可信 ItemsPerUnit 展示，不能拆开一份 opaque 物品。
- 0、负数、溢出及超余额均显示错误并禁用提取；可提取余额为 0 有独立原因，不显示不可能的“1～0”范围。余额被占用或减少时保留原草稿，要求玩家纠正，不自动改为较小数量。
- 成功后行内显示结果及新余额，配合主题的成功标签；失败显示原地原因与停止标签。上方保留最近一次结果，因此记录耗尽/移除后仍能看到本次反馈。
- `TryExtractForPresentation` 是现有提取循环的内部输出口，额外返回已完成持久化确认的单位数。每个堆仍走原有准备、日志、投放、核对、提交链，不从余额差猜交付数量。公开 `TryExtract` 的 bool、部分成功原因格式和调用契约保留。
- 已确认部分交付后，数量框只保留原请求减去已确认完成的部分；失败不自动重试。下一次明确提取只请求剩余数量。
- 若有交付结果未知，继续进入原有全页核对状态；即使完成核对，原行仍要求玩家检查到账数量并修改数量后才能继续，不自动重放可能已交付的部分。
- 同一 EntryId 的提取单位变化时重置为待核对数量并禁用提取，重新填写后才继续。库存记录消失时清掉对应草稿，新 Game 清除全部行草稿；同 Game 关闭重开、翻页、名称搜索、普通余额刷新均保留其他有效草稿。
- 行内输入与上一批输入法修复一致，先读完整批输入，再修改 owner。关闭窗口前的已排队数量也会保存；旧页面动作、已过期上下文与未消费文本仍不能执行旧参数。

## 公共布局与边界

沿用 Host 公共 `ClientPresentationRow.WithControls`、整数 field、动作、图标、徽标、主题角色和确认能力，没有插件私有 Draw 或新增 renderer。

每页最多 20 个显示行（含组标题），为 owner 每贡献最多 32 个动作留出翻页/计划/批量操作空间，不提高 Host 全局资源限额。搜索、状态和次级编辑区使用现有 fixed header，小窗口允许该区独立滚动；库存列表使用公共紧凑行。

普通库存列表不使用会触发自动归位的 SelectedId；当前详情对象通过“当前查看”徽标标识，避免一次提取改变选择而把列表滚回顶部。Host 现有 `ScrollToRow` 额外支持普通列表身份，方法签名不变、feed 的定位/高亮行为保持；用于明确翻页或更改搜索时回到结果开头。普通刷新保留数值滚动位置，内容耗尽或高度变化时仍可能夹到合法范围，不承诺屏幕像素完全不动。

未变更业务协议、保存 schema、物品权威、确认规则或来源校验。单笔提取仍同步按堆执行，超大数量的性能优化不在本切片；批量操作继续使用既有逐帧队列。异步到账/结果未知不能被 UI 的回调完成替代。
