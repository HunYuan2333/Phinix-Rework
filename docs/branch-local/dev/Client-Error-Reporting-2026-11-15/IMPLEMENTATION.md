# 统一错误窗口：E0 / E1 实施记录

日期：2026-11-15。分支：`codex/client-error-reporting`。

> 本文保留 E0/E1 历史记录。后续 E2 的变化和最新验证见 [E2 实施记录](E2-IMPLEMENTATION.md)与 `verification-e2.json`；原 `verification.json` 不作为当前源码的验证指纹。

## 本轮合同

- 新增中立 `IClientErrorService` / `IClientErrorReporter`，位于现有客户端 SDK 合同程序集，不引用 Verse/Unity 类型。插件在 Activate 时通过真实 module 绑定，在任意线程上报；停止后绑定失效。身份和版本由 Host 绑定，不要求插件拼接日志前缀。
- Reporter 接受原始 Exception、稳定 code/operation、是否提醒；返回错误编号，不重试、不重抛、不授予成功/取消/退款含义。正常拒绝仍使用原 Result。
- 本切片不需要新增 Common 接口：客户端合同通过已有 ExtensionHostContext 服务表注入，模块启停通过已有 observer 槽。E2 若共享 loader/registry 需要挂点，优先使用已有 HostLogEntry.Exception / StructuredLog，再决定最小共享扩展和精确 pin；没有直接修改 submodule 或 vendor。
- 不更改既有 TaskSnapshot、Result、IExtensionLogger 的二进制签名。新增 SDK 类型是增量能力，未来插件用 TryGetService 检测；尚未发布新的包版本或兼容范围。

## 实际接入与处置

| 入口 | 记录/提示 | 传播与副作用 |
|---|---|---|
| 生产 dispatcher 的 callback catch | 保存原异常、插件身份、任务上下文；Failed；请求窗口 | 仍隔离，后续任务继续；无故障服务时完整异常文本回退，不再只记类型 |
| 原有 Root.Update postfix 中的 Client.Update | 立即记录，下一次主线程通知处理窗口 | 原 catch 中 bare throw，保留同一异常；不另打一次重复堆栈 |
| Host InitializeExtensions 最外层 catch | 清理前记录主故障，清理失败独立记录 | 保持原先的失败清理与不再抛出策略；清理不能遮住主故障 |
| 第三方/内置模块主动 Reporter.Report | 相同存储/额度/通知路径 | 不改变调用者决定的异常传播或业务结果 |
| 窗口打开/绘制、复制失败 | 次级故障可查，notify=false | 不递归弹窗；复制失败可重试；原报告保持可复制 |

原评估不可覆盖更新。`migration-ledger.tsv` 使用基线行号与 SHA-256 标识原位置，并提示源码是否变化；它不是当前行号索引，也不是所有捕获点已经迁移。`inventory-client-error-migration.py` 可重新生成登记。当前登记了 2,343 个基线位置，其中 dispatcher 与初始化最外层共两个捕获点完成迁移，其余待逐项审阅。本轮新增 RootPatch/窗口/控制器和初始化清理的次级捕获点以本表登记，不伪装成原评估中已有的位置。

## 资源、生命周期与隐私

- 近期记录上限 64 个故障组，每组异常正文上限 65,536 字符（外加明确截断标记及有界元数据），异常树最多 64 节点、16 层。消息超过 8,192 字符整体省略并标注，避免截断后绕过脱敏。淘汰、日志出口失败和递归抑制有可复制计数。
- 同一 Exception 实例跨边界复用编号；不同异常按 owner/code/稳定 operation/异常类型与调用帧分组，保留第一份完整样本和累计次数、首次/末次时间。任务 ID 放在首样本上下文，不参与分组，避免每帧新任务制造弹窗风暴。详细调用点相同但 message 不同的错误会归组；不是逐次完整历史档案。
- 所有诊断字符串在上报时冻结；用弱引用身份表去重，不保存 Exception.Data、Game、Thing、业务回调或原 Exception 强引用。框架只在模块活跃时保留 module 身份，停止时撤销绑定。
- 栈通过标准 StackTrace 采集，而不是调用第三方 ToString。保留方法调用帧，初版不导出源码路径/行号；没有抛出过的异常明确标注没有捕获栈。原样 rethrow 给游戏的异常本身未改写。
- 消息过滤已知凭据字段、Bearer、URL、常见绝对本机路径；不主动采集 payload、SQL 参数、聊天、存档和配置。这是有测试覆盖的保守过滤，不是任意第三方自由文本的机密识别器；插件不得将敏感业务数据放进 code/operation/message，后续认证路径接入需专门审阅。
- 日志写入在保存之后、锁外执行；异常属性也在锁外读取。坏 logger 只增加失败计数，不覆盖原故障。每组首次记录进入原 Host 日志桥，重复计数可在窗口重新复制；无新磁盘或数据库存储。

## 窗口行为

- 使用 Host 原生窗口与控件，不依赖 Store、可选插件或 presentation renderer 正常工作。中英文，“复制错误详情”和“关闭”，多条记录可切换，复制反馈留在窗口中。
- 从现有 Host Update 先处理有界通知状态，再执行声音/业务队列，不向业务队列再提交弹窗任务。启动长事件未完成时暂存，主线程/窗口栈就绪后打开。
- 只有一个窗口；同组关闭后不重复弹出，新故障可再次提醒。新故障不悄悄替换玩家当前选择的报告。
- 小窗口中的说明和摘要可滚动，复制/关闭按钮固定在可见区域；复制读取保存的字符串，不读取被屏幕裁剪的文字。
- Host Mod 设置提供最近错误入口；主题未安装时仍有原生入口。关闭窗口不清空报告、不重试或取消业务。

## 本轮验证

验证结果见 `verification.json`；测试工具与构建日志在其中指向的隔离输出目录。

定向测试编译生产 ErrorService、通知控制器、dispatcher、公开错误/任务合同、RootPatch 及错误窗口；外围游戏/Harmony/接口使用最小替身。因此能验证控制流与无图形状态下的窗口行为，不能当作真实游戏绘制验收。

- net10.0 与 net472/Mono 各 48 项检查通过，包括异常树、原始帧、同对象去重、并发计数、复制、绘制失败和具名身份/停止约束。
- 已有 ResourceRecoveryRuntimeTests 使用生产 dispatcher 和真实 net10 SDK 程序集运行，6 项队列/取消回归通过。
- 最新源码的 1.6 Host/内置插件隔离构建通过；1.7 rev1248 引用下的 28 项目图重建通过（有构建环境和既有依赖警告，零错误）。

联合构建使用真实游戏引用编译 Host、五个内置插件和维护中的两个独立业务插件。额外 Example 插件仍引用当前 Host 中不存在的 relay 类型，单独登记为既有不兼容，未借此修改其业务或宿主接口。
