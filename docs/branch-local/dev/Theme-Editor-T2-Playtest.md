# T2 主题编辑器游戏验收

先退出游戏，整包同步 Output/phinix-rework 到 Mods/phinix-rework，再重启。本批主题操作仍热更新；红包/人才贸易沿用已有 1.1.1 单包。无需重新安装插件或修改存档。

整包包含 Themes/default.xml、新的语言资源与同批 SDK/内置插件程序集；不要只替换 PhinixClient.dll。沿用之前的测试 01–05，新增的 06-inheritance-v3.xml 可放入同一个用户主题目录后刷新，用于检查文件中的继承指令与参数。

## 分组与说明

打开主题窗口，右侧应按 Host、聊天、交易、库存和商店分组；名称与用途支持中文/英文，key 留在提示中。配色项搜索独立于左侧主题搜索，可以按名称、模块、类别或 key 搜索。

检查窄窗口：底部操作变为两行，编辑区可纵向滚动，输入、清除、继承和应用均可达。

## 两种重置语义

使用测试 02（聊天独立覆盖）：

1. 选择聊天正文，来源应是“当前主题文件”，粉色。
2. 改成蓝色，来源变“用户覆盖”；没有点击应用之前，实际聊天仍为原已应用颜色。
3. 点击“清除用户覆盖”：预览恢复文件中的粉色。
4. 点击“恢复继承”：预览变为 ui.text.primary 的黄色，来源显示继承路径。
5. 应用后已有聊天正文热更新；重启后继承意图仍保留。
6. 再点“清除用户覆盖”，文件粉色应恢复。

没有回退角色的颜色与参数，第二个按钮为“使用注册默认值”；同样跳过当前/default 文件值，使用该项注册默认值。底部“清除本主题覆盖”只清除当前主题的颜色、参数、继承指令，其他主题的已保存覆盖不受影响。

## 参数与边界

搜索“用户名颜色饱和度”或 chat.nameColor.saturation，输入 0.2 并应用，普通他人昵称应变淡；亮度设为 0.5 应变暗。自定义富文本昵称和自己的昵称仍按其原样式显示。

输入 -1、2、NaN 或仅输入小数点：应用/导出应不可用，实际样式不变。切换到另一个配色项再回来，未完成输入仍在；清除该项或清除本主题覆盖可恢复。有效参数按主题保存，重启后保留。

## 草稿与刷新

- 编辑主题 A，切到 B，再回到 A：草稿、当前选项、输入和编辑滚动仍保留。
- 只选择颜色、不输入内容：来源不能自动变成“用户覆盖”，导出不应凭空增加该项。
- 点击刷新或切语言：列表更新，草稿保留；未编辑的继承值应重新显示当前预览值。
- 取消/关闭：丢弃未应用草稿；此前已经点击应用的值继续保存。
- 若自然出现注册项消失或主题文件被删除，保留草稿并阻止对缺失主题应用；不要为此刻意制造插件故障。

## 导出与兼容输入

导出到一个新文件，再导入：颜色、参数和继承效果一致。包含 inherit 指令的文件为主题 v3；普通显式覆盖仍导出 v2。测试 01–05 的 v1/v2 文件继续可读，未知插件键继续保留且计入未使用项。

导出成功后应显示完整绝对路径，并尝试打开所在文件夹。可以复制导出路径或再次打开目录；路径较长时悬停提示可读完整内容。系统调用仅保证尽力启动，文件管理器未弹出时仍可复制路径找文件。检查含中文和空格的目录即可，三端行为尚未实机验收。导入仍用现有路径输入，不引入原生文件选择器。

本批设置写为 ThemeSettings v2，读取旧 v1；替换前的文档保存在同路径 .previous。不要把新的 v3 文件交给尚未支持它的旧客户端解析；旧解析器应该拒绝，而不是猜测指令。本项目的 1.9 支持限于维护插件内部 adapter，不承诺旧客户端读取新主题格式。

本批仅编译通过；尚未运行自动化测试或本清单的游戏验收。
