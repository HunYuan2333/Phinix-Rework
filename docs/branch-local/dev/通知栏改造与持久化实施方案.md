# 通知栏改造与持久化实施方案

> 2026-06-21，基于《设计哲学.md》《聊天增强功能实施方案.md》与代码库实测编写。
>
> **本文档是方案文档，不是已实施记录。** 所有"现状"行号均为代码库实测（截至 2026-06-21），"目标"为待实施设计。
>
> **决策记录**：通知从临时横幅升级为**持久化 + 侧栏列表 + 即时横幅**三层架构。服务端持久化通知并按时间戳在客户端连入时自动分发；客户端侧栏新增通知 Tab，横幅保留为即时提醒。
>
> **与《聊天增强功能实施方案.md》的关系**：该文档 §0 将 notice 持久化列为 P2 并推迟。本文档是 P2 的具体落地方案，同时修正 P1 已实施的横幅模式的两个缺陷（切服务器残留、无历史回看）。

## 0. TL;DR

| 改动 | 可行性 | host 改动 | 插件改动 | Proto 改动 | 风险 |
|------|--------|-----------|----------|------------|------|
| **服务端通知持久化** | 🟢 高 | 零 | Chat 扩展新增 `AddNotice` / `noticeHistory` / 独立 `.bin` | 零（复用既有 payload） | 低 |
| **连入按时间戳自动分发** | 🟢 高 | 零 | Chat 扩展在 `HistoryRequestType` 命令处理中追加 notice 分发 | 零 | 低 |
| **侧栏多 Provider Tab 切换** | 🟢 中 | `ServerTab.cs` 增量改动 | 零 | 零 | 中（host UI 容器改动，需过 §7 check-list） |
| **NoticeSidebarProvider 通知列表面板** | 🟢 高 | 零 | Chat 扩展新增 `IServerSidebarProvider` 实现 | 零 | 低 |
| **横幅切服务器清空** | 🟢 高 | 零 | Chat 扩展订阅 disconnect 事件 | 零 | 低 |
| **Legacy 模式功能禁用提示** | 🟢 高 | 零 | Chat 扩展在 `CompatibilityModeChanged` 时提示 | 零 | 低 |

**推荐实施顺序**：横幅清空（最小）→ 服务端持久化 → 连入分发 → 侧栏 Tab 容器 → 通知面板 → Legacy 提示。

## 1. 背景与目标

### 1.1 触发需求

当前通知（notice）系统存在三个问题：

1. **切服务器公告残留**：`NoticeBannerProvider`（`Extensions/Chat/Client/NoticeBannerProvider.cs:11`）的 `activeNotices` 列表永不清空，不订阅 disconnect 事件。用户切换服务器后，旧服务器的公告靠 10 秒超时自然消失，在新服务器连接后的超时窗口内仍显示旧公告。
2. **通知不持久化**：`NoticeConsoleCommand.Execute`（`Extensions/Chat/Server/NoticeConsoleCommand.cs:55`）调 `chatApi.BuildNotice()` 创建 payload 后直接广播，**不存入任何历史**。客户端连接晚于广播则永远看不到该通知。《聊天增强功能实施方案.md》§1.2 将此列为 P2 并推迟。
3. **横幅无历史回看**：`NoticeBannerProvider` 是纯瞬时 UI（`ActiveNotice` 内只有 `Text`/`DurationSeconds`/`StartTime`），超时即消失，无已读标记、无历史列表。用户关闭横幅后无法回看。

### 1.2 目标

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| **P0** | 切服务器时横幅立即清空 | 断开连接 → 横幅消失；新服务器连入 → 仅显示新服务器的通知 |
| **P0** | 服务端持久化通知 | `notice` 命令 → 通知存入 `notice-history.bin` → 服务端重启后仍在 |
| **P0** | 连入按时间戳自动分发 | 客户端连入 → 收到保留窗口内（默认 24h）的所有未过期通知 |
| **P0** | 侧栏通知 Tab | 侧栏顶部出现 `[用户|通知]` Tab 切换，通知 Tab 显示完整通知列表 |
| **P1** | 通知列表交互 | 未读条目左侧金色竖条高亮、点击标记已读、相对时间戳、"全部已读"按钮 |
| **P1** | Legacy 模式提示 | 连入 Legacy 服务器 → 系统消息提示"通知、@提及、回复等功能不可用" |

### 1.3 非目标

- **不重构现有聊天消息管线** —— `ChatMessageHandler` / `PhinixFrameworkChatService` 既有路径行为不变
- **不引入新序列化框架** —— 仍用 protobuf + DataContractJsonSerializer
- **不做通知的富媒体**（图片、链接预览）—— MVP 只支持富文本
- **不做通知的定向推送**（给特定用户/用户组）—— MVP 只做全服广播
- **不做通知的客户端跨服务器持久化** —— 通知列表在 disconnect 时清空，仅服务端持久化
- **不修改 `INoticeBannerProvider` 接口签名** —— 遵循 §6 增量原则，新增 `INoticeListProvider` 而非改老接口

## 3. 设计哲学合规对照

| 条款 | 合规设计 |
|------|----------|
| **§1.1 插件平权** | 通知业务全部在 Chat 扩展。host 的 `ServerTab` 多 sidebar tab 改动是通用 UI 容器改动，不硬编码"通知" |
| **§1.2 host 不依赖插件** | `Client.csproj` 不新增插件引用。`ServerTab` 通过 `IServerSidebarProvider` 接口收集，不引用 `NoticeSidebarProvider` 具体类型 |
| **§1.3 host 只做通用服务** | host 仅提供：(a) `IServerSidebarProvider` 挂载点 (b) `IPersistent` 持久化机制。通知语义（持续时间、未读标记、保留窗口）由 Chat 扩展决定 |
| **§2.1 松耦合** | `NoticeSidebarProvider` 通过 `IServerSidebarProvider` 接入 `ServerTab`，不直接修改 `ServerTab.cs` 业务分支 |
| **§2.3 减少硬编码** | `ServerTab` 侧栏 Tab 由 `SidebarProviders` 列表动态渲染，单个 provider 时不显示 Tab 栏（向后兼容） |
| **§3.5 错误隔离** | 通知解析 try-catch，单个通知损坏不影响其他通知；`AddNotice` 失败不中断广播 |
| **§3.6 资源边界** | `noticeHistory` 容量上限（默认 50）；`NoticeSidebarProvider.notices` 容量上限（默认 100）；disconnect 时清空客户端列表；服务端 `notice-history.bin` 持有 `FileStream` 在 `Save`/`Load` 中 `using` 释放 |
| **§3.7 不绕过管线** | 通知广播仍通过 `IFrameworkServerBroadcaster.Broadcast`（内部走 `pipelineRunner.DispatchOutbound`），不直接 `netServer.Send`；连入分发复用 `HistoryRequestType` 命令响应路径 |
| **§3.8 日志与可观测性** | `AddNotice` / `Save` / `Load` / 分发失败均通过 `RaiseLogEntry` / `hostContext.Log` 上报；异常日志附带完整 `Exception` |
| **§5.3 版本化与 API 兼容** | proto 追加 `BuiltInChatHistoryStore.notices` 字段 2（不修改字段 1）；`FrameworkChatProtocol.NoticeType` 常量已存在，本次启用；`INoticeBannerProvider` 接口不改，新增 `Clear()` 为接口默认方法或 concrete 方法 |
| **§6 增量更新** | `INoticeBannerProvider` 不删；`ServerTab` 改动是增量（多 provider 时新增 Tab 渲染分支，单 provider 时走老路径）；`NoticeConsoleCommand` 改 `BuildNotice` → `AddNotice` 是内部改动，命令签名不变 |
| **§8.3 UI 性能** | `NoticeSidebarProvider` 用脏标记跳过无变更时的重计算；通知列表用 `VerticalScrollContainer` 复用现有滚动机制；相对时间字符串缓存，不每帧 `DateTime.Now` |

## 4. 服务端改动

### 4.1 Proto（零改动）

**无需修改 proto**。`BuiltInChatMessagePayload` 已有 `is_notice`（字段 8）和 `notice_duration_seconds`（字段 9）。`BuiltInChatHistoryStore` 追加字段 2 用于独立存储通知（不影响字段 1 的聊天历史，符合 §5.3）：

```protobuf
message BuiltInChatHistoryStore {
  repeated BuiltInChatMessagePayload chat_messages = 1;
  repeated BuiltInChatMessagePayload notices = 2;   // ← 新增，存储通知历史
}
```

**兼容性**：老服务端解析新 `BuiltInChatHistoryStore` 时忽略字段 2，不崩溃；新服务端解析老文件时字段 2 为空列表，不崩溃。

### 4.3 `PhinixFrameworkChatService` 实现

**新增字段**：

```csharp
private readonly List<global::Phinix.Framework.BuiltInChatMessagePayload> noticeHistory
    = new List<global::Phinix.Framework.BuiltInChatMessagePayload>();
private readonly object noticeHistoryLock = new object();
private readonly int noticeHistoryCapacity;          // 默认 50
private readonly int noticeRetentionWindowHours;     // 默认 24
```

**新增方法**：

```csharp
public global::Phinix.Framework.BuiltInChatMessagePayload AddNotice(string text, int durationSeconds)
{
    var notice = new global::Phinix.Framework.BuiltInChatMessagePayload
    {
        MessageId = Guid.NewGuid().ToString(),
        SenderUuid = FrameworkProtocol.SystemSenderUuid,
        Message = TextHelper.SanitiseRichText(text ?? string.Empty),
        Timestamp = Timestamp.FromDateTime(DateTime.UtcNow),
        IsNotice = true,
        NoticeDurationSeconds = durationSeconds
    };

    lock (noticeHistoryLock)
    {
        noticeHistory.Add(notice.Clone());
        if (noticeHistory.Count > noticeHistoryCapacity)
            noticeHistory.RemoveAt(0);
    }

    RaiseLogEntry(new LogEventArgs($"Notice added: {TextHelper.StripRichText(text)}"));
    return notice;
}

public global::Phinix.Framework.BuiltInChatMessagePayload[] GetNotices()
{
    lock (noticeHistoryLock)
    {
        return noticeHistory.Select(n => n.Clone()).ToArray();
    }
}

public global::Phinix.Framework.BuiltInChatMessagePayload[] GetNoticesSince(DateTime cutoffUtc)
{
    lock (noticeHistoryLock)
    {
        return noticeHistory
            .Where(n => n.Timestamp != null && n.Timestamp.ToDateTime().ToUniversalTime() >= cutoffUtc)
            .Select(n => n.Clone())
            .ToArray();
    }
}
```

**`Save` / `Load` 扩展**（`:158,181`）：

```csharp
public void Save(string path)
{
    BuiltInChatHistoryStore store;
    lock (messageHistoryLock) lock (noticeHistoryLock)
    {
        store = new BuiltInChatHistoryStore
        {
            ChatMessages = { messageHistory.Select(m => m.Clone()) },
            Notices = { noticeHistory.Select(n => n.Clone()) }   // ← 新增
        };
    }
    // ... 既有写入逻辑不变
    RaiseLogEntry(new LogEventArgs($"Saved {store.ChatMessages.Count} chat messages, {store.Notices.Count} notices"));
}

public void Load(string path)
{
    lock (messageHistoryLock) lock (noticeHistoryLock)
    {
        // ... 既有解析逻辑
        messageHistory.Clear();
        messageHistory.AddRange(store.ChatMessages.Select(m => m.Clone()));

        noticeHistory.Clear();                                      // ← 新增
        noticeHistory.AddRange(store.Notices.Select(n => n.Clone()));

        RaiseLogEntry(new LogEventArgs($"Loaded {messageHistory.Count} chat messages, {noticeHistory.Count} notices"));
    }
}
```

**`BuildNotice` 保留**：作为纯构造方法（不存储），`AddNotice` 内部可调它再存。`NoticeConsoleCommand` 改用 `AddNotice`。

### 4.5 连入自动分发

**文件**：`Extensions/Chat/Server/BuiltInChatServerExtension.cs:109-122`

`HandleIncomingCommand` 处理 `HistoryRequestType` 时，在发完聊天历史后追加通知分发：

```csharp
public ServerIncomingCommandResult HandleIncomingCommand(FrameworkPacket command, ServerFrameworkContext context)
{
    // 既有：发聊天历史
    foreach (var historyMessage in chatApi.GetHistory())
    {
        context.SendMessage?.Invoke(context.ConnectionId, chatApi.BuildBroadcastPacket(historyMessage));
    }

    // ← 新增：发保留窗口内的通知
    DateTime cutoff = DateTime.UtcNow.AddHours(-noticeRetentionWindowHours);
    foreach (var notice in chatApi.GetNoticesSince(cutoff))
    {
        context.SendMessage?.Invoke(context.ConnectionId, chatApi.BuildBroadcastPacket(notice));
    }

    // 既有：发同步完成标记
    context.SendMessage?.Invoke(context.ConnectionId, chatApi.BuildHistorySyncCompletePacket());

    return new ServerIncomingCommandResult { Action = MessageHandlingResultAction.Handle };
}
```

**保留窗口**：默认 24 小时，通过 `ChatServerConfig` 配置（见 §4.6）。窗口外的通知不分发（历史归档，不主动推送）。

## 5. 客户端改动

### 5.1 `ServerTab` 侧栏多 Provider Tab 切换

**文件**：`Client/Source/GUI/Windows and panels/ServerTab.cs`

**现状**（`:30-32`）：

```csharp
sidebarProvider = Instance.SidebarProviders
    .OrderBy(p => p.Order)
    .FirstOrDefault();
```

**目标**：收集所有 sidebar provider，多个时用 `TabDrawer` 渲染 Tab 切换，单个时走老路径（向后兼容）：

```csharp
private readonly List<IServerSidebarProvider> sidebarProviders;
private readonly List<TabRecord> sidebarTabList = new List<TabRecord>();
private int activeSidebarTab = 0;
private const float SIDEBAR_TAB_HEIGHT = 30f;

// 构造函数
sidebarProviders = Instance.SidebarProviders
    .OrderBy(p => p.Order)
    .ToList();

for (int i = 0; i < sidebarProviders.Count; i++)
{
    int index = i;
    // Tab 标签由 provider 提供（新增接口属性，见 §5.2）
    sidebarTabList.Add(new TabRecord(
        sidebarProviders[i].TabLabel,
        () => activeSidebarTab = index,
        () => activeSidebarTab == index));
}
```

**`DoWindowContents` 渲染**（`:72-94`）：

```csharp
Rect mainRect = usableRect;
Rect rightColumnRect = default;
if (sidebarProviders.Count > 0)
{
    float sidebarWidth = sidebarProviders.Max(p => p.PreferredWidth);
    rightColumnRect = usableRect.RightPartPixels(sidebarWidth);
    mainRect = usableRect.LeftPartPixels(usableRect.width - (sidebarWidth + DEFAULT_SPACING));

    // 单个 provider：不显示 Tab 栏，直接绘制（向后兼容）
    if (sidebarProviders.Count == 1)
    {
        sidebarProviders[0].Draw(rightColumnRect);
    }
    // 多个 provider：顶部 Tab 栏 + 内容区
    else
    {
        Rect sidebarTabRect = rightColumnRect.TopPartPixels(SIDEBAR_TAB_HEIGHT);
        Rect sidebarContentRect = new Rect(
            rightColumnRect.x, sidebarTabRect.yMax,
            rightColumnRect.width, rightColumnRect.yMax - sidebarTabRect.yMax);

        TabDrawer.DrawTabs(sidebarTabRect, sidebarTabList, sidebarWidth);
        sidebarProviders[activeSidebarTab].Draw(sidebarContentRect);
    }
}
```

**§2.3 合规**：`ServerTab` 不硬编码"用户/通知"Tab 名，由 provider 的 `TabLabel` 动态提供。


**§6 合规**：新增属性为破坏性变更（第三方实现需添加 `TabLabel`）。缓解措施：
1. 在接口文档注释中明确这是 §6 允许的增量扩展
2. 提供默认实现扩展方法（.NET 4.7.2 不支持接口默认方法，但可提供 `SidebarProviderBase` 抽象基类作为过渡）
3. 搜索仓库确认仅 `ChatSidebarProvider` 实现，无第三方 submod 受影响

**替代方案**（若担心破坏性）：不改 `IServerSidebarProvider`，新增 `IServerSidebarTabProvider : IServerSidebarProvider` 带 `TabLabel`。`ServerTab` 优先收集 `IServerSidebarTabProvider`，回退到老接口。本方案推荐直接扩展接口，因为当前仅一个实现。

### 5.4 `NoticeSidebarProvider` — 通知列表面板

**新文件**：`Extensions/Chat/Client/NoticeSidebarProvider.cs`

```csharp
internal sealed class NoticeSidebarProvider : IServerSidebarProvider
{
    private readonly IChatUiHostContext hostContext;
    private readonly List<NoticeEntry> notices = new List<NoticeEntry>();
    private readonly object noticesLock = new object();
    private const int MAX_NOTICES = 100;
    private Vector2 scrollPos;
    private bool unreadDirty = true;
    private int unreadCount;
    private string cachedRelativeTime;
    private float lastCacheTime;

    public float Order => 10f;  // 在 ChatSidebarProvider(0f) 之后
    public float PreferredWidth => 210f;
    public string TabLabel => "Phinix_sidebar_notices".Translate();

    public NoticeSidebarProvider(IChatUiHostContext hostContext)
    {
        this.hostContext = hostContext;
        hostContext.OnDisconnect += (_, __) => Clear();
    }

    public void Add(UIChatMessage notice)
    {
        if (notice == null || !notice.IsNotice) return;
        lock (noticesLock)
        {
            if (notices.Count >= MAX_NOTICES) notices.RemoveAt(0);
            notices.Add(new NoticeEntry
            {
                MessageId = notice.MessageId,
                Text = notice.Message,
                Timestamp = notice.Timestamp,
                IsUnread = true
            });
            unreadDirty = true;
        }
    }

    public void Clear()
    {
        lock (noticesLock)
        {
            notices.Clear();
            unreadCount = 0;
            unreadDirty = true;
        }
    }

    public void Draw(Rect inRect)
    {
        // 顶部：标题 + 未读数 + "全部已读"按钮
        Rect headerRect = inRect.TopPartPixels(28f);
        Rect markAllRect = headerRect.RightPartPixels(80f);
        Rect titleRect = headerRect.LeftPartPixels(headerRect.width - 80f);

        int currentUnread = GetUnreadCount();
        string title = currentUnread > 0
            ? $"🔔 {"Phinix_sidebar_notices".Translate()} ({currentUnread})"
            : $"🔔 {"Phinix_sidebar_notices".Translate()}";
        Widgets.Label(titleRect, title);

        if (Widgets.ButtonText(markAllRect, "Phinix_notice_markAllRead".Translate()))
        {
            MarkAllRead();
        }

        // 分隔线
        Widgets.DrawBoxSolid(new Rect(inRect.x, headerRect.yMax, inRect.width, 1f), ChatTheme.GroupIndentLine);

        // 通知列表
        Rect listRect = new Rect(inRect.x, headerRect.yMax + 4f, inRect.width, inRect.yMax - (headerRect.yMax + 4f));
        DrawNoticeList(listRect);
    }

    private void DrawNoticeList(Rect inRect)
    {
        lock (noticesLock)
        {
            if (notices.Count == 0)
            {
                Widgets.NoneLabelCenteredVertically(inRect, "Phinix_notice_empty".Translate());
                return;
            }

            // 用滚动容器渲染
            float rowHeight = 48f;
            Rect contentRect = new Rect(inRect.x, inRect.y, inRect.width - 16f, rowHeight * notices.Count);
            Widgets.BeginScrollView(inRect, ref scrollPos, contentRect);

            float cursorY = contentRect.y;
            foreach (var entry in notices)
            {
                Rect rowRect = new Rect(contentRect.x, cursorY, contentRect.width, rowHeight);

                // 未读高亮
                if (entry.IsUnread)
                {
                    Widgets.DrawBoxSolid(new Rect(rowRect.x, rowRect.y, 3f, rowRect.height), ChatTheme.NoticeAccent);
                    Widgets.DrawBoxSolid(rowRect, ChatTheme.NoticeBg);
                }
                else if (Mouse.IsOver(rowRect))
                {
                    Widgets.DrawBoxSolid(rowRect, ChatTheme.RowHoverBg);
                }

                // 时间戳（相对时间，缓存避免每帧计算）
                string relTime = GetRelativeTime(entry.Timestamp);
                GUIUtils.SaveTextFormat();
                Text.Font = GameFont.Tiny;
                Text.Anchor = TextAnchor.UpperLeft;
                Widgets.Label(new Rect(rowRect.x + 8f, rowRect.y + 2f, rowRect.width - 16f, 14f),
                    relTime.Colorize(ChatTheme.ReplyQuoteText));
                Text.Font = GameFont.Small;
                Widgets.Label(new Rect(rowRect.x + 8f, rowRect.y + 16f, rowRect.width - 16f, rowHeight - 18f),
                    entry.Text);
                GUIUtils.RestoreTextFormat();

                // 点击标记已读
                if (Widgets.ButtonInvisible(rowRect) && entry.IsUnread)
                {
                    entry.IsUnread = false;
                    unreadDirty = true;
                }

                cursorY += rowHeight;
            }

            Widgets.EndScrollView();
        }
    }

    private int GetUnreadCount()
    {
        if (unreadDirty)
        {
            lock (noticesLock)
            {
                unreadCount = notices.Count(n => n.IsUnread);
                unreadDirty = false;
            }
        }
        return unreadCount;
    }

    private void MarkAllRead()
    {
        lock (noticesLock)
        {
            foreach (var entry in notices) entry.IsUnread = false;
            unreadDirty = true;
        }
    }

    private string GetRelativeTime(DateTime timestamp)
    {
        // 缓存：每 5 秒更新一次相对时间字符串
        float now = Time.realtimeSinceStartup;
        if (cachedRelativeTime != null && (now - lastCacheTime) < 5f) return cachedRelativeTime;
        lastCacheTime = now;

        TimeSpan delta = DateTime.UtcNow - timestamp;
        if (delta.TotalMinutes < 1) cachedRelativeTime = "Phinix_notice_justNow".Translate();
        else if (delta.TotalMinutes < 60) cachedRelativeTime = "Phinix_notice_minutesAgo".Translate((int)delta.TotalMinutes);
        else if (delta.TotalHours < 24) cachedRelativeTime = "Phinix_notice_hoursAgo".Translate((int)delta.TotalHours);
        else cachedRelativeTime = "Phinix_notice_daysAgo".Translate((int)delta.TotalDays);
        return cachedRelativeTime;
    }

    private sealed class NoticeEntry
    {
        public string MessageId;
        public string Text;
        public DateTime Timestamp;
        public bool IsUnread;
    }
}
```

**§8.3 UI 性能合规**：
- `unreadCount` 脏标记缓存，不每帧遍历
- `GetRelativeTime` 字符串缓存 5 秒
- `noticesLock` 保护线程安全（`Add` 可能在网络线程触发）

## 6. 完整数据流

### 6.1 通知创建与广播（服务端）

```
管理员控制台: notice 30 服务器10分钟后重启
  → CommandInterpreter.Run("notice", args)
  → NoticeConsoleCommand.Execute
  → chatApi.AddNotice(text, 30)                    ← 存入 noticeHistory
  → chatApi.BuildBroadcastPacket(notice)
  → broadcaster.Broadcast("builtin.chat", packet)  ← 全服广播
  → (定期 Save 时写入 notice-history.bin)
```

### 6.2 在线客户端接收

```
服务端广播 FrameworkPacket(MessageType, payload.IsNotice=true)
  → PhinixFrameworkClient.packetHandler → handleMessage
  → ChatMessageHandler.HandleIncomingMessage → chatApi.RenderMessage
  → addDisplayMessage → OnDisplayMessageReceived
  → FrameworkClientChatServiceAdapter.onDisplayMessageReceived → ToUiMessage
  → BuiltInChatClientExtension.chatNotificationHandler
    → if (IsNotice)
       → noticeBannerProvider.Enqueue   ← 横幅即时提醒（10秒后消失）
       → noticeSidebarProvider.Add      ← 侧栏列表（持久，可回看）
```

### 6.3 客户端连入自动分发

```
客户端连接 → 登录成功 → BeginNegotiation → FrameworkV2 协商成功
  → CompatibilityModeChanged(FrameworkV2)
  → BuiltInChatClientExtension.compatibilityChangedHandler
  → 发送 HistoryRequestType 命令
  → 服务端 BuiltInChatServerExtension.HandleIncomingCommand
    → 发送 chatHistory（既有）
    → 发送 noticeHistory 中 timestamp >= now-24h 的通知  ← 新增
    → 发送 HistorySyncComplete
  → 客户端逐条接收 → chatNotificationHandler
    → noticeSidebarProvider.Add（加入列表，未读标记）
    → noticeBannerProvider.Enqueue（横幅，可选——连入分发时可能不希望全部弹横幅）
```

**连入分发的横幅抑制**：连入分发的历史通知不应弹横幅（否则用户连入瞬间被一堆横幅淹没）。通过 `FrameworkPacket` 的 metadata 标记"历史回放"：

```csharp
// 服务端分发时
var packet = chatApi.BuildBroadcastPacket(notice);
packet.SetMetadata(FrameworkMetadataKeys.HistoryReplay, "1");  // 复用既有 metadata 机制
context.SendMessage?.Invoke(context.ConnectionId, packet);
```

```csharp
// 客户端 chatNotificationHandler
if (args.Message.IsNotice)
{
    bool isHistoryReplay = /* 从 FrameworkDisplayMessage.Source 或 metadata 判断 */;
    if (!isHistoryReplay)
        noticeBannerProvider?.Enqueue(args.Message);  // 仅实时通知弹横幅
    noticeSidebarProvider?.Add(args.Message);         // 历史和实时都加入列表
}
```

### 6.4 切服务器清空

```
用户断开连接
  → netClient.OnDisconnect
  → PhinixFrameworkClient.reset()           ← 清空 displayMessages
  → ClientUserEventStream.RaiseDisconnected
  → ChatUiHostContext.OnDisconnect → ChatMessageList.Clear()
  → BuiltInChatClientExtension disconnectHandler → noticeBannerProvider.Clear()  ← 新增
  → NoticeSidebarProvider.hostContext.OnDisconnect → Clear()                     ← 新增（构造函数订阅）
```

### 6.5 服务端重启恢复

```
服务端启动 → BuiltInChatServerExtension.Activate → Load("notice-history.bin")
  → noticeHistory 恢复
  → 新客户端连入 → GetNoticesSince(now-24h) → 分发恢复的通知
```

## 10. 风险与缓解

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| `IServerSidebarProvider` 新增 `TabLabel` 破坏第三方 submod | 中 | 搜索仓库确认仅 `ChatSidebarProvider` 实现；提供 `TabLabel` 默认值文档；若需保守可新增 `IServerSidebarTabProvider` 子接口 |
| 连入分发大量历史通知导致客户端卡顿 | 中 | 保留窗口默认 24h + 容量上限 50 条；客户端侧栏用滚动容器 + 脏标记；横幅抑制避免瞬间弹窗 |
| `notice-history.bin` 文件损坏 | 低 | `Load` try-catch，损坏时重建空文件（既有 `messageHistory` 同机制） |
| 横幅与侧栏双投递导致重复显示 | 低 | 横幅是瞬时提醒，侧栏是历史列表，职责分离；用户可关闭横幅 |
| Legacy 模式下通知 Tab 显示空列表 | 低 | 显示"暂无通知"占位文本；`compatibilityChangedHandler` 弹信件提示功能受限 |

## 11. 后续扩展（非本次范围）

- **通知定向推送**：`AddNotice` 扩展 `targetUuids` 参数，服务端按连接 capability + UUID 过滤分发
- **通知分类**：`BuiltInChatMessagePayload` 追加 `notice_type` 字段（维护/活动/警告），客户端按类型筛选
- **通知已读状态持久化**：客户端记录已读 `MessageId`，跨会话不重复提示
- **通知跨服务器同步**：客户端持久化已读状态，切服务器后对比服务端列表自动标记
- **`FrameworkChatProtocol.NoticeType` 启用**：当前复用 `MessageType` + `is_notice` flag。若未来通知需要独立 capability 协商（如老客户端不收通知），可启用 `NoticeType` 作为独立消息类型
