# 聊天增强功能实施方案 — notice / @艾特 / 回复

> 2026-06-21，基于《设计哲学.md》《框架Protobuf协议设计.md》与代码库实测编写。
>
> **本文档是方案文档，不是已实施记录。** 所有"现状"行号均为代码库实测（截至 2026-06-21），"目标"为待实施设计。
>
> **决策记录**：notice 客户端采用**专用显示区域**（非混入聊天流），由独立消息类型 + 独立 UI 组件承载。

## 0. TL;DR

三项聊天增强改动的核心结论：

| 功能 | 可行性 | host 改动 | 插件改动 | Proto 改动 | 风险 |
|------|--------|-----------|----------|------------|------|
| **notice 全服公告** | 🟡 中高 | 2 个增量挂载点 | Chat 扩展新增命令 + 客户端独立 banner | 新增 `BuiltInChatNoticePayload` | 控制台扩展点是新 host 挂载点，需过 §7 check-list |
| **@艾特 + 蓝色信封** | 🟢 高 | 零 | Chat 扩展闭环，复用 Trade 已验证的 Letter 机制 | `BuiltInChatMessagePayload` 加字段 5 | displayName 重名/空格歧义 |
| **回复功能** | 🟢 高 | 零 | Chat 扩展闭环，纯客户端 UI + payload 字段 | `BuiltInChatMessagePayload` 加字段 6 | 原消息被裁剪时的降级显示 |

**推荐实施顺序**：回复 → @艾特 → notice（按 host 改动量与风险递增）。回复和 @艾特 可合并一次 proto 改动（同时加字段 5、6）。

## 1. 背景与目标

### 1.1 触发需求

聊天作为 Phinix 最核心的交互通道，当前能力较弱（纯文本广播 + 历史同步）。三位用户提出的增强：

1. **运营公告**：服务端管理员需要向全体在线用户推送公告，且公告应有醒目的展示位（不淹没在聊天流里）、可配置持续时间。
2. **@艾特提醒**：用户希望在消息中点名他人，被点名者收到类似交易通知的**蓝色信封**（RimWorld `LetterStack`），避免漏看。
3. **消息回复**：类微信/QQ 的回复引用，可指定某条消息进行回复，目标消息以引用形式展示。

### 1.2 目标（按优先级）

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| **P0** | 回复功能端到端可用 | 用户右键任意聊天消息 → 选"回复" → 输入框上方出现引用条 → 发送后接收方看到原消息引用 |
| **P0** | @艾特端到端可用，被艾特者收到蓝色信封 | 用户输入 `@displayName`（带自动补全） → 接收方客户端识别 `mentioned_uuids` 含本地 UUID → `Find.LetterStack.ReceiveLetter` 弹蓝色信封 |
| **P1** | notice 命令 + 专用 banner 显示 | 服务端控制台 `notice <text>` → 全体在线客户端顶部 banner 显示公告，持续 N 秒（可配置），到时自动淡出 |
| **P1** | notice 持续时间可配置 | 命令支持 `notice <durationSeconds> <text>`，客户端设置项 `chat.notice.defaultDuration` 兜底 |
| **P2** | notice 历史可查看 | 客户端 banner 关闭后，notice 仍可在专用"公告历史"面板回看 |

### 1.3 非目标

- **不重构现有聊天消息管线** —— `BuiltInChatClientExtension` / `ChatMessageHandler` / `PhinixFrameworkChatService` 既有路径行为不变
- **不引入新序列化框架** —— 仍用 protobuf（chat payload）+ DataContractJsonSerializer（外封套）
- **不做 notice 持久化广播**（P2 才考虑）—— P1 只推在线连接，不补偿离线用户
- **不做 @艾特的群组/角色维度** —— MVP 只支持 @单个用户，@all 等扩展推迟
- **不做热重载** —— 控制台命令扩展点在服务器启动时一次性发现

## 2. 设计哲学合规要点（必须遵守）

本方案所有设计决策均以《设计哲学.md》为基准。下列条款在实施过程中**不得违反**：

| 哲学条目 | 对本方案的约束 |
|----------|---------------|
| **§1.1 插件平权** | notice 命令实现必须落在 Chat 扩展内，不得在 host 写"if 命令名 == notice then ..."特殊分支。控制台命令扩展点（`IServerConsoleCommandProvider`）是**通用挂载点**，任何插件都能注册命令 |
| **§1.2 host 不依赖插件** | host 工程不得引用 `ChatExtension` 或 `ChatExtension.Server`。`Server.csproj` 现有 `ReferenceOutputAssembly=false` 的弱引用模式保持不变。host 通过 `ResolveExtensionApis<IServerConsoleCommandProvider>()` 动态发现命令 |
| **§1.3 host 只做通用服务** | host 仅提供：(a) 控制台命令扩展点 (b) 公开广播 API。**notice 业务语义（持续时间、banner 样式）由 Chat 扩展决定** |
| **§2.1 松耦合** | 客户端 banner 通过 `IMainTabProvider` 或新增 `INoticeBannerProvider` 接口接入 `ServerTab`，不直接修改 `ServerTab.cs` 业务分支 |
| **§2.3 减少硬编码** | host 不得硬编码"notice"命令名；banner UI 由 Chat 扩展贡献，不由 host 内置 |
| **§3.4 通用事件流取代专用桥接** | @艾特的蓝色信封通过 `IClientMainThreadDispatcher.Enqueue` + `Find.LetterStack` 实现，不新增 host 专用"艾特通知"接口 |
| **§3.7 插件不得绕过通信管线直连底层传输** | notice 广播必须通过新增的 host 公开广播 API（内部仍走 `pipelineRunner.DispatchOutbound`），不直接调 `netServer.Send`。@艾特、回复的出站消息仍走 `IFrameworkClientTransport.TryHandleOutgoingMessage` 管线 |
| **§3.8 日志与可观测性** | notice 命令执行、广播发送失败、banner 显示异常均通过 `hostContext.Log` / `ILoggable` 上报，不得 `Console.WriteLine` |
| **§5.3 版本化与 API 兼容** | 新增接口 = `MINOR` 版本升级；`BuiltInChatMessagePayload` 现有字段 1-4 不得修改，新字段追加为 5、6；新增 `BuiltInChatNoticePayload` 独立消息类型，不重用既有字段编号 |
| **§6 渐进式迁移 / Host 与 Core 仅做增量更新** | `CommandInterpreter` 既有静态字典保留不变，仅**追加**插件命令回退路径；`PhinixFrameworkServer` 的私有 `dispatchOutboundBroadcast` 不删除，**新增**公开方法包装之；既有 `IServerUserManager` 接口不动 |
| **§7 提交与审查 check-list** | 控制台命令扩展点属新增 host 挂载点，必须确认：(a) host 工程未新增对插件的强引用 (b) 未硬编码业务类型 (c) 错误隔离——单条插件命令抛异常不得崩控制台 |
| **§8 UI 渲染性能** | banner 的淡出动画/计时不得在 `DoWindowContents` 路径上 `new` 对象；计时用 `Time.realtimeSinceStartup` 差值，不每帧 `DateTime.Now` |

## 4. 协议变更

### 4.1 Proto Schema

**文件**：`Extensions/Chat/Contracts/Proto/Message/BuiltInChat.proto`

**现状**（`BuiltInChat.proto:7-12`）：
```protobuf
message BuiltInChatMessagePayload {
  string message_id = 1;
  string sender_uuid = 2;
  string message = 3;
  google.protobuf.Timestamp timestamp = 4;
}
```

**目标**（追加字段 5、6、7，**不修改既有字段**，符合 §5.3）：
```protobuf
message BuiltInChatMessagePayload {
  string message_id = 1;
  string sender_uuid = 2;
  string message = 3;
  google.protobuf.Timestamp timestamp = 4;
  repeated string mentioned_uuids = 5;   // @艾特目标 UUID 列表
  string reply_to_message_id = 6;        // 回复目标消息 ID（空字符串表示非回复）
  string reply_to_snippet = 7;           // 回复原消息截断快照（≤50 字符，原消息被裁剪时降级显示）
}

// 新增独立消息类型，承载 notice 公告
message BuiltInChatNoticePayload {
  string notice_id = 1;                  // 公告唯一 ID（去重/关闭用）
  string text = 2;                       // 公告正文（支持富文本）
  int64 duration_seconds = 3;            // 显示持续秒数（0 = 用客户端默认）
  google.protobuf.Timestamp timestamp = 4;
}

// 历史存储追加 notice 列表（P2 用）
message BuiltInChatHistoryStore {
  repeated BuiltInChatMessagePayload chat_messages = 1;
  repeated BuiltInChatNoticePayload notices = 2;   // 仅 P2 启用
}
```

**兼容性说明**：
- `mentioned_uuids` / `reply_to_message_id` / `reply_to_snippet` 为可选字段（proto3 默认值），老客户端解析新消息时忽略这些字段，不崩溃
- 老服务端解析新客户端消息时同样忽略，@艾特/回复对老服务端"透明降级"为普通消息
- `BuiltInChatNoticePayload` 是全新类型，老客户端不注册其 capability，服务端不会向其派发（见 §5.1 capability 协商）

**文件**：`Server/CommandInterpreter.cs` 改动（**增量，不改静态字典**）：
```csharp
public class CommandInterpreter
{
    private static readonly Dictionary<string, Command> commands = /* 保留不变 */;

    private readonly Func<IReadOnlyList<IServerConsoleCommandProvider>> pluginCommandResolver;

    public CommandInterpreter(Func<IReadOnlyList<IServerConsoleCommandProvider>> pluginCommandResolver = null)
    {
        this.pluginCommandResolver = pluginCommandResolver;
    }

    public void Run(string command, List<string> args)
    {
        if (command == "help") { PrintHelp(args); return; }
        if (commands.ContainsKey(command)) { /* 既有逻辑不变 */ return; }

        // 新增：插件命令回退路径
        if (pluginCommandResolver != null)
        {
            foreach (IServerConsoleCommandProvider provider in pluginCommandResolver())
            {
                if (string.Equals(provider.CommandName, command, StringComparison.OrdinalIgnoreCase))
                {
                    try { if (!provider.Execute(args)) Console.WriteLine($"Plugin command '{command}' failed."); }
                    catch (Exception ex) { Console.WriteLine($"Plugin command '{command}' threw: {ex.Message}"); }
                    return;
                }
            }
        }
        Console.WriteLine($"Unknown command '{command}'");
    }
}
```

**错误隔离**（§3.5）：单条插件命令抛异常被 try-catch 捕获，不影响控制台主循环。

#### 5.1.2 Chat 服务端扩展改动

**文件**：`Extensions/Chat/Server/BuiltInChatServerExtension.cs`

新增 notice 命令实现（**落在插件内，符合 §1.1**）：
```csharp
public sealed class NoticeConsoleCommand : IServerConsoleCommandProvider
{
    private readonly IFrameworkChatServerApi chatApi;
    private readonly IFrameworkServerBroadcaster broadcaster;
    private readonly IServerUserManager userManager;

    public string CommandName => "notice";
    public HelpEntry[] HelpEntries => new[]
    {
        new HelpEntry("notice", new[]{"text"}, "Broadcasts a server notice to all online clients."),
        new HelpEntry("notice", new[]{"durationSeconds", "text"}, "Broadcasts a notice with custom display duration.")
    };

    public bool Execute(List<string> args)
    {
        if (args.Count < 1) return false;
        int duration = 0; string text;
        if (args.Count >= 2 && int.TryParse(args[0], out duration)) text = string.Join(" ", args.Skip(1));
        else { text = string.Join(" ", args); duration = 0; }

        BuiltInChatNoticePayload payload = chatApi.BuildNotice(text, duration);
        FrameworkPacket packet = chatApi.BuildNoticePacket(payload);
        broadcaster.Broadcast("builtin.chat", packet);
        return true;
    }
}
```

在 `BuiltInChatServerExtension.Register` 中注册：
```csharp

```

`IFrameworkChatServerApi` 接口追加（**增量，不删既有成员**）：

```csharp
private readonly List<INoticeBannerProvider> bannerProviders;  // 构造时收集

public override void DoWindowContents(Rect inRect)
{
    // 顶部 banner 区（新增）
    float bannerHeight = 0f;
    foreach (var banner in bannerProviders) bannerHeight += banner.CurrentHeight;
    Rect bannerRect = inRect.TopPartPixels(bannerHeight);
    Rect belowBanner = inRect.BottomPartPixels(inRect.height - bannerHeight);
    float cursorY = bannerRect.yMin;
    foreach (var banner in bannerProviders)
    {
        float h = banner.CurrentHeight;
        banner.Draw(new Rect(bannerRect.x, cursorY, bannerRect.width, h));
        cursorY += h;
    }
    // 既有逻辑改用 belowBanner 替代 inRect
}
```

```csharp
internal sealed class NoticeBannerProvider : INoticeBannerProvider
{
```

```csharp
private HashSet<string> parseMentionedUuids(string raw)
{
    HashSet<string> result = new HashSet<string>();
    foreach (ImmutableUser user in hostContext.UserDirectory.GetUsers(loggedIn: true))
    {
        string tag = "@" + TextHelper.StripRichText(user.DisplayName);
        if (raw.Contains(tag)) result.Add(user.Uuid);
    }
    return result;
}
```

## 7. 风险与缓解

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| 控制台命令扩展点是新 host 挂载点，可能违反 §1.3 | MEDIUM | 接口通用化（`IServerConsoleCommandProvider` 不含 notice 语义），任何插件可注册任意命令。审查时确认 host 未硬编码 "notice" 字符串 |
| 插件命令抛异常崩控制台 | HIGH | `CommandInterpreter.Run` 的插件回退路径必须 try-catch（§3.5），仅打印错误不传播 |
| @艾特 displayName 重名/空格歧义 | MEDIUM | MVP 用自动补全浮窗；富文本 `<mention uuid="...">` 内部用 UUID 引用，显示用 displayName |
| 回复原消息被 1000 条上限裁剪 | LOW | payload 冗余 `reply_to_snippet`（≤50 字）降级；客户端再查 display store，双保险 |
| notice 广播对老客户端"漏发" | LOW | 走 capability 协商（`PhinixFrameworkServer.cs:209`），老客户端不声明 `builtin.chat.notice` 能力，服务端不派发，无异常 |
| banner 计时每帧分配 | MEDIUM | 用 `Time.realtimeSinceStartup` 差值，不每帧 `new DateTime` / `TimeSpan`（§8.3） |
| 大量 notice 队列堆积 | LOW | `NoticeBannerProvider.activeNotices` 设上限（如 3 条），超出丢弃最旧并记 Warning（§3.6） |
| `ServerTab` 改动影响既有布局 | MEDIUM | banner 高度 0 时 `belowBanner == inRect`，既有逻辑零感知；增量改动可独立回滚 |
| proto 字段编号冲突 | HIGH | 严格用 5/6/7（@/回复/snippet）和 1-4（notice 新类型），不重用。审查时对照 `BuiltInChat.proto` 现状 |
