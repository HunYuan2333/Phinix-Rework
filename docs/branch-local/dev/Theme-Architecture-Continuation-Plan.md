## 目标与职责

Host 拥有主题发现、输入校验、选择、持久化、有效样式解析、原子快照和通用控件。Host 的 ui.* 是共享语义角色，ext.* 是宿主扩展管理视图。Chat、Trade、Inventory、Store 与第三方插件同等注册自己的样式；Host 不依赖插件 Contracts 或猜测插件业务颜色。主题包是纯数据覆盖，不会实例化插件或执行代码。

主题目录统一选择/应用，编辑项按 owner 与类别分组。插件只需当前样式读取 API；主题文件版本、旧键、客户端 API 1.9 差异均留在输入或维护插件内部 adapter。

## 解析规则

用户当前主题覆盖 > 当前主题显式值 > builtin.default 显式值 > 注册声明的共享角色/本模块回退键 > 注册默认值。builtin.default 显式值是现有主题来源层，继续保留，避免改变已配置主题含义。共享角色先解析自己的覆盖，再被插件继承。

主题缺键属于正常部分覆盖；读取未注册键属于开发错误。未知键校验后保留在主题原始数据/用户覆盖中，不进入有效样式；重新注册时再参与解析。注册默认值保证插件在没有专属主题时仍可显示。回退键不得跨插件建立隐式依赖，必须是 Host 角色或同 owner 已注册/同批注册键，循环和类型冲突在提交前拒绝。

## 兼容性与更新边界

- 原 ui.*、ext.*、chat.*、trade.*、inventory.*、plugin-store.* 和用户主题选择/覆盖保持稳定。短 namespace 由模块显式声明并由 Host 校验占用；新的第三方默认使用完整 module ID 作为 namespace。所有者由实际激活实例确定，不能由字符串伪造。历史全局 nameColor.* 参数在输入 adapter 归一化为 chat.nameColor.*，保留原文件和数值含义。
- 当前 API 2.0 尚未正式发行，没有第三方旧主题 API 调用方；允许替换本阶段未发布的 RegisterOwner 入口。内置消费方同批迁移，不建立长期双注册协议。测试/示例的旧调用方需随后协调迁移，未经运行不声称通过。
- 红包/人才贸易 1.1.1 使用 1.9 基线、不静态依赖新主题 API。本批保持 API 常量/文件版本 2.0、CLR 绑定身份 1.9，不能恢复或宽松放行已删除的旧核心接口。后续主题接入只能通过内部 adapter，1.9 使用插件默认样式。
- XML v1/v2、历史别名及旧设置仍由 ThemeInputAdapter 归一化；未知键不等于旧键，业务不做 schema 判断。未来 theme package schema 与客户端 API/CLR 身份分别验证。
- 主题应用热更新；程序集更新、插件安装与启停沿用重启生效。必须同步本批完整客户端，避免只替换 SDK 或个别插件 DLL。
- 停用插件移除当前注册/有效键，但保留用户值和原始主题；重新启用恢复。缺失整个主题继续保留选择意图并显示默认，不能悄悄改写用户选择。
