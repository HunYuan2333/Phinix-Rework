# SQLite 实现与验证记录

日期：2026-11-10。位置：客户端 dev 工作区，基于 `939e8e2`。本记录描述当前实现，不代表已经发布或通过游戏实机验收。

## 项目大前提

这是游戏 Mod。保留本地事务、基本幂等、合理输入限制、正确 Game/模块所有权；优先正常可用、明确失败和简单维护。不追求每次崩溃都恢复、全面防读档、跨服务端/世界/数据库的全局原子提交。少见中断可以明确放弃并提示可能丢物，不能伪造服务端成功、自动退款已发送但结果未知的请求，或静默删除已提交余额。这项前提已加入根 AGENTS 和中英文设计哲学。

## 当前实现

### 通用基础设施

`Client/Storage.Contracts` 提供 owner/逻辑库、同步 Read/Write 工作单元、schema migration、数据库身份及一致备份 API；合同不引用游戏或任何业务。`Client/Storage.Sqlite` 实现连接、事务、升级历史校验及原生库加载。业务 SQL/表由消费模块声明，不通过库存转借数据库。

数据放在框架用户数据根的 `Phinix/ExtensionData/<owner>/databases/<name>.sqlite3`：库存使用 `builtin.inventory/inventory`，交易使用 `builtin.trade/trade`。owner 是命名与生命周期约定，不是对同进程 Mod 的安全隔离。各库独立事务，不承诺跨库事务。回调只做数据库工作，不执行网络或世界副作用，也不会自动重试业务回调。

固定依赖为 Microsoft.Data.Sqlite.Core 10.0.13、SQLitePCLRaw 2.1.13，包含锁文件；封装 provider 类型，不将其暴露到库存合同。使用 rollback journal 默认模式、foreign_keys=ON、synchronous=FULL、2 秒锁等待。不是另行实现业务 WAL。Host 统一注册服务，模块释放租约，Host 停止时清理剩余租约。

### 库存

SQLite 是共享余额权威，存档不再持续输出余额快照。条目 payload 存为 BLOB，元数据单独保存；提交用 revision 比较后按变化写行。回执、预留、计划、导入认领在库存自己的表中。仍保留内存 ledger 投影与领域规则，未改为一套庞大的 ORM 或每个命令一套数据库框架。

- 同一本地用户数据配置的所有 Game 使用同一余额，不因登录账号、服务器、存档路径或另存为创建新库存。物理交付仍绑定原 Game；切 Game 让旧 scope 失效。
- GameComponent 保留旧 JSON/SaveId 读取和升级标记。导入数据与来源认领在同一事务；成功后才清除组件内旧字段，下次正常保存清理磁盘存档，不强制保存或直接改写 `.rws`。
- 同一 SaveId 只认领一次；未保存清理就退出，再进旧档不会重复加余额。已认领谱系的不同分支不补差额，给出未保留变更提示后清理旧字段。不同谱系的重复条目/回执/预留来源冲突则保留旧字段，不阻塞共享库存。
- 没有 SaveId 的历史快照使用稳定内容指纹作为来源退路，并通过资产来源 ID 检查跨来源重叠；这不是全面防读档机制。
- 保留 payload、回执及预留。旧活跃预留变成 Uncertain；旧计划保存为暂停数据，不在新游戏时间线上自动运行。旧 journal 不再是导入前提，后续未核实变更不自动恢复，提示可能未迁入，旧文件保留。
- 上次中断的提取在新 Game 接管时扣除相关数量、清除 pending 并显示可能丢失提示。单个 pending 不再阻断无关库存。UI 可放弃当前提取，也可确认放弃未决预留；后者是 Abandoned，不冒充远端成功，不能再退款。
- 数据库身份不同于存档标记时提示后使用本机共享库。损坏/打不开的库不会假装写成功，提供重试入口。旧“按当前存档回滚整份库存”的入口已移除。

### 交易

Trade intent/completion 及各项证据改存交易 SQLite，原文件仅按文件一次性导入，不再写新的 loose-file 日志。每条证据保留基本校验，按 endpoint/principal/subject 索引；坏历史行隔离并提示，不让整模块因一条坏记录停用。完成记录清除大载荷，保留小型去重凭据。现代协议的交付证据等服务端确认后再清理。

移除了累计历史的 64 MiB/4096 终身准入限制和每次报价的虚拟空间预留；保留单记录 64 MiB 边界。尚未解决的记录仍占磁盘，不宣称存储可以无限增长。

业务也相应调整：

- 本地准备/编码/落库失败属于 NotSent，解除本次本地托管；真正进入传输之后的异常继续 Unknown，不能自动退款。
- 界面读取 Submit 的 false，不再显示已提交。
- 普通报价在 Finished 后收到匹配的迟到成功回包仍可结算；reset 保留原有特定保护。
- 已持久化原始结果可以直接核对，不强制等待额外 query；更新操作状态不再以整个库存可写为前提。预留结算仍需正确身份和实际可写库存。
- 终态通知隔离订阅者异常；解码或主线程入队失败有警告。没有为未证明的世界副作用建立自动无限重投机制。

## 剩余边界与后续验收

1. 尚未运行 Windows/Waylith 游戏、真实 Scribe 保存往返或操作系统强杀/断电测试；Linux dotnet/Mono 组件通过不能替代这些验收。其他 native 平台只验证包内容，未验证运行。
2. 数据库事务不覆盖网络和地图世界保存，不杜绝所有丢物/重复。读取旧世界可能恢复已移出地图的实体，这是接受的游戏存档边界。
3. RedPacket 的独立持久化/阶段问题（原审计 F13/F14）、人才会话槽积累（F15）未在本切片重写；它们的构建兼容通过，不代表这些问题已修复。
4. 原 F06 的库存载荷膨胀及 Trade 累计容量已处理；Trade 单证据仍保留 JSON 包络和单笔边界，极端大交易的端到端预算仍需游戏验收，不宣称 F06 全部关闭。
5. 通用 Backup API 已验证，但本次没有新增玩家备份/恢复 UI。恢复旧数据库是共享余额回滚，不具备完整反回滚保证。历史暂停计划没有新增跨世界重新绑定向导。
6. 不保证自动找回旧 journal 未进入存档的变更；迁移入口读取合法旧快照并保留历史文件。升级不支持降级客户端双写，也不提供从 SQLite 导出旧余额的路径。
7. 核心修复覆盖原 F01–F05、F07–F12 的主要客户端路径，但部分投递失败以明确告警和有限恢复结束，并非保证每笔自动恢复；实机验收后再决定发布。
