### 1.4 证据等级与统计规则

- `S`：本轮静态追到注册/投影/绑定/回调及相关结果处理。`G待测`：未做当前HEAD游戏内布局、命中、键盘/IME、焦点、滚动、网络互通与最终交付验收。`入口缺失/只读能力`是静态可证事实，不等于游戏试验失败。可达性还以插件激活和业务条件为前提。
- 统一基准是“主窗口已打开、尚未进入该目标功能”。`N`表示进入目标主Tab：标签可见1次，溢出菜单2次；默认页自动已显示可减去这一入口动作，行中仍按统一N记账。`设置→某项`的两次点击已直接计入，不再加N。
- `C`是鼠标点击总数，包含接受确认窗的点击；`K`是其中确认次数，不再与C相加；`I`是完成字段的一次输入/替换，不是字符/按键数。Enter/拖滑块单列替代，不伪装为鼠标点击。`f`为本次实际聚焦字段的点击数（通常每个要编辑字段1次，Tab切换可减少）；首次全选删除/输入细节依平台，不编造固定击键数。
- `g=0/1`为库存组是否先展开，`b`为实际选择筛选/设置按钮次数，`r=0/1`为是否需要点刷新，`v`为选择其他版本次数，`t=0/1`为改变红包类型；`D=0/1`为是否先开sidebar抽屉，`O=0/1`为sidebar是否进溢出菜单。符号均是条件项，不是平均点击估计。
- `G`记录页面/窗口层级，`q`为窄栏来回切换次数，`p`为实际分页点击数，`s`为内容超出窗口产生的滚动操作数；`0..s`表示依数据量、缩放、字体和窗口高度变化，不能从源码固定。文件目录深度为`d`。如增加分页/窄栏点击，也应加到C；为可读性表中在滚动栏单列，不偷偷假定为0。
- `W`为异步等待：连接/认证、网络权威回执、对方操作、下载/校验、中继、物品分组或游戏帧推进，不计入点击。所有C都是给定数据/有效权限下的基础路径；校验失败/恢复/错误输入重试另按纠错路径增量计算。
- 同任务首次/重复/批量、上下文捷径分列或明确增量。`CX-*`只从已经可见的聊天上下文算捷径，不能与统一基准混加。第三方未安装插件的自定义业务无法穷举，E-01只统计真实公共挂载机制，不捏造其功能。

## 3. 默认主题与状态可辨识性

### 3.1 实际颜色链与fallback

`ThemeSources.Discover(modRoot, userDirectory)`读取`Themes/default.xml`为`builtin.default`，旧短key由ThemeInputAdapter归一到`ui.*`/`chat.*`。UiTheme先注册角色，再解析每个key：draft显式覆盖 → 当前主题显式值 → builtin.default基线值 → 若有fallback继续解析目标key → 最后才用无fallback角色的注册默认值。显式inherit会跳过相应层。注册时写了一个蓝色default，并不表示最终必然蓝色。

本次计算条件为：选中builtin.default、无用户profile覆盖、默认XML存在并解析成功、无额外上游GUI tint。实际玩家已选主题/保存override未知，本报告不把玩家截图默认外观与此条件自动等同。

| 最终用途 | key与值（RGBA，0..1） | 来自哪里/渲染效果 |
|---|---|---|
| 页面/面板 | ui.background=(.082353,.078431,.070588,1)；ui.surface=(.098039,.094118,.082353,1) | XML不透明底；不是UiTheme构造时透明background/surface默认 |

### 3.2 可复算对比结果

### 3.3 可证问题和已有区分手段

1. 页面/面板仅1.04:1、输入/页面仅1.03:1，区域层级主要依靠间距和细边框。separator对页面2.28:1、对普通按钮1.51:1；在密集列表、窄窗和缩放后，边界识别余量小。默认暗色并不自动等于文字不可读：主文字15.05:1，次文字8.81:1。
2. 选中与hover填充完全相同（1.00:1），用户必须找到强调条/标题或pill下划线区分；因此“所有选中态都不存在”不成立，但在状态色覆盖标题、长文本/图标拥挤时仍存在混淆风险。强调色对该填充4.83:1，标记的颜色本身可辨，3px宽度和位置需游戏核验。
3. Danger只是红字＋普通按钮底，常态对比2.94:1；普通按钮hover改变底色后仍需重算，不应只看ui.error对页面4.44:1。需要阅读的红色按钮标签存在清晰度风险，尤其取消/重置/卸载。
4. 时间戳2.83:1、引用文字约2.75:1；字体常为Tiny/次级信息，细节阅读是实质风险。当前左时间戳已在姓名之前，报告不再把历史左侧位置当当前bug。
5. 自己消息底1.02:1、被提及底1.07:1、hover叠底1.10:1，单靠背景不足以稳定提示；用户名/提及文字/状态文本提供其他线索，需把用户注意力落点作为实机观察项。
6. Disabled与surface重合，部分当前选项（交付偏好/筛选/连接方式）以“禁用”表达已选。需要结合说明/选中标记才能区分“当前已选”和“功能不可用”。pending有文字和状态tone，但并非每个网络请求都有统一spinner/可取消状态；Host不会推测业务结果。
7. Host对长文本已有测量、wrap、clip/tooltip、overflow及窄栏切换。固定32px控件、3px选中条、圆角12/16、card padding12并非全部响应字体缩放；Example原生主页直接按剩余高度不绘制控件，是与公共滚动页不同的风险。是否真的被遮挡/截字须G验证。
8. 交易当前已用plain/compact、行内输入、共用下部、双方标题显示确认状态，提交报价位于下部刷新右侧；不能再次沿用旧“先选行再找数量窗/提交固定在顶部”的路径。下部固定占剩余60%（双空65%）、多pane滚动与固定头可能造成局部留白/窄窗往返；这是数据与窗口相关待测，不能凭参数宣称布局验收失败。

普通按钮按下是另一处实际fallback风险：ui.button.pressed继承亮强调色，而Normal文字仍主文字，约1.64:1；Danger悬停红字约2.33:1、按下约2.07:1。主要按钮因使用暗文字没有这个相同问题。按下态持续时间短，不能直接等同整次操作不可用，但状态变化过程中标签反而更难读已可由源码解释。
