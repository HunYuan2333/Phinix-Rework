# 验证、诊断与恢复

## 分开报告证据

| 状态 | 能说明什么 | 不能代替什么 |
| --- | --- | --- |
| 源码检查 | 声明、调用路径、配置与边界符合所检查的源码 | 编译或实际绑定 |
| 编译通过 | 指定输入/运行时产生 DLL，命令退出 0 | 安装、激活或业务兼容 |
| 白盒通过 | 明确列出的断言、CLI 与边界测试通过 | 实际游戏绘制和多 Mod 环境 |
| 游戏通过 | 指定游戏构建执行了具体场景 | 未执行版本/路径的兼容性 |

“待测”是每项证据的缺口，不是更高验证级别。写清实际命令、输入与结果；控制台测试程序用实际执行命令运行，不能用 dotnet test 的空成功伪造断言数量。无日志异常只覆盖已执行路径。历史记录标日期与范围，不包装成此次复测。

## 先找最早有效错误

记录游戏准确版本、Host/API/插件实际加载版本、来源与摘要。优先最早的 LoaderException 或拒绝原因，再分析连锁异常。不要索要完整敏感日志；只保留所需诊断，不提交玩家原始日志。

| 错误/现象 | 诊断方向 |
| --- | --- |
| CandidateHostIncompatible | CompatibilityVersion、游戏变体、manifest 范围；CLR AssemblyVersion 不等于产品版本 |
| PackageNotFound | 包 ID、版本、运行时路由、主题/DLL feed 和已发布资产是否一致；不直接等同限流 |
| RepositoryRateLimited | 检查 HTTP 状态、响应正文、限流头、认证与 URL。当前客户端部分 403 映射较宽，错误名本身不足以证明额度耗尽 |
| UpdateScopeChanged | Index 的批准策略与新包范围变化；保留旧发布，审查新策略，不绕过审批 |
| UnknownField | 实际客户端/清单 schema 与字段、所选变体是否匹配；看原始拒绝字段，不能只凭系统平台归因 |
| 安装版本新但加载版本旧 | 当前进程仍使用旧绑定；核对重启与启动摘要 |

## 状态与物品恢复

使用稳定操作 ID、明确状态和权威回执。回调/task 完成不等于业务确认；关闭视图不取消交易或自动返还。已经发送而结果未知的操作保留记录，不能凭超时当作失败重新付款或返还。

物品/Pawn 转换、预留与交付保持整批原子性。缺 Def、codec、依赖或有效地图时报告拒绝，不静默丢项。切档、断线、重复回执与乱序回执按实际业务所有者处理；Host 保持中立，不接管账本、报价或人物权威。

验证从小的确定性规则、包与绑定检查开始，再执行相关游戏流程。不要为了纯文案修改模拟整个游戏，也不要因编译通过跳过实际交付与恢复测试。
